# multi_agent

## 역할
- 이 폴더: 멀티 에이전트(`backend/multi_agent/`)의 회귀 테스트. 소스 폴더와 같은 이름으로 짝을 맞춘다(`tests/graph/` ↔ `backend/graph/`와 같은 규칙).
- 넣는 것: `test_<대상>.py`. LLM과 검색기는 가짜로 바꿔 API 없이 돌린다. 실제 모델·외부 서비스·DB·소켓은 호출하지 않는다.
- 넣지 않는 것: 단일 그래프 시험(`tests/graph/`), 평가 실행기와 동결 감시(`tests/evals/`), 판정 코드 시험(`tests/judge/`).
- 담당: 에이전트

실행: `uv run pytest -q tests/multi_agent`(저장소 루트).

저장된 실측 응답을 재생하는 시험(`test_docs_agent.py`)은 가짜 공급자로 그 응답을 다시 흘려 코드의 처리(인용 교정, 문장 제거, 보존)를 확인한다. 새 모델 성적이 아니고 원시 파일은 바꾸지 않는다. 재생에 쓰는 원시 파일은 `evals/results/threads/injection_baseline_live_2026-11-11_03.jsonl`, `evals/results/threads/injection_t3_smoke_live_2026-11-11_07.jsonl`, `data/demo/snapshot/chunks.jsonl`이다.

## 파일
| 파일 | 확인하는 것 |
|---|---|
| `MULTI_AGENT.md` | 이 문서 |
| `test_build.py` | 조립(`build.py`): 바로 끝내는 길(일상 대화, 범위 밖 거절, 계획 형식 실패 거절), 품번 없음 사실이 계획과 거절 문구에 닿음, 가격 질문의 가격 안내(Mouser 호출 없음), 할 일 1개는 Supervisor를 다시 부르지 않음, 할 일 2개는 동시에 돌고 종합으로 합침, 종합이 지어낸 숫자는 답 검사가 거절, 모두 실패하면 재계획 뒤 거절, 판정 인터럽트 재개, 새 턴에 보고·판정 칸 비우기, 그림의 한국어 노드 이름과 조건 라벨, 기억 읽기(선호 실장 방식 읽기·사용자 격리·Store 없음·읽기 실패)와 찾기 후보 순서에만 미치는 영향 |
| `test_contracts.py` | 계획서 형식 검사(거절 사유 없음, 일상 대화 reply 없음, 할 일 수 범위, 번호 순서, 판정에 맞지 않는 종류, 검색어 없는 문서 할 일), 보고 요약 한도, 이유 코드 분류, 상한 상수 |
| `test_facts_lookup.py` | 사실 확인이 MCP 도구(`check_corpus`) 응답(가짜 함수)으로 `Facts`를 만들고 확인할 것이 없으면 도구를 안 부름 |
| `test_supervisor.py` | Supervisor가 LLM에 주는 글(질문·사실·보고·현황·선택지), 결정 처리(한도 거절, 꺼진 웹 거절), 횟수 세기, 재계획 규칙(재시도 가능한 실패만 1회, 확정 거절은 안 함), 승인 사례를 가진 입력(계획·할 일 꾸러미에 닿되 현재 사양 근거가 되지 못함), 프롬프트가 모든 노드와 거절 사유를 담았는지, 찾기 질문에 판정 찾기 할 일이 없으면 코드가 맞춤, 판정 답의 출력 경계(답 정리·종합 모두 판정 표만 냄), 부분·실패 문서 혼합 때 성공 본문·근거 보존, 문서 보고의 넷리스트 인용 권한(채택/실패/제외/앞 회차), footprint를 계획에 넘기지 않음, 단일 partial의 미완료 안내 |
| `test_agents.py` | RAG 에이전트: 지시서 검색어로 찾고 근거 채점 + 답 쓰기를 LLM 한 번으로 함(역할 할 일은 검색 없이 넷리스트), 근거가 없으면 다른 검색어로 한 번만 다시 찾음, 보여 준 적 없는 인용을 코드로 막음, 다른 품번 줄을 LLM 전에 거름, 검색 장애·0건 보고, 정격 같은 품번 찾기, 문서 없는 정격 질문은 회로 근거로 대신하지 않음, 내부 근거 실패 때 외부 검색 1회와 웹 인용 수용, 일부 답이면 빠진 부분을 한 번 더 찾음. 사실 확인·거절 문구·판정 답 틀도 함께 확인 |
| `test_docs_agent.py` | RAG 에이전트의 인용 처리: 허용 번호 명시, 인용 누락·미제공 번호의 교정 1회 상한, 교정 후 미인용 문장 제거와 제공 번호 문장 보존(partial·missing·제거 요약 유지), 과거 사례 인용 거부, enough + missing의 partial 분류, G/GH 접미사·기본형 근거 허용, 변형 품번의 품번 규칙 주석 재검색, 극성·정격·패키지 근거 보존, 저장된 실측 응답 재생 |
| `test_judge.py` | Spec 에이전트: 읽기 LLM 1번, 질문에 없는 숫자 버리기, 인터럽트 한 번과 재개 값, 규칙 없는 역할, 판정·찾기·정렬, 비교는 `verdict`에서만, 품번 앞 제조사 이름 떼기, 주문 코드만 다른 동일품, 찾기에 원래 부품 패키지·분류 넘기기, 선호 실장 방식이 찾기 순서만 바꾸고 질문의 실장 요구가 이김 |
| `test_judge_read.py` | 판정 읽기: 읽기 입력 글에 역할마다 값 이름·종류가 있음, 프롬프트가 모든 값 이름의 뜻을 담음, 역할에 없는 이름은 버려 `dropped`에 남음, 코퍼스 밖 요구(사양 표에 없는 성질, TSC 아닌 제조사, 확인 안 된 개정판)가 묻지 않고 판정 보고로 나옴, footprint만 다른 두 입력의 멀티 계획·역할 읽기·문서 입력이 같음 |
| `test_part_names.py` | 읽기 뒤 품번 바로잡기(`part_names.py`): 사용자 글의 품번으로 맞추고 글에 품번이 없거나 둘 이상이거나 앞부분이 겹치면 그대로 둠, 후보가 원래 부품이 되지 않음, 주문 코드는 한 칸 띄어 씀 |
