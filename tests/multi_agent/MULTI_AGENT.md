# multi_agent

## 역할
- 이 폴더: 멀티 에이전트(`backend/multi_agent/`)의 회귀 테스트를 둡니다. 소스 폴더와 같은 이름으로 짝을 맞춥니다(`tests/graph/` ↔ `backend/graph/`와 같은 규칙).
- 넣는 것: `test_<대상>.py`. LLM과 검색기는 가짜로 바꿔 API 없이 돌립니다.
- 넣지 않는 것: 단일 그래프 시험(`tests/graph/`), 평가 실행기와 동결 감시(`tests/evals/`), 판정 코드 시험(`tests/judge/`).
- 담당: 에이전트

실행: `uv run pytest -q tests/multi_agent`(저장소 루트).

## 파일
- `MULTI_AGENT.md` — 이 문서
- `test_build.py` — 조립: 역할 질문 직행, 검색 → 작성 → 검증 → 끝, 검색 두 번 실패 → 못 찾음 거절, 범위 밖 거절, 품번 없음 사실이 Supervisor와 거절 문구에 닿는지, 검증 실패 뒤 다시 쓰기 한 번, 켜지 않은 기능 거부. 서브에이전트가 끝날 때마다 판단으로 돌아오는지(경로)
- `test_judge.py` — 판정 에이전트: 읽기 LLM 1번, 질문에 없는 숫자 버리기, 인터럽트 한 번과 재개 값, 규칙 없는 역할, 판정 · 찾기 · 정렬, 비교는 `verdict`에서만. 가짜 LLM · 가짜 사양 표
- `test_facts_lookup.py` — 사실 확인이 MCP 도구 응답(가짜 함수)으로 `Facts`를 만드는지 · 확인할 것이 없으면 도구를 안 부르는지
- `test_agents.py` — 검색(실패 사유 3종 · 필터 풀기 · 사유 쌓기) · 작성(거절 답 실패 보고) · 검증(다시 계산 · 넷리스트 인용 · 기록만 모드) · 사실 확인 · 거절 문구(일상어)
- `test_supervisor.py` — Supervisor가 LLM에 주는 글(질문 · 사실 · 보고 · 현황 · 선택지)과 결정 처리(한도 거절, 꺼진 웹 거절, 끝내는 길 유지), 횟수 세기, 프롬프트가 모든 노드와 거절 사유를 담았는지. 가짜 LLM
- `test_contracts.py` — 결정서 · 보고서 모양 검사(목록 밖 노드 · 이유 없는 거절 거부), 이유 코드 분류, 한도 규칙(판단 8 · 검색 2 · 작성 2, 같은 사유 반복 → 못 찾음)
