# multi_agent

## 역할
- 이 폴더: 멀티 에이전트(`backend/multi_agent/`)의 회귀 테스트를 둡니다. 소스 폴더와 같은 이름으로 짝을 맞춥니다(`tests/graph/` ↔ `backend/graph/`와 같은 규칙).
- 넣는 것: `test_<대상>.py`. LLM과 검색기는 가짜로 바꿔 API 없이 돌립니다.
- 넣지 않는 것: 단일 그래프 시험(`tests/graph/`), 평가 실행기와 동결 감시(`tests/evals/`), 판정 코드 시험(`tests/judge/`).
- 담당: 에이전트

실행: `uv run pytest -q tests/multi_agent`(저장소 루트).

## 파일
- `MULTI_AGENT.md` — 이 문서
- `test_build.py` — 조립: 역할 질문 직행, 검색 → 작성 → 검증 → 끝, 검색 두 번 실패 → 못 찾음 거절, 범위 밖 거절, 품번 없음 사실이 Supervisor와 거절 문구에 닿는지, 검증 실패 뒤 다시 쓰기 한 번, 켜지 않은 기능 거부, 판정 길(판정 읽기 → 판정 → 인터럽트 한 번 재개 → 작성 → 검증 → 끝, 읽기는 한 번), 판정 도구 · 체크포인터 없이 켜면 거부, 새 턴에 판정 칸 비우기, 가격 질문 → 단일 그래프와 같은 가격 안내(검색 · HTTP 호출 없음, 값 없음). 서브에이전트가 끝날 때마다 판단으로 돌아오는지(경로), 그림(`get_graph(xray=True)`)의 한국어 노드 이름과 조건 라벨이 재계획 고리 하나뿐인지
- `test_judge.py` — 판정 에이전트: 읽기 LLM 1번, 질문에 없는 숫자 버리기, 인터럽트 한 번과 재개 값, 규칙 없는 역할, 판정 · 찾기 · 정렬, 비교는 `verdict`에서만, 품번 앞 제조사 이름 떼기(TSC), 주문 코드만 다른 동일품과 주문 정보 표 인용(쇼트키 면제 뒤에도 동일품), 찾기에 원래 부품 패키지 · 분류 넘기기. 가짜 LLM · 가짜 사양 표 요구 말에 시험 조건 숫자가 섞여도 그 항목 단위 숫자가 하나면 원문 연산 말을 쓰는지(#50).
- `test_judge_read.py` — 판정 읽기: 읽기 입력 글에 역할마다 그 역할의 값 이름 · 종류가 있는지, 프롬프트가 모든 값 이름의 뜻을 담았는지, 그 역할의 이름은 남고 다른 이름은 버려 `dropped`에 남는지, 그 이름이 기준값까지 닿는지. 코퍼스 밖 요구 거절: 사양 표에 없는 성질 → `not_found`, TSC 아닌 제조사 → `part_missing`, 확인 안 된 개정판 → `revision_missing`이 묻지 않고 판정 보고로 나오는지, 사양 표 항목 · TSC · 확인된 개정 코드는 통과하는지, 멀티 그래프에서 Supervisor가 작성을 골라도 거절로 끝나는지, 거절 문구가 있는 품번을 없다고 하지 않는지, 40자 넘는 `revision_wanted` 설명 글을 요구 없음으로 받고, 글 안의 개정 코드는 남기는지. 가짜 LLM · 가짜 사양 표 코퍼스에 없는 후보 거절 · 빈 판정 보고는 실패(#47), vz_min · vz_max는 범위가 있는 인용만(#48).
- `test_facts_lookup.py` — 사실 확인이 MCP 도구 응답(가짜 함수)으로 `Facts`를 만드는지 · 확인할 것이 없으면 도구를 안 부르는지
- `test_agents.py` — 검색(실패 사유 3종 · 필터 풀기 · 사유 쌓기) · 작성(거절 답 실패 보고, 판정 답은 코드 틀) · 검증(다시 계산 · 넷리스트 인용 · 기록만 모드, 판정 답은 틀과 같은지) · 사실 확인 · 거절 문구(일상어) · 판정 답 틀(확인 안 됨이어도 찾은 값 · 빠진 값 · 주의, 찾기 0개) 문서 에이전트가 일부 답이면 빠진 부분을 한 번 더 찾고 앞 근거를 함께 보이는지, 새 근거가 없거나 더 나쁘면 첫 답을 쓰는지(#49).
- `test_docs_agent.py` — 문서 에이전트: 물은 품번이 변형 품번(SMAJ6.5CA 등)이면 품번 규칙 주석(양방향 모두 적용 · IR 한도 2배)을 한 번 더 찾아 붙이는지, 표 주석 카드를 다른 품번 줄로 거르지 않는지(가짜 검색)
- `test_supervisor.py` — Supervisor가 LLM에 주는 글(질문 · 사실 · 보고 · 현황 · 선택지)과 결정 처리(한도 거절, 꺼진 웹 거절, 끝내는 길 유지), 횟수 세기, 프롬프트가 모든 노드와 거절 사유를 담았는지. 가짜 LLM 찾기 질문인데 판정 찾기 할 일이 없으면 코드가 그 할 일로 맞추는지(#47).
- `test_contracts.py` — 결정서 · 보고서 모양 검사(목록 밖 노드 · 이유 없는 거절 거부), 이유 코드 분류, 한도 규칙(판단 8 · 검색 2 · 작성 2, 같은 사유 반복 → 못 찾음)
