# 청킹 v1 대 v4h 검색 비교 (같은 동결 평가셋 v3, 같은 임베딩·검색 코드)

- 상태: 현행 (측정 2026-11-13)
- 목적: 강사 지적 ② "청킹을 같은 평가셋으로 비교한 원시 결과가 없다"에 대한 원시 결과. 검색만 잰다(답 작성·채점 없음).
- 비교 대상: 옛 청커 v1 `tsc-cards-2026-11-01`(52,244개) 대 현행 v4h `tsc-v4h-2026-11-08`(51,967개). 이 문서에서 두 쪽을 `v1`, `v4h`로만 부른다.

## 설정

| 항목 | v1 | v4h |
|---|---|---|
| 로컬 DB (컨테이너 `sojafit-db-1`, pgvector pg16) | `sojafit_prod_backup_1109` | `sojafit_v4` |
| chunker_version (전 행 동일) | `tsc-cards-2026-11-01` | `tsc-v4h-2026-11-08` |
| `document_chunks` 행 수 | 52,244 | 51,967 |
| `chunk_embeddings` (`voyage-4-large`) 행 수 | 52,244 | 51,967 |
| `source_documents` (문서 수) | 1,360 | 1,360 |
| 청크 적재일 (`created_at`) | 2026-11-02 | 2026-11-08 |
| 쪽 번호가 있는 (문서, 쪽) 수 | 7,019 | 5,739 |

- 공통: 레포 커밋 `2f8298e`(백엔드·실행기 변경 없음), 임베딩 `voyage-4-large` 1024차원, 검색 `backend.rag.retrieve.retrieve(k=10)` 하이브리드(BM25 + 벡터 RRF → Voyage rerank-3), `DEMO_MODE=0`. 환경은 `DATABASE_URL`만 다르다. 운영 Supabase DB는 연결하지 않았다. 로컬 DB는 읽기 전용 조회만 했다.
- 실행기: `evals/runners/run_retrieval_v3.py`. 코드는 바꾸지 않았다. 문항에 `query`가 있으면 재작성 LLM을 건너뛰는 기능이 이미 있어 그것을 썼다.
- 고정 질의: [rewrite_q3_v3.json](../../../inputs/rewrite_q3_v3.json)(서비스 `rewrite()` 출력을 1번만 만들어 두 쪽이 공유). 질의 글은 두 쪽에서 문항별로 같음을 결과 json에서 확인했다.
- 평가셋: `evals/dataset_v3.jsonl`(동결, 수정 없음). 관련 25건 중 정답이 `<파일>.pdf, N쪽` 꼴인 문항은 21건이다. 나머지 4건은 회로 근거만 있어 실행기가 뺀다(그래서 25건이 아니라 21건).

| 파일 | sha256 |
|---|---|
| `evals/dataset_v3.jsonl` | `05202314ed1d009593ab14bc5d44e3d7ab7dd4a9f7e726f98282198c7999b4fd` |
| `evals/inputs/rewrite_q3_v3.json` (고정 질의) | `05e9c0bedcdc853f979c0ec40614b0042bba233ce41acdfe8c36a607d69cb4e7` |
| 실행기 입력 `v3_fixedq.jsonl` (평가셋 + 문항별 `query`, 아래 명령으로 재생성, 저장소에 두지 않음) | `abd8df05420663cef9621b27fa9c191e11d9d6c2eb58918dd5225d06b24109c7` |

재현: 위 두 파일에서 `v3_fixedq.jsonl`을 만든다(평가셋 각 줄에 `rewrite_q3_v3.json`의 `queries[id].Q3`를 `query`로 더함). 이어서 DB를 바꿔 같은 명령을 두 번 돌린다.

```
DEMO_MODE=0 DATABASE_URL=<로컬 DB> PYTHONPATH=. uv run python -m evals.runners.run_retrieval_v3 <v3_fixedq.jsonl> evals/results/chunking/v1-vs-v4h-2026-11-13/retrieval_<v1|v4h>_2026-11-13.json
```

## 결과 (21문항, 각 DB 1회 실행)

| 지표 | v1 | v4h |
|---|---|---|
| 문서 Recall@5 | 0.8095 | 0.8095 |
| 쪽 Recall@5 | 0.8095 | 0.8095 |
| 문서 MRR | 0.8095 | 0.8095 |
| 쪽 MRR | 0.8095 | 0.8095 |
| page_frac@5 (정답 쪽 중 상위 5개에 든 비율) | 0.6111 | 0.6349 |
| 재작성 제외 검색 시간 p50 / p95 (초) | 0.89 / 1.20 | 0.85 / 1.49 |

질문 유형별 page_frac@5: candidate_judge(10건) v1 0.8167 · v4h 0.8417, candidate_find(5건) 0.05 · 0.10, rating(6건) 0.7361 · 0.7361. 문서·쪽 Recall과 MRR은 세 유형 모두 두 쪽이 같다(judge·rating 1.0, find 0.2).

문항별 차이 (원시는 두 json의 `rows`):

| 문항 | v1 | v4h | 비고 |
|---|---|---|---|
| v3-08 (SS14H, 정답 4쪽) | page_frac 0.50 | 0.75 | v4h가 SS12H 2쪽을 상위 5개에 넣음 |
| v3-15 (SMAJ 대체 찾기, 정답 4쪽) | 0.25 | 0.50 | |
| 나머지 19건 | 같음 | 같음 | 상위 5개 목록이 달라도 쪽 집합 기준 page_frac은 같음. 상위 5개 쪽 목록이 순서까지 완전히 같은 문항은 9건 |

- 모든 적중 문항(17건)은 두 쪽 모두 1위에 정답 문서·쪽이 있다(rank 1). 그래서 Recall·MRR은 포화되어 청커를 구별하지 못하고, 차이는 page_frac@5뿐이다.
- 21건 중 4건(v3-11~v3-14, candidate_find)은 두 쪽 모두 결과가 비어 0점이다. 실행기가 질문에서 뽑은 품번(1N4001, 1N400x·SM4002, PB3, SS14-E3)이 코퍼스에 없어 품번 필터가 허용 청크 0개를 만든다(`retrieve()`의 설계). 청커와 무관한 실행기 한계이며, 이 때문에 Recall 상한이 17/21 = 0.8095이다.

## 비용

LLM 재작성 21회(Haiku, 짧은 입출력)와 Voyage 임베딩 · rerank 17회 × 2 DB. 호출 사용량 로그는 남기지 않았다 [추정] 합계 USD 0.1 미만(승인 상한 0.50). 정확한 청구액은 OpenRouter · Voyage 대시보드에서 확인해야 한다.

## 한계

- 표본이 작다. 21건 중 차이가 난 것은 2건(page_frac 0.25씩)이고 통계 검정은 하지 않았다. "v4h가 낫다"가 아니라 "Recall·MRR은 같고 page_frac이 약간 높다"까지만 말할 수 있다.
- 각 DB 1회 실행이다. 질의는 고정했지만 Voyage 임베딩 · rerank의 반복 변동은 재지 않았다. 시간은 로컬 컨테이너 기준이며 첫 호출 변동을 포함한다(p95는 문항 21개 중 둘째로 느린 값).
- 정답은 쪽 단위(`<파일>.pdf, N쪽`)로 적혀 있어 청크 경계와 무관하다. 그래서 v1에도 불리하지 않게 같은 기준으로 잰다. 정답 쪽 (문서, 쪽)은 21문항 전부 두 DB에 청크가 존재함을 확인했다. 다만 정답이 v4h 코퍼스의 쪽 번호를 기준으로 작성되었으므로, v1의 쪽 번호 부여 방식이 다르면 v1에 불리할 수 있다. 정답 쪽이 v1에도 모두 있어 이 영향은 이번 측정에서는 드러나지 않았다.
- 적재일이 다르다(v1 11-02, v4h 11-08). v1 DB는 11-09 운영 백업이라 인증 표가 있고 `source_documents.category`(마이그레이션 012) 열이 없다. 검색 코드는 이 열을 읽지 않는다. v4h 코퍼스는 청커 외에 파서·표 처리 개선이 함께 들어 있어, 차이를 청킹 하나의 효과로만 해석할 수 없다.
- 이 실행기는 v3의 "정답이 쪽으로 적힌" 문항의 검색 길만 잰다. 후보 찾기(candidate_find) 유형은 서비스의 별도 찾기 경로를 거치지 않아 과소 측정된다.
- 고정 질의는 생성 직후 자동 확인(품번 빠짐 · 없던 숫자)을 돌리지 않았다.

sha256은 `SHA256.txt`.
