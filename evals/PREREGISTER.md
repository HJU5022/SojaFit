# 사전 등록

바꾸기 **전에** 적습니다. 결과를 본 뒤에 기준을 정하면 어떤 결과든 성공처럼 보입니다. 한 번에 하나만 바꿉니다.

기대는 **숫자 범위**로 적습니다(예: "0.60~0.75"). "좋아질 것"은 기대가 아닙니다. 기대가 틀려도 불이익은 없고, 틀린 기대를 기록으로 남기는 것이 이 표의 목적입니다(아래 #5에서는 기대 다섯 개 중 네 개가 틀렸습니다). 측정 뒤에 "맞음/틀림" 칸만 채우고 위의 기대 칸은 고치지 않습니다.

API와 로컬 후보는 실행 환경이 다릅니다. Recall@5·MRR·다중 근거 Recall@5는 동일한 평가셋과 검색 파이프라인에서 후보 구성의 **검색 품질**을 비교하는 1차 지표입니다. 질의 p95·1,000청크 시간·비용은 후보별 **운영 프로파일**로 따로 보고하며, 그 차이를 임베딩 모델 자체의 인과적 속도 차이로 해석하지 않습니다.

완성 서비스의 애플리케이션은 모든 임베딩을 API로 호출하고 현재 로컬 실행은 시험에만 사용합니다. 운영 API는 외부 관리형 또는 팀이 별도 추론 서버에 배포한 자체 API일 수 있습니다. 따라서 로컬 실험은 후보 선별 단계이며 최종 확정 실험이 아닙니다. 최종 후보는 같은 동결 입력을 실제 운영 endpoint의 정확한 모델 ID·차원·query/document 형식으로 다시 실행하고, Recall@5·MRR·다중 근거 Recall@5와 endpoint 지연·토큰/인프라 비용을 측정합니다. 로컬과 운영 API의 모델 변형이 다르면 별도 후보로 사전 등록합니다.

## 2026-11-02 임베딩 × 검색 방식 격자 본평가 (#16)

임베딩 모델과 `vector(N)`을 정하는 본평가다. 지금까지의 측정(10-30 프록시, 11-01 초안 19문항, 11-02 PDF 3건 smoke)은 dense만 썼거나 동결 전 문항이어서 서로 비교할 수 없으므로 모델 선택에 쓰지 않고, 동결한 v1로 처음부터 다시 잰다. 격자는 임베딩 6종 × 검색 방식 6칸 + 모델과 무관한 BM25 3칸을 질의 글 2종으로 곱한 78칸이다. 비교는 다른 축을 고정하고 한 축만 다른 칸끼리 한다.
