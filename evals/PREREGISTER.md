# 사전 등록

바꾸기 **전에** 적습니다. 결과를 본 뒤에 기준을 정하면 어떤 결과든 성공처럼 보입니다. 한 번에 하나만 바꿉니다.

기대는 **숫자 범위**로 적습니다(예: "0.60~0.75"). "좋아질 것"은 기대가 아닙니다. 기대가 틀려도 불이익은 없고, 틀린 기대를 기록으로 남기는 것이 이 표의 목적입니다(아래 #5에서는 기대 다섯 개 중 네 개가 틀렸습니다). 측정 뒤에 "맞음/틀림" 칸만 채우고 위의 기대 칸은 고치지 않습니다.

API와 로컬 후보는 실행 환경이 다릅니다. Recall@5·MRR·다중 근거 Recall@5는 동일한 평가셋과 검색 파이프라인에서 후보 구성의 **검색 품질**을 비교하는 1차 지표입니다. 질의 p95·1,000청크 시간·비용은 후보별 **운영 프로파일**로 따로 보고하며, 그 차이를 임베딩 모델 자체의 인과적 속도 차이로 해석하지 않습니다.

완성 서비스의 애플리케이션은 모든 임베딩을 API로 호출하고 현재 로컬 실행은 시험에만 사용합니다. 운영 API는 외부 관리형 또는 팀이 별도 추론 서버에 배포한 자체 API일 수 있습니다. 따라서 로컬 실험은 후보 선별 단계이며 최종 확정 실험이 아닙니다. 최종 후보는 같은 동결 입력을 실제 운영 endpoint의 정확한 모델 ID·차원·query/document 형식으로 다시 실행하고, Recall@5·MRR·다중 근거 Recall@5와 endpoint 지연·토큰/인프라 비용을 측정합니다. 로컬과 운영 API의 모델 변형이 다르면 별도 후보로 사전 등록합니다.

- 출발 자료: 조원 보고 DB 837MB·벡터 표 786MB(HNSW 363MB). 저장소에는 원본 DB·전체 카드·벡터가 없으므로 직접 확인한 기준선이 아니다. [공유 문서](https://oreumi.notion.site/D0-D1-TSC-40bebaa8982b80008b72fdc07528c799)의 분류별 수량도 출처 기록으로만 쓴다.

### 2026-11-02 PR #23 반영: 축소 보류와 비교 조건 명시

- #10은 **적용 보류**한다. 원본 13분류 전체를 유지하고 subset 도구는 독립 수동 CLI로만 둔다. 위 최초 기대와 미측정 이력은 보존한다.
- #9의 다음 실행은 저장값만 halfvec으로 반올림한 뒤 vector로 읽고, 질문은 float32로 유지하는 정확 코사인 검색이다. HNSW 제거는 먼저 별도 조건으로 기록하고 정밀도 비교 양쪽에는 같은 인덱스 조건을 쓴다. 최초 top-5 기대 0.99~1.00과 공식 Recall@5·MRR 무하락 게이트는 유지한다.
- 이미 본 조원 보고: PR #23의 코퍼스 크기 MiB 829.5→466.7→258.0→237.8, 카드 질의 1,000개 top-5 집합 일치 100%, 순서 999/1,000. 저장소 자료로 한 실측·독립 재현이 아니며 원본 SQL·표본·벡터가 없어 조건 일치도 미확인이다. 현재 합성 테스트는 실제 코퍼스 실험이 아니다.
- 250MB는 최초 진단 목표로 남기며 코퍼스를 삭제하는 채택 기준으로 쓰지 않는다. 현재 수동 SQL은 동일 본문 벡터 중복 제거를 하지 않는다.
