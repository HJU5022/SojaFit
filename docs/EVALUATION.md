# 평가 준비 시 빠진 항목

기본 게이트와 마감은 기존 README·GATES, 평가 방식과 결과는 `EVAL_REPORT.md`, 평가셋 동결은 `evals/EVALS.md`에서 관리합니다. 여기서는 그 문서에 없는 평가 축과 준비 항목만 보충합니다. 새 팀 규칙이나 수치 합격선을 만들지 않습니다.

## 기본 배점

| 축 | 배점 |
|---|---:|
| 문제와 시장 근거 | 15 |
| RAG 품질 | 25 |
| 에이전트 설계와 신뢰성 | 25 |
| 배포와 운영 | 20 |
| 증거 패키지와 발표 | 15 |

## 추가로 준비할 근거

- [ ] 목표 직무 채용 공고 50건을 분석해 반복 업무·필요 역량을 정리한다. 공고 분석 자료는 서비스 코퍼스와 구분한다.
- [ ] 사용자·지불 주체는 확인 사실과 가설을 구분한다. 범용 챗봇과 동일 질문 5개를 비교한 결과는 기존 평가 리포트 10장에 기록한다.
- [ ] 외부 검토자 1명에게 서비스와 근거를 검토받고 피드백·반영 여부를 남긴다.
- [ ] 임베딩은 100건으로 시간·비용을 먼저 측정하고 전체 구축량을 추정한다. 모델 선택의 품질·비용 절충과 한계는 평가 리포트에 기록한다.
- [ ] 검색/생성·승인 대기의 컨텍스트 경계와 근거 부족 시 재검색·종료 조건을 설명한다. 답변 인용이 실제 검색 문서에 존재하는지 코드로 검증한다.
- [ ] 전원 발표 파트를 맡고 AI가 작성한 코드도 설계 이유를 설명한다. 현장 입력은 정상·경계·방어 3종으로 연습한다.

공식 정확도·Recall·응답 시간 합격 수치는 공개되지 않았습니다. 팀 목표와 지표 분모·오류 처리 기준은 확정 후 기능 정본과 평가 리포트에 기록합니다.

## 가산 선택

필수 게이트가 모두 충족된 경우만 적용하며 합계 적용 상한은 +10점입니다. 선택 여부와 실제 결과를 기록하고 필수 구현을 가산으로 중복 계산하지 않습니다.

| 항목 | 배점 | 별도로 보여야 할 것 |
|---|---:|---|
| 자동화 | +5 | 증분 추가·갱신, 완전 목록일 때만 삭제, 중복 실행 방지, 정시 실행 기록·실패 알림 |
| 파인튜닝 | +5 | 도메인 학습 데이터·학습 결과, 동일 평가셋의 베이스 비교·실제 출력 |
| GraphRAG | +3 | 벡터 검색이 지는 질문 유형, 그래프 적용 전후 비교 |
| MCP + Skill | +3 | 3차 RAG의 MCP 실제 호출과 도메인 Skill 실제 사용, 같은 평가셋의 Skill 유무 비교 |

기존 2차 MCP·Skill을 그대로 가져온 것만으로는 신규 가산 근거가 되지 않습니다.
