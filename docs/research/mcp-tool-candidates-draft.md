# SojaFit MCP·웹 검색 도구 후보 논의 초안

> **상태: 초안 / 팀 결정 전**<br>
> 작성: 2026-11-03 · 외부 서비스 가격 재확인: 2026-11-03<br>
> 목적: 팀이 MCP 도구 후보와 웹 검색 공급자를 선택하고 다음 작업을 준비한다. 아래 순위는 문서 조사에 따른 예비 순서이며 실제 검색 품질·지연·비용 실측 순위가 아니다. 공급자 가격과 조건은 도입 직전 다시 확인한다.

## 1. 팀이 결정할 항목

1. 필수 웹 검색 요구가 실시간 외부 검색 실행을 뜻하는지, 평가자의 키 없는 데모 환경에서 어떤 실행이 허용되는지 확인한다.
2. 웹 검색 1차 비교 대상: Tavily·Exa·Brave. 무료 한도, API 키, 공식 문서 발견율을 비교한 뒤 선택한다.
3. 우리 검색을 직접 FastMCP로 노출할 범위와 LangGraph 연동 담당을 정한다.
4. 검색 결과를 가져올 수 있는 공식 도메인, PDF 검증 절차, 외부 조회 실패와 데모 모드 동작을 정한다.
5. 실측 질문, 담당자, 예산·호출 상한, 중단 조건과 결과 기록 위치를 정한 뒤 실험을 사전 등록한다.

## 2. 프로젝트 현재 상태와 제약

- [MCP 안내](../../backend/mcp_skill/MCP_SKILL.md): 프로젝트 RAG 검색의 MCP 노출과 LangGraph 호출, 도메인 Skill의 유무 비교가 가산 범위다. 조사 당시 서버는 예제 도구만 있었으며 현재 구현 상태는 구현 계획을 확인한다.
- [RAG 안내](../../backend/rag/RAG.md): `retrieve(question, k, parts)`는 기존 코퍼스의 BM25·벡터 검색과 품번 필터를 사용한다. 데모 모드는 임베딩 API 없이 BM25를 사용한다.
- [SPEC](../../SPEC.md): 현재 정본 조건으로 공식 자료 출처·페이지·표·행을 보존한다. TSC 실시간 문서는 검증 관문을 통과한 뒤 사용하고, 수치·단위 비교는 `backend/judge/`에서 수행한다.
- 평가자는 키 없이 Compose를 시작하는 조건이 있다. 키 없는 데모의 대체 응답이 **실시간 웹 검색 필수 조건을 충족하는지**는 아직 확인되지 않았다.
- Mouser는 확장 단계이며, 응답을 DB·데모 응답·대화·체크포인트·트레이스에 저장하지 않는 프로젝트 정책을 따른다.
- Exa의 익명 공개 MCP 연결 및 공개 질의 1회 기능 탐색을 했다(7절). Tavily·Brave 호출, 계정 생성, API 키 발급, 공급자 간 검색 품질·비용·지연 비교는 하지 않았다.

## 3. 도구별 외부 MCP 후보

각 순위는 조사 당시 기능 설명을 기준으로 한 제안이다. 운영 안전성·프로젝트 호환성은 별도 검증이 필요하다.

### 3.1 기존 코퍼스 검색 `search_corpus`

**우선 제안:** 외부 범용 서버를 서비스 검색에 바로 쓰기보다, 우리 `retrieve()`를 자체 FastMCP로 노출한다. 외부 후보는 개발 점검 또는 대체안으로 비교한다.

| 외부 순위 | 후보 | 장점 | 제한·검토 사항 |
|---:|---|---|---|
| 1 | [Microsoft PostgreSQL MCP](https://github.com/microsoft/postgres-mcp/blob/main/USAGE.md) | PostgreSQL 조회·운영 점검, 읽기 전용 질의 지원 | 범용 SQL. 기존 RRF·품번 필터·출처 반환을 자동 재현하지 않음. DB 계정 권한도 제한 필요 |
| 2 | [Supabase MCP](https://supabase.com/features/mcp-server) | Supabase 관리·조회, 프로젝트 범위와 읽기 전용 옵션 | 로컬 Compose 서비스 검색을 그대로 대체하기 어려움. 접근 권한·인증 확인 |
| 3 | [mcp-server-pgvector](https://github.com/mittalpk/mcp-server-pgvector) | pgvector 유사도·하이브리드 검색 도구 | 커뮤니티 구현. 스키마·정확 검색·RRF·인용 필드 호환성 미확인 |

## 4. 웹 검색 비용·적합성 비교

2026-11-03 공식 가격 안내를 기준으로 한 단순 비교다. 무료 크레딧 적용 전 검색만 계산했으며 본문 추출, 추가 결과, 재시도, LLM 비용은 포함하지 않는다. 계정·지역·결제 조건과 실제 청구는 도입 직전 재확인한다.

| 항목 | Tavily | Exa | Brave Search |
|---|---|---|---|
| 공식 MCP | 있음 | 있음 | 있음 |
| 검색 키 | 필요 | API는 필요. 호스팅 MCP 익명 접근은 제한 있음 | 필요 |
| 무료 안내 | 월 1,000크레딧, 청크 불필요 | API 플랜 월 $10 크레딧. 익명 MCP 한도는 별도 | Search 플랜 월 $5 크레딧. 청크 등록 조건 확인 |
| 검색 1,000회 예시 | Basic·종량제 $8 | Lite $4부터 / Auto $7부터 | Search $5 |
| 추가 비용·조건 | Basic 1크레딧/회, Advanced 2크레딧/회. 추출 별도 | 검색 모드·결과 수·본문 추출에 따라 차이 | Search 플랜 조건 및 별도 본문 확보 확인 |
| 적합성 가설 | 공식 도메인 필터·검색/추출 통합 비교 | 키 없는 MCP 가능성 검토 | 일반 검색 대조군 |
| 아직 미확인 | 우리 품번 검색 품질, 실제 소모·지연 | 익명 한도·가용성, 공식 PDF 검색 품질 | 공식 도메인 제한 방식, 계정 등록, 품번 정확도 |

공식 근거: [Tavily 요금·크레딧](https://docs.tavily.com/documentation/api-credits), [Tavily 가격](https://www.tavily.com/pricing), [Exa 가격](https://exa.ai/pricing), [Exa MCP 익명 제한](https://github.com/exa-labs/exa-mcp-server), [Brave Search 가격](https://brave.com/search/api/).

**계산 예:** Tavily Basic 1,000회 × $0.008 = $8, Exa Lite 1,000회 = $4부터, Brave Search 1,000회 = $5. 무료분·별도 추출을 제외한 예시다. Tavily Advanced는 검색당 2크레딧이므로 같은 횟수라도 소모가 다르다.

## 5. 다음 회의 및 검증 순서

1. **요구사항 확인:** 웹 검색 필수 조건의 원문과 평가자 키 없는 환경에서 허용되는 동작을 확인한다.
2. **도구 경계 결정:** 자체 RAG MCP, 외부 웹 검색, PDF 검증, 결정적 판정의 책임과 입출력을 정한다.
3. **비교 사전 등록:** 동일한 TSC 품번·질문 10~20개, 기대 결과, 공급자별 검색·추출 횟수, 예산·중단 조건을 `evals/preregister.md`에 먼저 적는다. 동결 평가셋을 수정하지 않는다.
4. **조건별 측정:** 공식 PDF/제품 페이지 발견율, 정확한 품번·제조사, 페이지·표·행 연결 가능성, 오류·재시도, 시간, 비용·키 없는 데모 동작을 기록한다. 품질·지연은 실제 호출 후에만 기재한다.
5. **팀 결정 후 구현:** 기능이 SPEC에 없으면 `docs/specs/` 작업서를 먼저 작성하고, 필요한 MCP SDK·클라이언트·서버 의존성과 Compose·Cloud Run 실행 방식을 확인한다.
6. **검증:** LangGraph가 실제 MCP 도구를 호출하는지와 도구가 검색·파싱·판정·승인 경계를 지키는지 검사한다. 가산을 목표로 한다면 Skill 사용/미사용을 같은 평가셋에서 비교한다.

### 이전 8질의 채점·비용 구상 — 이력 (확정 조건은 8절)

- 검색 공급자당 동일 질의 8개, 질의당 검색 1회·상위 5개 결과를 제안한다. 검색 모드·필터·타임아웃·재시도는 호출 전 공급자별로 명시하고, 차이가 있으면 결과에 기록한다.
- 검색 결과의 `공식 도메인`, `품번/계열 일치`, `개정판 일치`를 각각 기록한다. 검색 결과 제목만으로 PDF 내용이 맞다고 판정하지 않는다. 공식 도메인의 정의와 현재 판본은 담당자가 확정해야 한다.
- 성공·실패·오류·미호출을 구분한다. 검색 시간은 각 호출 원시값과 중앙값·최대값을 우선 기록하며, 8회라는 작은 표본의 p95는 안정적인 운영 지표로 주장하지 않는다.

Brave 원문·URL은 보관하지 않았으며 파생 통계 보관 가능 여부는 공급자 확인이 필요하다. 응답 시간은 클라이언트가 요청을 보낸 뒤 응답을 받을 때까지이며 Exa MCP 초기화와 Tavily 프로세스 시작은 포함하지 않는다. Brave는 키 인증, 다른 두 후보는 익명 방식이다. 세 방법의 시점·프로토콜·캐시가 달라 속도 차이를 공급자 고유 성능으로 단정할 수 없다.

Brave의 7회는 무료분 적용 전 단가로 $0.035에 해당하며, 사용자가 직전에 무료 크레딧 $5·자동 충전 꺼짐을 확인했다. 대시보드의 실제 차감액은 재확인하지 않았다. 이번에는 재시도나 별도 페이지·PDF 다운로드를 하지 않았다.


## 11. 30개 문항 웹 검색 탐색 — 2026-11-03

### 설계

기존 W01~W08을 제외한 프로젝트의 TSC 문서 manifest에서 seed 42로 문서 30개를 무작위 추출했다. 본 실험은 분류별 층화 표본이나 동결 평가셋이 아니다. 비동결 문항과 과거 참고 URL (원본 파일은 저장소 외부에 보관), [사전등록](../../evals/guides/preregister.md), 응답 본문·URL 없는 질의별 집계 (원본 파일은 저장소 외부에 보관) 및 측정 실행기 (원본 파일은 저장소 외부에 보관)를 남긴다. Brave 결과의 파생 통계 보관 범위는 공급자 확인 필요.

- 동일 30개 질문, 후보·질문당 1회, 상위 5개, 15초 제한, 재시도·별도 PDF 다운로드 없음. Tavily SDK 0.8.5 익명 Basic, Exa 익명 MCP, Brave Web Search API 사용.
- 공식 도메인: 상위 5개 중 taiwansemi.com 또는 하위 도메인이 있는 문항 수.

## 12. Tavily 인증 API 30문항 재측정 — 2026-11-03
