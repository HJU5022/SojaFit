# 로그인 피드백 및 AUTH_SECRET 검증 실측

- 측정 시각: 2026-11-02 19:59 KST
- 대상: STH 작업 트리의 미커밋 인증 변경. 로컬 `.env`의 `AUTH_SECRET`을 실제로 사용했으며 키와 세션 토큰, DB 접속 정보는 기록하지 않았다.
- 환경: Windows, Python 3.12.10, FastAPI `TestClient`, Docker PostgreSQL 16.15. 임시 Compose DB 두 개를 사용하고 기존 DB와 세션은 건드리지 않았다.
- 측정 조건: 실제 네트워크 서버가 아닌 동일 컴퓨터의 TestClient에서 PostgreSQL에 접속했다. 계정별 세 번씩 순차 호출한 단일 측정이며 운영 지연이나 동시 부하의 대표값이 아니다.
- DB 시드 확인은 `DEMO_MODE=1`과 `0`인 새 볼륨을 각각 사용했다. API의 키 사용 측정은 데모 계정이 준비된 격리 DB에서 `DEMO_MODE=0`과 로컬 키를 지정해 실행했다.

## 피드백 항목별 결과

| 확인 항목 | 결과 | 근거 |
|---|---|---|
| `/api/auth/me` 역할 반환 | 통과 | 관리자 3/3 `admin`, 일반 사용자 3/3 `user`, 모두 HTTP 200 |
| 관리자 API 권한 | 통과 | 관리자 계정 목록 3/3 HTTP 200, 일반 사용자 3/3 HTTP 403. 상태 변경과 세션 폐기는 아래 pytest 통합 테스트에서 확인 |
| 키 없는 새 데모 DB | 통과 | `DEMO_MODE=1` 초기화에서 관리자 1개·일반 1개 생성 |
| 비데모 기본 계정 차단 | 통과 | `DEMO_MODE=0`에서 계정 환경변수가 비어 있을 때 기본 계정 0개 |
| 사용자 지정·불완전 시드 | 통과 | 격리 DB의 `test_demo_seed_configuration` 다섯 조건에서 설정 재정의와 일부 값 오류 확인 |
| 실제 로컬 AUTH_SECRET | 통과 | 6/6 세션에서 DB 저장값이 로컬 키로 계산한 HMAC-SHA256과 일치하고 SHA-256 단독값과 다름 |
| 키 변경과 세션 | 통과 | 일반 사용자 세션 중 임시 키로 바꾸자 `/api/auth/me` HTTP 401. 키를 복원한 뒤 로그아웃 성공 |
| 키 없는 데모·배포 시작 조건 | 통과 | 자동 테스트에서 키 없는 데모 시작, 데모 외 키 누락·짧은 키 거부, 유효한 테스트 키 시작 확인 |
| 로그아웃 | 통과 | 6/6 HTTP 200, 로그아웃 후 `/api/auth/me` 6/6 HTTP 401 |

## 개별 응답 시간

단위는 밀리초(ms), `time.perf_counter()`로 TestClient 호출 전후를 측정했다. 연결·DB 처리와 로그인 비밀번호 검증을 포함한다.

| 역할 | 반복 | 로그인 | `/api/auth/me` | 로그아웃 |
|---|---:|---:|---:|---:|
| admin | 1 | 443.70 | 15.85 | 17.71 |
| admin | 2 | 425.76 | 32.36 | 29.74 |
| admin | 3 | 408.90 | 26.65 | 12.56 |
| user | 1 | 392.31 | 13.53 | 12.89 |
| user | 2 | 432.93 | 14.31 | 13.51 |
| user | 3 | 398.81 | 13.19 | 32.29 |

로그인 시간 중앙값은 관리자 425.76ms, 일반 사용자 398.81ms다. 각 3회에 불과해 분포나 성능 차이의 근거로 해석하지 않는다.

## 자동 회귀 검사

- 격리 PostgreSQL에 `TEST_AUTH_DATABASE_URL`을 지정하고 Windows 인코딩 차이를 피하기 위해 `PYTHONUTF8=1`로 `.venv/Scripts/python.exe -m pytest -q -rs` 실행: **75 passed, 10 skipped, 18.39초**.
- 건너뛴 10건은 별도 RAG 테스트 DB 또는 코퍼스가 필요한 검사다. 인증 DB 통합 테스트와 시드 5조건, 키 교체·로그아웃 검사는 실행됐다.
- 시드·키 검사의 가짜 키는 테스트 전용이며, 위 6회 실측만 로컬 `.env`의 실제 키를 사용했다.

## 범위와 남은 확인

- 실제 브라우저의 운영자 메뉴는 아직 구현되지 않아 메뉴 표시를 확인하지 않았다. 서버 측 역할 응답과 관리자 API만 확인했다.
- 로컬 API 컨테이너의 `.env` 전달, 클라우드 비밀값 설정, 배포된 서비스의 HTTPS·다중 인스턴스·동시 부하 및 기존 볼륨 적용은 이번 측정 범위에 포함되지 않았다.
- `AUTH_SECRET`을 추가·변경·제거하면 이전 세션은 다시 로그인해야 한다. 키가 저장되지 않은 환경에서 앱을 재시작하면 환경 설정에 따라 동작이 달라질 수 있다.
