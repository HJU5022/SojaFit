# MCP 서버·LangGraph 두 사람 작업 분담안

> 2026-11-03 작성 당시 제안. 담당자와 세부 경로는 역할 협의 후 확정한다. 최신 디렉터리 정리 후 문서 경로는 `docs/research/`로 재분류했다. 역할 분담은 여전히 팀 합의 전 제안이다.


아래는 담당자 이름을 정하기 전의 제안이다. A는 MCP 서버와 도구, B는 LangGraph와 통합 검증을 맡는다. 그래프·검색·서비스의 실제 담당 경로는 팀 계약을 확인하고 조율한다. 현재 사용처와 경로는 디렉터리 정리 후 다시 확인한다.

| 순서 | MCP 서버·도구 담당 A | LangGraph·통합 담당 B | 관계 |
|---|---|---|---|
| 1 | 도구 5개의 입력·출력·호출 조건과 현 구현 한계를 점검하고 유지·내부 기능·점검용 후보를 정리한다. | 최신 main 그래프의 검색 주입 계약, 라우팅·재검색 경로와 기존 평가 테스트를 확인한다. | 병렬 가능. 실제 도구 노출은 공동 결정 |
| 2 | `search_corpus`의 품번 목록 입력 검증과 빈 결과·도구 오류 계약을 제안한다. | 그래프가 기대하는 `retriever(query, *, parts=...)` 입력과 카드 필수 필드, 장애 시 흐름을 정리한다. | 두 결과를 대조해 공동 계약 확정 |
| 3 | 서버 기동·종료, stdio 응답 형식과 도구 단위 오프라인 검증을 준비한다. | 합의된 계약에 맞춰 MCP 클라이언트·그래프 연결 방안을 준비하고 가짜 응답으로 정상·빈 결과·장애·재검색 경로를 검증한다. | 계약 확정 후 구현. 각자 별도 테스트로 병렬 진행 |
| 4 | 데모 외부 호출 차단, 웹 후보 미검증 표시와 공개 정보 전송 경계를 검증한다. | 격리 테스트 DB의 합성 표본으로 그래프 → MCP → 검색 결과·출처를 검증하고 결과·지연·환경을 기록한다. | 공동 통합. A는 서버 진단 지원, B는 결과 기록 |
| 5 | 회로·문서·PDF 도구의 노출 필요성과 서버 내부 기능 경계를 팀에 제안한다. | 그래프 기존 회로 입력 처리와 중복 여부, 도구 사용 시점을 팀에 제안한다. | 팀 결정 후 후속 범위 확정 |

### 완료 기준

- **A:** 도구마다 실제 호출처와 제안 사용처, 입력·출력·오류·보안 경계가 문서화되고, 유지하기로 한 도구의 대표 정상·거부 사례가 검증된다. 웹 실호출은 무료 한도와 실제 지출 $0 조건을 재확인하기 전까지 보류한다.
- **B:** 가짜 검색기로 라우팅·정상·빈 결과·장애·최대 두 번 검색을 확인하고, 격리 DB에서 실제 MCP를 경유한 결과와 출처를 기록한다. 장애와 빈 결과를 혼동하지 않는다.
- **공동:** 동일한 도구 이름·인자·결과 형식과 실패 시 처리에 합의하고, 합의 범위를 SPEC 또는 작업서와 테스트에 반영한다. MCP 독립 테스트만으로 앱 전체 연결 완료라고 판단하지 않는다.

### 충돌을 줄이는 작업 방식

- 현재 코드 기준 A는 `backend/mcp_skill/`, B는 `backend/graph/`의 연결을 주로 검토한다. 상대 영역 수정이 필요하면 먼저 담당자와 범위를 정한다. 파일 경로는 팀 디렉터리 정리 후 재확인한다.
- 공통 문서·SPEC와 통합 테스트는 담당을 한 명 정하고 상대가 리뷰한다. `retrieve` 검색 구현·평가 동결 자료는 해당 담당자와 협의한다.
- 팀의 디렉터리 정리 PR이 main에 병합될 때까지 각자 설계·호출 계약 및 오프라인 점검을 준비한다. 이후 기존 미커밋 변경과 새 파일을 보관하고 최신 main을 각자 브랜치에 반영해 경로·import 충돌을 해결한다.
- PR은 팀의 한 PR 한 목적 규칙에 맞춰 도구 계약·서버 작업과 그래프 연결을 논리적으로 나눈다. 연결 PR은 필요한 서버 계약이 들어온 기준 커밋을 명시한다.
