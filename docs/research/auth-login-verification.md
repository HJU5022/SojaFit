# 로그인·세션·scrypt 실측 기록

## 목적과 환경

PR 인증 리뷰에서 요청한 두 계정의 세션 분리, 잠금·만료 경계, 동시 비밀번호 검증의 메모리를 확인했다. 기준 코드는 STH 커밋 `8dc9630`, 측정일은 2026-11-02(KST)다. 결과는 로컬 시험이며 Cloud Run 배포 결과가 아니다.

- Windows 11, Python 3.12.10, FastAPI 0.162.0, 테스트 전용 PostgreSQL 16.15(Docker).
- FastAPI `TestClient`는 Windows의 단일 Python 프로세스에서 실행했고, 별도 컨테이너의 PostgreSQL에는 localhost TCP로 연결했다. 브라우저·외부 네트워크는 포함되지 않는다.
- 각 시험은 무작위로 만든 임시 계정을 사용하고 종료 후 해당 계정·세션·실패 기록만 삭제했다. 비밀번호와 세션 토큰은 기록하지 않는다.
- 기존 전체 회귀 검사: 테스트 전용 PostgreSQL과 임시 pgvector DB, UTF-8 모드에서 `pytest -q` 결과 **73 passed, 1 skipped**. GitHub Actions 실행 결과는 아니다.

## 두 계정 로그인·로그아웃과 세션 격리

2026-11-02 15:55:15에 임시 계정 A·B로 각각 로그인했다. 로그인과 사용자 확인의 ID가 각 DB 계정의 ID와 일치하는 것을 확인했다.

| 요청 | 기대 | 관측 |
|---|---:|---:|
| A 로그인 / B 로그인 | 각 200 | 각 200 |
| A 사용자 확인 / B 사용자 확인 | 각 200 | 각 200 |
| A 로그아웃 후 A 사용자 확인 | 401 | 401 |
| A 로그아웃 후 B 사용자 확인 | 200 | 200 |
| B 로그아웃 후 B 사용자 확인 | 401 | 401 |

이는 인증 세션 분리 결과다. 실제 회로·대화·장기 기억·견적 데이터의 사용자 간 접근 차단은 이 시험에 포함되지 않는다.

## 5회 실패 잠금과 세션 만료 경계

2026-11-02 15:53:30에 PostgreSQL **한 트랜잭션의 `CURRENT_TIMESTAMP`를 고정**하고 TestClient 요청이 같은 테스트 연결을 사용하도록 구성했다. 임시 계정은 트랜잭션 롤백으로 정리했다. 실제로 15분·30분·8시간을 기다린 시험은 아니다.

- 잘못된 비밀번호 1~5회는 모두 401, 1~4회에는 잠금 시각이 없었고 5회째 생성된 잠금 종료 시각은 트랜잭션 기준 시각으로부터 **900초 후**였다.
- 정상 로그인으로 생성된 세션의 절대 만료는 같은 기준 시각으로부터 **28,800초 후**였다.

| 조건 | 경계 1μs 전 | 정확한 경계 | 경계 1μs 후 |
|---|---:|---:|---:|
| 15분 잠금 종료, 올바른 비밀번호 | 401 | 200 | 200 |
| 30분 비활동 세션 | 200 | 401 | 401 |
| 8시간 절대 만료, 최근 활동 유지 | 200 | 401 | 401 |

`CURRENT_TIMESTAMP`는 트랜잭션 시작 시각이다. 따라서 실제 요청에서 DB 대기나 scrypt 처리 시간이 길어지면 응답 완료 시각부터 잰 잠금·세션 유효 시간과 차이가 생길 수 있다. 위 표는 고정된 DB 시각에서의 비교와 설정 간격을 검증한다.

## 실제 scrypt 동시 실행의 로컬 메모리

2026-11-02 15:55:15에 코드의 `scrypt(n=131072, r=8, p=1)`를 실제 실행했다. Windows `GetProcessMemoryInfo`로 **API와 TestClient가 함께 실행되는 Python 프로세스**의 메모리를 2ms 간격을 목표로 표본 추출했다. 표본은 단일 요청 29개, 동시 요청 35개이며 스케줄링에 따라 표본 간 간격은 달라지고 실제 최고점을 놓칠 수 있다. PostgreSQL 컨테이너와 OS 전체 메모리는 포함하지 않는다.

| 측정 | 실행 전 working set | 표본 중 최대 working set | 증가량 | 실행 전 private bytes | 표본 중 최대 private bytes | 증가량 |
|---|---:|---:|---:|---:|---:|---:|
| 로그인 1건 | 54.11 MiB | 183.43 MiB | 129.32 MiB | 39.93 MiB | 169.59 MiB | 129.66 MiB |
| 로그인 2건 동시 | 55.39 MiB | 312.13 MiB | 256.74 MiB | 41.13 MiB | 298.48 MiB | 257.36 MiB |

두 로그인은 모두 200이었고 실제 scrypt 호출 구간이 **343.11ms 겹쳤다**. 두 호출이 실행 중인 동안 세 번째 로그인은 **503**으로 거부됐으며 해당 요청의 측정 시간은 10.52ms였다. 두 요청을 동시에 시작시키기 위해 잠금 획득 후 검증 직전에 동기화 대기를 둔 시험이므로 두 로그인 전체 응답 시간은 일반 서비스 지연으로 해석하지 않는다. 각 시나리오는 단일 실행이고, 증가량에는 Python·요청 처리에 따른 다른 메모리 변화도 포함된다.

현재 코드는 같은 PostgreSQL DB의 트랜잭션 advisory 잠금 두 개로 로그인 경로의 동시 검증을 제한한다. 이 제한은 해당 DB와 로그인 경로를 공유할 때 적용된다. 계정 생성 명령의 scrypt는 범위 밖이며, DB 연결이 검증 중 끊어져 잠금이 먼저 해제되는 상황에서도 전체 프로세스의 메모리 상한을 보장한다고 볼 수 없다.
