# 코퍼스 밖 TSC 품번의 공개 확인 방안

- 상태: 계획 (미결정 선택지. 채택된 방안 없음)
- 기준일: 2026-11-12
- 정본 여부: 비정본(정본: [SPEC](../../../SPEC.md) 2절·6절, 결정은 ADR로 기록)
- 관련 문서: [MCP 서버 도구 6종](mcp-tool-implementation-plan.md), [MCP 검색 도구 작업서](../../specs/mcp-search-tools.md), [ADR 0006](../../adr/0006-근거가-없어도-대화는-이어-간다.md)

## 1. 질문

코퍼스 밖 TSC 품번도 공식 문서를 실시간 조회한다는 SPEC 요건을 유지하면서 비공개 품번을 외부에 보내지 않으려면, 어떤 공개 품번 목록으로 사전 확인하고 목록에 없는 품번은 누가 어떤 절차로 확인하는가.

## 2. 현재 상태

| 항목 | 값 | 근거 |
|---|---|---|
| SPEC 요건(목표 흐름) | 코퍼스에 없는 TSC·Infineon 문서를 공식 사이트에서 받아 검증 관문을 거친 뒤 근거로 쓴다. 현재 구현은 TSC 공식 URL의 미검증 후보 탐색까지 | `SPEC.md:67` (2절) |
| 검증 관문 | Docling 2.145.0(OCR 끔)으로 모든 쪽을 파싱하고 표 숫자를 pdfplumber 글자와 대조한다. G5 평가는 실시간 조회를 끈 조건으로 실행한다 | `SPEC.md:291`, `SPEC.md:297` (6절) |
| 현재 MCP 웹 도구 | manifest에 있는 TSC 문서 ID만 외부 검색하고 목록 밖은 `unverified`로 막는다. SPEC의 코퍼스 밖 조회 흐름은 지원하지 않는다 | `backend/mcp_skill/mcp_server/server.py`의 `search_tsc_web` |
| manifest의 성격 | 과거 공개 출처 기록이라 현재 공개 상태·최신성을 보장하지 않고 개별 품번 목록과 같지 않을 수 있다. 공개 품번이라도 검색한 사실 자체가 외부에 노출된다 | `data/manifest.jsonl` |

## 3. 선택지

| 방안 | 사전 확인과 처리 | 장점 | 한계와 확인 사항 |
|---|---|---|---|
| 1. 공개 품번 목록 별도 관리 | 신뢰한 공식 자료로 목록을 만들어 로컬에서 정확히 대조하고 목록 밖은 차단 | 개별 품번을 외부에 보내기 전 대조 가능. 출처를 팀이 관리 | 범위·갱신 주기·담당자, 자동 수집·저장 허용 조건 필요. 미등록 공개 품번도 차단 |
| 2. 담당자 확인 후 목록 추가 | 미확인 품번은 검색을 멈추고 담당자가 공식 근거를 확인한 뒤 목록에 등록, 이후 검색 허용 | 사람이 근거와 예외를 검토. 1번을 점진적으로 확장 | 처리 지연과 담당자 부담. 담당자에게 품번을 전달하는 것과 확인 과정의 외부 전송 각각 승인 범위 필요 |
| 3. 사용자 확인 후 검색 | 전송할 품번·공급자를 사용자에게 보여 주고 확인을 받으면 검색 | 새 품번을 빠르게 처리 | 사용자 확인은 공개 여부의 증명이 아님. 외부 전송을 허용하므로 "공개로 확인된 품번만 허용"보다 완화된 정책이며 별도 결정 필요 |
| 4. 제조사 서비스 직접 확인 | 제조사 카탈로그·검색으로 품번 확인 | 공식 출처와 대조 | 개별 품번 조회가 제조사에도 전송됨. 품번 전송 없이 확보한 목록으로 먼저 확인하거나 별도 전송 권한 필요. API 존재·접근·이용 조건 미확인 |

논의 출발안은 1번 + 2번이다. 공개 품번 목록을 코퍼스와 별도로 관리하고, 목록에 없으면 외부 검색을 중단한다. 미확인 건은 권한 있는 담당자에게 내부적으로 전달하고, 전달·외부 확인의 권한과 절차를 먼저 확정한 뒤 검토한다. 확인할 수 없으면 판정 근거가 없음을 사용자에게 안내한다. 이 조합은 사람의 확인과 목록 갱신까지 즉시 실시간 조회를 보장하지 않으므로 코퍼스 밖 품번의 실시간 조회 요건 충족 방식은 별도 합의가 필요하다. 사용자의 "공개" 응답이나 정규식 일치는 공개 근거로 삼지 않는다.
