# SojaFit 오류 수정·검증 완료 내역

작성일: 2026-11-15<br>
대상: OSC 브랜치의 회로도 검색, 사용자 입력, 부품 판정, 대화 기억 개선 작업<br>
작성 시점: OSC `0676efb5`와 로컬 변경 사항 기준

회로도 검색을 점검하기 시작한 뒤 발견한 문제 중 수정과 검증을 마친 내용을 정리했습니다. 작업에 참여하지 않은 조원도 사용자가 겪은 문제, 발생 원인, 바뀐 동작을 한 줄씩 확인할 수 있도록 같은 형식의 표를 사용했습니다.

표의 결과는 각 작업 당시 남긴 기록을 기준으로 합니다. 보고서를 작성하면서 코드나 설정을 바꾸거나 테스트·외부 API 호출을 새로 실행하지 않았습니다.

## 표 읽는 방법

| 표시·용어 | 의미 |
|---|---|
| 실제 API·화면 | 로컬 서비스에 실제 요청을 보내고 브라우저 표시까지 확인했습니다. 검증에 사용한 주소는 `http://localhost:8011`입니다. |
| 자동 테스트 | 준비한 입력과 응답으로 오류를 재현하고, 수정 후 같은 검사가 통과하는지 확인했습니다. |
| HTTP 통합 테스트 | API와 렌더러 사이의 요청·응답을 연결해 검사했습니다. 외부 서비스 응답과 시간은 테스트에서 제어했습니다. |
| 문서·설정·코드 비교 | 안내 문구와 실제 설정·실행 코드·변경 목록을 대조했습니다. |
| 넷리스트 | 회로의 부품과 부품 사이 연결 정보를 담은 파일입니다. |
| 심벌 | 회로도에서 부품을 나타내는 기호입니다. `Device:D`는 특정 품번에 묶이지 않은 일반 다이오드 기호입니다. |
| 렌더러 | KiCad 원본이나 PDF를 화면에 표시할 이미지로 변환하는 구성 요소입니다. |
| 후보·캐시 | 후보는 검색 후 검사를 거친 참고 회로 자료입니다. 캐시는 이미 확인한 결과를 일정 시간 보관하는 기능입니다. |
| CDFER | SS33 사용 회로를 포함한 공개 프로젝트 `CDFER/Melbourne-Live-Train-Map`입니다. 연결된 도면 11장을 검증했습니다. |
| VF·누설전류 | VF는 다이오드의 순방향 전압입니다. 누설전류는 역방향 전압을 걸었을 때 흐르는 전류이며, 두 항목은 서로 다른 조건으로 다룹니다. |

회로도 검색은 참고 자료를 찾는 기능입니다. 표에서 정상 회로가 표시됐다는 것은 해당 품번의 사용 근거와 표시 동작을 확인했다는 뜻입니다. 대체 부품 판정과 사람의 승인은 별도 절차입니다.

## 1. 입력·업로드·프로젝트 사용 흐름

| 발견한 문제 | 원인 | 해결한 내용 | 확인된 효과 |
|---|---|---|---|
| 전송에 실패한 질문 초안이 사라졌습니다. 전송을 기다리며 새로 쓴 질문도 지워질 수 있었습니다. | 서버가 질문을 접수했는지, 현재 입력이 제출 당시 초안과 같은지 확인하기 전에 입력을 초기화했습니다. | 서버의 실행 번호가 확인된 뒤 제출 당시와 같은 초안만 한 번 비우도록 했습니다. | **자동 테스트:** 접수 실패 후 초안, 대기 중 새 입력, 첫 질문 전달, 공백을 포함한 질문의 처리를 확인했습니다. |
| 다른 프로젝트로 이동해도 이전 질문이나 부품 선택 오류가 남았습니다. | 화면의 입력 상태가 프로젝트 변경 뒤에도 유지됐습니다. | 실제 프로젝트 ID가 바뀔 때 질문과 부품 선택 오류를 초기화했습니다. | **자동 테스트:** 프로젝트를 전환하면 이전 질문과 오류가 현재 프로젝트에 섞이지 않는 것을 확인했습니다. |
| 한 파일만 처리하는 정책과 파일 선택·드롭 동작이 맞지 않았습니다. | 다중 선택, 여러 파일 드롭, 기존 첨부가 있을 때의 추가 선택 처리가 일관되지 않았습니다. | 파일 선택을 하나로 제한하고 추가 파일은 안내와 함께 거절했습니다. 기존 파일과 초안은 유지하고 같은 파일의 중복 선택은 무시했습니다. | **화면·자동 테스트:** 두 번째 파일을 선택해도 기존 첨부와 초안이 유지되는 것을 확인했습니다. |
| 업로드가 실패해도 파일을 어떻게 고쳐야 하는지 알기 어려웠습니다. | 인코딩, 넷리스트 문법, 요청 형식 오류를 구분한 안내가 부족했습니다. | 오류별로 UTF-8 재저장, 넷리스트 재내보내기 등의 안내를 제공했습니다. 기존 HTTP 400 응답과 오류 코드는 유지했습니다. | **실제 API:** 인코딩·문법·multipart 요청 형식 오류에 서로 다른 안내가 나오는 것을 확인했습니다. |
| 지원하지 않는 부품으로 새 검토에 진입할 수 있었습니다. | 부품 선택 화면과 직접 URL 진입의 제한이 일치하지 않았습니다. | 두 경로에서 새 검토를 막고 기존 저장 기록은 읽을 수 있도록 했습니다. | **화면·자동 테스트:** 범위 밖 부품 선택과 직접 진입이 차단되고 저장 기록 열람이 유지되는 것을 확인했습니다. |
| 다른 부품에 작성한 초안이 부품 선택과 함께 자동 전송됐습니다. | 선택한 부품과 초안의 대상이 같은지 확인하지 않았습니다. | 부품과 초안의 대상이 일치할 때만 초기 질문을 전달하도록 했습니다. | **실제 API·화면:** R1에 관한 초안을 남긴 뒤 D3를 선택했을 때 분석 요청은 0회였습니다. 전송 버튼을 눌렀을 때는 정상 요청이 발생했습니다. |

근거: [기존 프런트·회로도 보고서의 1~5번](frontend-schematic-work-summary-2026-11-15.md), [OSC 작업 기록](../worklog/osc.md)의 ‘프런트 전송 초안과 프로젝트 전환 오류 수정’, ‘UX 확인 항목 26·35·36·39 수정’, ‘사용자 검증의 다섯 동작 오류 수정’.

## 2. 회로도 검색·자료 검증·화면 표시

| 발견한 문제 | 원인 | 해결한 내용 | 확인된 효과 |
|---|---|---|---|
| 회로도의 출처와 원본 링크를 찾기 어려웠습니다. | 출처 정보가 이미지 뒤에 배치돼 있었습니다. | 출처, 원본 자료 링크, 게시 페이지를 이미지 위에 배치했습니다. | **실제 API·화면:** 회로도 위에서 출처를 확인하고 원본으로 이동할 수 있었습니다. 확대할 때도 출처 위치가 유지됐습니다. |
| 제조사 공식 여부와 라이선스 확인 상태가 혼동됐습니다. | 자료 분류, 공식 여부, 이용 조건이 문구에서 명확히 구분되지 않았습니다. | 제조사 공식 여부와 이용·재배포 조건 확인 여부를 따로 표시했습니다. | **화면:** 공식 확인과 라이선스 확인 상태를 각각 읽을 수 있었습니다. |
| 회로도 상단의 후보 버튼이 무엇을 바꾸는지 알기 어려웠습니다. | 현재 선택과 선택 후 바뀌는 내용에 대한 안내가 부족했습니다. | ‘현재 보는 자료’, ‘이 자료 보기’와 선택 상태를 표시하고 회로도·출처가 함께 바뀐다는 안내를 추가했습니다. | **화면·자동 테스트:** 현재 자료를 구분하고 다른 후보로 전환하는 동작을 확인했습니다. |
| Elektrotanya 후보를 열면 502 오류가 발생했습니다. | 외부 사이트가 기본 HTTP 클라이언트 식별값의 요청에 403을 반환했습니다. | 공개 이미지 요청에 서비스 이름을 밝힌 User-Agent를 지정했습니다. | **실제 API·화면:** 정보 응답과 이미지 응답이 모두 HTTP 200이었고, 3060×1980 이미지가 로드됐습니다. |
| SS33 다이오드 검색에 Ranger SS33 무전기 회로도가 나왔습니다. | 같은 문자열을 쓰는 제품과 부품의 검색 목적을 구분하지 못했습니다. | 제품·보드 검색과 다이오드 사용 회로 검색을 분리했습니다. 실제 배치 품번과 다이오드 근거를 검사하고 무전기 등 충돌 자료를 제외했습니다. | **실제 API·화면:** SS33 사용 회로가 표시됐고 Ranger 자료는 다이오드 검색에서 제외됐습니다. |
| 실제 사용 회로가 있어도 검색 후보에 들어오지 못했습니다. | 저장소 이름 중심 검색과 낮은 후보 상한에 의존했습니다. | 부품 목록 색인과 여러 GitHub 검색 경로를 결합했습니다. 후보 중복을 제거하고 수집·검사 상한을 24개로 맞췄습니다. | **실제 API·화면:** 최종 검증에서 SS33과 1N4148의 화면 후보를 각각 4개씩 선택해 표시했습니다. |
| `Device:D` 같은 일반 다이오드 기호를 쓴 정상 회로가 탈락했습니다. | 특정 심벌 라이브러리 이름에 치우쳐 다이오드를 분류했습니다. | 실제 배치된 참조번호와 품번, 심벌의 구조를 함께 확인하도록 했습니다. | **자동 테스트·실제 표시:** 일반 기호에 품번을 적은 정상 회로가 검증을 통과하고 표시됐습니다. |
| 사용자 정의 BAT54 심벌을 정상 다이오드로 인식하지 못했습니다. | 표준 심벌 이름에 의존해 프로젝트 자체 심벌을 놓쳤습니다. | 원문 설명과 양극·음극 핀 구조를 함께 검사하고 실제 부품의 참조번호·품번으로 연결했습니다. | **실제 API·화면:** `PoolController:BAT54`를 사용한 회로가 이미지로 변환돼 표시됐습니다. |
| 라이선스가 선언된 정상 저장소도 표기 차이 때문에 탈락했습니다. | 이전 GPL 식별자와 짧은 CERN 고지의 표현을 충분히 인식하지 못했습니다. | 명확한 라이선스 별칭을 정규화하고 고정 원문의 선언·적용 범위를 함께 확인했습니다. | **자동 테스트·화면:** 해당 선언을 가진 원문이 통과했고 GPL-3.0-only와 CERN-OHL-S-2.0 표시를 확인했습니다. |
| 한 저장소에 독립 회로가 여러 개 있으면 정상 회로도 함께 탈락했습니다. | 저장소에 시작 회로가 하나라고 가정했습니다. | 검색 부품을 포함하고 연결된 도면이 완전한 계층을 개별 후보로 선택했습니다. 완전한 하위 회로도 별도 선택할 수 있게 했습니다. | **실제 API·화면:** SS34의 독립 회로와 1N4148의 KBDevBoard 하위 회로가 표시됐습니다. |
| 후보 전환 과정에서 다른 원본이나 다른 검색의 결과가 섞일 수 있었습니다. | 원본 회로와 파일 형식별 선택·캐시 경계가 부족했습니다. | 고정 버전과 시작 도면별로 후보를 관리했습니다. 해당 검색에서 검증한 URL만 선택하고 같은 회로 안에서만 대체 파일을 사용하도록 했습니다. | **실제 화면·자동 테스트:** 후보별 원본을 유지했고, 다른 검색의 임의 URL 선택을 차단했습니다. |
| 큰 회로 파일이나 새 KiCad 형식의 원문을 열지 못했습니다. | 큰 파일의 파서 처리 제한과 KiCad 버전 차이가 있었습니다. | 업로드 파서의 제한은 유지하면서 렌더러에서 구조별로 검사하도록 보완하고 KiCad 10.0.8을 적용했습니다. | **실제 API·화면:** jolly 2장과 CDFER 11장의 변환·표시를 확인했습니다. |
| 직접 표시할 수 없는 구형 KiCad 원문이 선택 목록에 나왔습니다. | 부품 검증이 가능한 원문을 그대로 표시 가능한 후보로 취급했습니다. | 실제 표시 가능한 형식만 선택 목록에 제공하고 같은 회로에 연결된 PDF·이미지를 사용했습니다. | **실제 API·화면:** aqleds의 구형 회로에 연결된 PDF 4장이 표시됐습니다. |
| CDFER가 원문 검사에 도달하기 전 계속 누락됐습니다. | 필요한 버전 정보보다 큰 commit 응답이 정보 응답 상한을 넘었고, 연결 원문 총량도 기존 12MiB 상한을 넘었습니다. | 같은 고정 버전을 작은 branch 응답으로 조회했습니다. 전체 원문 읽기 예산은 렌더러와 같은 25MiB로 맞췄습니다. | **실제 API·화면:** CDFER가 검색 후보에 포함됐고 도면 11장, 고정 원본 링크, GPL-3.0-only 표시를 확인했습니다. |

## 5. 대화 기억·주제 전환

아래 A와 B는 검증 대화에서 구분한 두 설계 조건입니다. A는 최초 `150V·10mA`에서 `12V·20mA`로 정정했고, B에는 별도로 `36V·5mA·주변 온도 55°C·허용 누설 10µA`를 입력했습니다. `R02`는 이때 사용한 전원 회로 역할의 내부 분류 코드입니다.

| 발견한 문제 | 원인 | 해결한 내용 | 확인된 효과 |
|---|---|---|---|
| 이전 질문이 현재 질문의 답변에 다시 등장했습니다. | 과거 사용자 입력을 현재 질문 문자열에 합쳐 에이전트에 전달했습니다. | 현재 요청과 대화 이력을 분리했습니다. 과거 내용을 명시적으로 참조하는 질문에서 이력을 활용하도록 했습니다. | **실제 API·화면:** 패키지 질문과 다른 품번의 사양 질문에 과거 D3 역할 설명이나 1N4007 안내가 붙지 않았습니다. |
