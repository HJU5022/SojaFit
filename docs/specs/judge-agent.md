# 판정 에이전트와 대체품 찾기 작업서

> 2026-11-06 · 조장 하정운 결정(11-05~11-06 설계 대화). 역할 23개의 규칙 원본은 저장소 밖 `전자_데이터시트/`(`역할-23개-한눈에-2026-11-05.md`, `역할-판정-2차의견-2026-11-05.md`, `보류-5개-규칙안-2026-11-06.md`)에 있고, 구현 때 이 작업서의 규칙 파일 형식으로 `backend/judge/rules/roles.yaml`에 옮긴다. 판정 5종의 뜻과 순서는 SPEC 3절, 부품 사양 표는 ADR 0013을 따른다.

## Why

- **페르소나**: 소형 MCU 회로로 시제품·소량 생산을 하는 하드웨어 개발자(SPEC 1절).
- **상황**: 단종·재고 부족·원가 절감으로 다이오드 하나를 바꿔야 한다. "D1을 이 부품으로 바꿔도 돼?"(판정) 또는 "D1 대신 쓸 부품 찾아 줘"(대체품 찾기)라고 묻는다. 서비스의 결론은 대체품 찾기이고, 판정은 그 도구다.
- **문제**:
  1. 멀티 그래프에 판정 에이전트가 없어 판정 · 찾기 질문을 대부분 거절한다. #38에서 판정(candidate_judge) 과잉 거절 8, 찾기(candidate_find) 과잉 거절 8이었다. #31 단일 그래프에서는 과잉 거절 23건 중 19건이 이 두 종류였다(ADR 0013).
  2. 값 하나만 없어도 "문서로 확인 안 됨"으로 끝나고, 무엇이 빠졌는지와 무엇을 알려 주면 되는지 말하지 않는다.
  3. 역할 규칙이 샘플 회로 13개에서 뽑은 6개뿐이었다(정답 판정 기준표 3절).
- **측정 지표**: 판정 연습 문제(dev셋)의 역할 정답률과 판정 코드 일치율, 찾기 문항의 후보 적중. 마지막에 동결 v2 70문항의 판정 · 찾기 과잉 거절(#38 대비).

## Goal

- 판정 질문과 대체품 찾기 질문에 판정 5종(SPEC 3절)과 데이터시트 인용(쪽 · 표 · 행)으로 답한다. 숫자 비교와 단위 비교는 `backend/judge/`에서만 한다(AGENTS 7번).
- **성공 기준**(dev셋 기준. 측정 전에 `evals/guides/preregister.md`에 기대를 적는다):
  - 역할 정답률 80% 이상
  - 판정 코드 일치율 70% 이상
  - 질문에 없는 숫자로 낸 판정 0건, 인용 없는 판정 0건
  - LLM 호출은 문항당 읽기 1번(형식 재시도 최대 2번), 인터럽트는 문항당 최대 1번
  - 동결 v2 마지막 측정에서 판정 · 찾기 과잉 거절이 #38의 16건에서 8건 이하
- **Out of Scope**:
  - Mouser 가격 · 재고 조회(SPEC 1절 "하지 않는 것", 확장 단계, ADR 0009). 찾기 결과의 정렬 단계에 나중에 끼울 자리만 둔다.
  - 견적서 저장과 승인(SPEC 8.4), 웹 조회(근거 등급 2), 다이오드가 아닌 부품의 판정.
  - 사양 표에 열저항 · I²t · IFRM · 온도 계수 칸 추가(나중 작업. 그 전까지 해당 조건은 "사람 확인"으로 둔다).
  - 동결 평가셋(v1, v2) 수정.

## What

### 공통 흐름 (판정 · 찾기 모두)

1. Supervisor가 질문 종류를 `candidate_judge` 또는 `candidate_find`로 정하고 `judge`로 보낸다(검색 에이전트를 먼저 거치지 않는다. 판정에 쓰는 값과 인용은 사양 표가 준다).
2. **읽기**(LLM, Haiku 1번): 대상 주변 회로(`circuit_around`)와 질문으로 역할(아래 23개 또는 `other`)과 그 근거 핀, 회로 값, 원래 부품, 후보 품번(판정만), 원하는 패키지 · 분류를 정해진 칸으로 낸다.
3. **숫자 확인**(코드): 회로 값마다 그 숫자와 단위가 질문 글(사용 조건 포함)에 실제로 있는지 본다. 없으면 버리고 "빠진 값"으로 친다.
4. **규칙**(코드): 그 역할의 조건을 `roles.yaml`에서 읽는다. 조건은 세 층이다.
   - 필수: 사양 표 값과 회로 값으로 코드가 계산할 수 있는 조건
   - 조건부 필수: 발동 조건(PWM, 데이터선, 고온, OP앰프 없음 등)이 있을 때만 필수
   - 주의(사람 확인): 실제로 봐야 하지만 문서로 계산할 수 없는 것. 판정을 바꾸지 않고 답에 목록으로 붙인다
5. **묻기**(그래프 인터럽트): 필수 조건이나 조건부 발동 여부에 필요한 회로 값이 빠졌으면 한 번에 모아 묻는다. 사용자가 답하면 같은 thread에서 이어 간다.
6. **값 읽기**(코드, MCP `get_part_specs`): 원래 부품과 후보의 사양 표 행(값 · 시험 조건 · 인용)을 읽는다.
7. **비교와 판정**(코드, `backend/judge/verdict.py`): 조건마다 통과 · 실패 · 확인 안 됨을 정하고, SPEC 3절 순서로 판정 5종을 낸다. 패키지가 다르면 판정과 별도로 "기판 수정 필요"를 붙인다.

### 판정 질문 (후보가 질문에 있음)

8. 후보 하나하나의 판정을 답으로 만든다.

### 대체품 찾기 질문 (후보를 찾음)

8. 필수 조건 중 숫자 하한 · 상한인 것을 사양 표 검색 조건으로 바꿔 `find_parts_by_specs`(MCP, 최대 50개)로 거른다. 원하는 패키지 · 분류도 건다. 시험 조건이 중요한 값(VF 등)은 거르기에 쓰지 않고 7단계에서 본다.
9. 거른 후보마다 7단계로 판정한다.
10. 정렬: 판정 순서(동일품 → 사양 동등 → 역할상 충분) → 같은 판정 안에서는 기판 수정이 필요 없는 부품 먼저 → 품번 순. 불충족은 뺀다. 판정별 상위 3개, 모두 합쳐 최대 5개를 보여 준다. "확인 안 됨" 후보는 견적 대상이 아니므로 따로 표시한다(SPEC 2절).

### 답 (작성 에이전트)

- 판정 경로의 답은 **코드가 만든 틀**로 쓴다. 숫자와 인용을 LLM이 다시 쓰지 않게 하려는 것이다. 틀은 다음 순서다.
  1. 판정
  2. 조건 표(조건, 기준과 계산식, 후보 값과 시험 조건, 통과 여부, 인용)
  3. 빠진 값과 "이걸 알려 주면 판정할 수 있다"
  4. 불확실한 조건
  5. 사람이 확인할 것
  6. 기판 수정 필요
  7. "같은 동작은 보장하지 않는다"
- "문서로 확인 안 됨"이어도 찾은 값 · 조건 · 빠진 것은 모두 보여 준다(ADR 0006).

### 역할 23개

R01 역극성 보호(직렬), R02 역류 방지, R03 릴레이 플라이백(켜고 끄기만), R04 제너 클램프 · 전압 기준, R05 AC · 브리지 정류, R06 ESD · TVS, R07 병렬 역극성 보호, R08 입력 핀 보호, R09 전압 낮추기, R10 신호선 다이오드 OR, R11 벅 프리휠링, R12 부스트 출력, R13 플라이백 전원 출력, R14 RCD 스너버, R15 부트스트랩, R16 차지펌프(양전압 2배 · 음전압), R17 피크 검파(피크 홀드 · 포락선), R18 게이트 보호 제너, R19 게이트 빨리 끄기, R20 레귤레이터 보호, R21 리셋 방전, R22 PWM 모터 프리휠링, R23 키 매트릭스 격리. 역할마다 규칙이 있다(11-05 정운 판정 18개, 11-06 보류였던 5개 채택). 공통 여유는 전압 ×1.25(정격의 80%), 전류 ×1.43(정격의 70%)이고, R13 · R14 · R16의 역할별 여유는 규칙 원본을 따른다.

### Edge Cases

| # | 상황 | 처리 |
|---|---|---|
| EC-01 | 역할이 `other`(23개 밖) | 판정하지 않는다. 찾은 값과 "이 역할은 판정 규칙이 없다"를 답한다 |
| EC-02 | 역할이 둘로 갈림(예: RESET→VCC 다이오드 하나 = R08 또는 R21) | 하나로 단정하지 않고 두 후보를 인터럽트로 확인한다. 답이 없으면 두 역할로 모두 판정하고 더 나쁜 판정을 낸다 |
| EC-03 | 읽기가 질문에 없는 숫자를 냄 | 버리고 빠진 값으로 친다(3단계) |
| EC-04 | 인터럽트에 답이 없음(평가 실행 포함) | 필수 값이 빠지면 그 조건은 확인 안 됨(→ "문서로 확인 안 됨"). 조건부 발동 여부가 빠지면 그 조건 없이 판정하고 "불확실한 조건"에 적는다. 기본값을 쓰는 규칙(R14 · R17)은 기본값으로 판정했다고 밝힌다 |
| EC-05 | 원래 부품이 코퍼스에 없거나 품번이 없음 | 동일품 · 사양 동등은 내지 않는다(SPEC 3절). 역할상 충분까지만 낸다 |
| EC-06 | 후보 값의 시험 조건이 기준과 다름(온도 TA/TJ, 시험 전류 · 전압, 펄스 폭 · 파형) | 그 조건은 확인 안 됨. 더 가혹한 조건의 값으로 한계를 추정하지 않는다. 조건 칸이 비면 표 제목의 기본 조건(예: TA=25°C unless otherwise noted)을 쓴다. 역전압 정격(VRRM · VR · VRWM)은 온도로 줄지 않아 사용 온도를 맞추지 않는다(11-06) |
| EC-07 | 후보 품번이 사양 표에 없음(코퍼스에는 있음) | 그 후보는 확인 안 됨. 찾아본 문서를 적는다. 코퍼스에 아예 없는 품번은 사실 확인(`part_missing`)이 먼저 처리한다 |
| EC-08 | 찾기 결과 0개 | 건 검색 조건을 그대로 보여 주고 "이 조건을 모두 채우는 TSC 부품을 사양 표에서 찾지 못했다"고 답한다 |
| EC-09 | 찾기 후보가 50개 상한에 걸림 | 상한에 걸렸다고 밝히고 패키지 · 분류를 좁히길 권한다 |
| EC-10 | 제조사가 같은 제품이라고 밝힌 주문 코드(예: 1N4148 A0G · R0G) | 동일품. 근거는 그 문장이 있는 청크다 |

## How

### 파일

| 파일 | 할 일 |
|---|---|
| `backend/judge/rules/roles.yaml`(새) | 역할 23개의 알아보는 법, 조건(층 · 코드 · 비교 · 기준식 · 발동 조건), 되물을 값, 주의 목록, 출처 |
| `backend/judge/verdict.py`(새) | 규칙 읽기, 기준 계산, 시험 조건 맞추기, 조건별 비교, 판정 5종, 찾기 검색 조건 만들기, 후보 정렬. LLM · DB를 부르지 않는다(값은 인자로 받는다) |
| `backend/multi_agent/agents/judge.py`(새) | 판정 에이전트: 읽기 → 숫자 확인 → 인터럽트 → 사양 표 조회 → `verdict` → 보고서 |
| `backend/prompts/judge_read.md`(새) | 읽기 프롬프트(영어, Langfuse `judge_read`) |
| `backend/multi_agent/build.py` · `supervisor.py` · `backend/prompts/supervisor.md` | `judge` 노드 연결과 `judge_enabled` 켜기. 판정 · 찾기 모두 `judge`로 보내게 프롬프트를 고친다(Langfuse 새 버전) |
| `backend/multi_agent/agents/writer.py` | 판정 결과가 있으면 코드 틀로 답한다 |
| `backend/graph/nodes.py` `circuit_around` | 큰 넷에서 앞 `MAX_NET_NODES`개만 보여 줘 대상 자신의 핀이 잘리는 문제를 고친다(대상 핀은 늘 넣는다) |
| `pyproject.toml` · `uv.lock` | `uv add pyyaml`(지금은 다른 패키지를 통해서만 잠금 파일에 있다) |

### 규칙 파일 형식(예: R01)

```yaml
R01:
  name: 역극성 보호(직렬)
  recognize: 커넥터·배터리 → 다이오드 → 전원 넷, 캐소드가 부하 쪽   # 읽기 프롬프트에 넣는다
  inputs: [v_in_max, i_max, v_drop_allowed]                              # 되물을 수 있는 회로 값
  conditions:
    - {tier: required, code: [VRRM, VR], op: ">=", basis: "v_in_max * kV"}
    - {tier: required, code: IF_AV, op: ">=", basis: "i_max * kI"}
    - {tier: conditional, code: VF, op: "<=", basis: "v_drop_allowed", when: "v_drop_allowed", at: {IF: i_max}}
  cautions: [발열(열저항 칸이 생기면 필수로)]
  source: "TI SLVA139 [문서]"
```

- `basis`는 회로 값 이름 · 숫자 · `kV`(1.25) · `kI`(1/0.7)와 사칙 연산만 쓴다. `verdict.py`가 정해진 문법만 읽는다(임의 코드 실행 없음).
- `orig.<코드>`(원래 부품 값)는 후보 행과 시험 조건이 같은 원래 부품 행의 값이다. 같은 조건의 원래 행이 없으면 그 조건은 확인 안 됨이고, `orig.*`를 쓰는 조건은 찾기 거르기에 쓰지 않는다(11-06).
- 회로 값 이름은 `roles.yaml`의 `inputs`를 모은 목록 하나로 고정한다. 읽기 출력 칸도 이 목록이다.

### 읽기 출력(구조화 출력, pydantic)

- `role`(R01~R23 · `other`), `role_alt`(갈릴 때 두 번째 후보, EC-02), `role_evidence`(근거 핀 목록, 예: `D1.K → +5V`)
- `values`: 회로 값 이름 → {`value`, `unit`, `quote`(질문에서 그대로 옮긴 글)}
- `original_part`, `candidates`(판정만), `package_wanted`, `category_wanted`

### 인터럽트

- LangGraph `interrupt({"missing": [...], "role_choices": [...], "question": "<한국어 질문 하나>"})`로 묻고, 재개 값은 `{"answers": {회로 값 이름: 값}, "role": <고른 역할, 있으면>}`이다. 체크포인터가 필요하다(`build_graph(checkpointer=...)`).
- 평가 실행기(`evals/runners/run_graph.py --multi`)는 인터럽트를 만나면 `{"answers": {}}`(= 모름, EC-04)로 한 번 재개한다. [주의] 빈 dict(`{}`)로 재개하면 LangGraph 1.2.18이 재개로 보지 않고 다시 멈춘다(11-06 실측).

### 한도 · 비용

- 읽기 1번 + 형식 재시도 최대 2번, 인터럽트 1번, 찾기 후보 50개, 답에 보여 주는 후보 최대 5개.
- 읽기 모델은 서브에이전트 기준 Haiku다(ADR 0014). lab에서는 정운 개인 Anthropic 키로 부른다.

## AC (Given-When-Then)

**AC-01 · 판정: 기준 미달이면 불충족**
- GIVEN: 역할 R01, 사용 조건 "입력 최대 20V, 최대 순방향 전류 150mA, 주변 25°C", 후보 1N5817(사양 표 VRRM 20 V, TA=25°C)
- WHEN: 판정한다
- THEN: VRRM 조건(≥ 25 V)이 실패해 `NOT_SUFFICIENT`. 조건 표에 기준 25 V, 후보 20 V, 인용(1N5817 SERIES_H2104.pdf 1쪽)이 있다

**AC-02 · 질문에 없는 숫자는 버린다**
- GIVEN: 질문에 전압이 없는데 읽기가 `v_in_max = 12 V`를 낸다
- WHEN: 숫자 확인을 한다
- THEN: `v_in_max`는 빠진 값이 되고 인터럽트 질문에 들어간다

**AC-03 · 필수 값이 끝내 없으면 확인 안 됨, 그래도 찾은 것은 보여 준다**
- GIVEN: 역할 R03, 코일 전류가 없고 인터럽트 재개 값이 비어 있다
- WHEN: 판정한다
- THEN: `NOT_VERIFIED`. 답에 후보의 VRRM · IFSM과 인용, 통과한 조건, "코일 정상 전류를 알려 주면 판정할 수 있다"가 있다

**AC-04 · 조건부 발동 여부를 모르면 나머지로 판정하고 불확실을 밝힌다**
- GIVEN: 역할 R02, 필수 조건(역전압 · 전류 · 25°C IR)은 모두 통과하고, 고온에서 쓰는지는 질문에 없으며 인터럽트 재개 값도 비어 있다
- WHEN: 판정한다
- THEN: 고온 IR 조건 없이 판정을 낸다. "불확실한 조건"에 "고온에서 쓰면 같은 온도의 IR을 비교해야 한다"가 있다

**AC-05 · 시험 조건이 다르면 그 조건은 확인 안 됨**
- GIVEN: R03 후보의 IFSM이 8.3 ms 반정현파 값이고, 질문의 차단 펄스는 1 ms 단발이다
- WHEN: IFSM 조건을 비교한다
- THEN: 그 조건은 `unverified`이고 더 가혹한 조건 값으로 추정하지 않는다

**AC-06 · 찾기: 거르고 판정하고 줄 세운다**
- GIVEN: 역할 R01, "입력 최대 12V, 부하 10mA, 표면실장, 기판 수정 가능"
- WHEN: 대체품을 찾는다
- THEN: `find_parts_by_specs`에 VRRM(또는 VR) ≥ 15 V, IF_AV ≥ 0.0143 A 조건이 걸린다. 불충족 후보는 빠진다. 답은 판정 순서 → 기판 수정 불필요 순으로 최대 5개이고, 후보마다 판정과 인용이 있다

**AC-07 · 규칙이 없는 역할은 판정하지 않는다**
- GIVEN: 읽기가 `role = other`를 낸다
- WHEN: 판정 에이전트가 돈다
- THEN: 판정 코드 없이 찾은 값과 "이 역할은 판정 규칙이 없다"를 답한다

**AC-08 · 호출 상한**
- GIVEN: 읽기 출력이 형식 검사를 계속 어긴다
- WHEN: 판정 에이전트가 돈다
- THEN: 읽기 호출은 3번(처음 + 재시도 2)을 넘지 않고, 인터럽트는 1번을 넘지 않는다

**AC-09 · 숫자 비교는 judge에서만**
- GIVEN: 판정 에이전트 코드
- WHEN: 시험을 돌린다
- THEN: 기준 계산과 비교는 `backend/judge/verdict.py` 함수로만 하고, 에이전트와 프롬프트는 숫자를 비교하지 않는다(가짜 LLM 시험으로 확인)

**AC-10 · 대상 핀은 잘리지 않는다**
- GIVEN: 대상 다이오드가 노드 9개 이상인 GND 넷에 붙어 있다
- WHEN: `circuit_around`를 부른다
- THEN: 그 넷의 보여 주는 노드에 대상 자신의 핀이 들어 있다
