# SojaFit 작업대 정보 구조

## Why

- **페르소나**: KiCad 회로에서 교체 대상 부품을 검토하고 근거와 판정을 승인하는 개발자
- **상황**: 프로젝트 선택부터 D5 질문, 추가 입력, 근거 검토, 승인과 견적까지 한 화면에서 수행한다.
- **문제**: 기존 3열 화면은 대화와 결과의 우선순위가 약하고, 근거·판정·활동을 오가며 현재 실행 상태를 파악하기 어렵다.
- **측정 지표**: 핵심 흐름의 화면 이동 0회, 키보드만으로 모든 dialog 열기·닫기 가능, 1440×900과 390×844에서 가로 넘침 0건

## Goal

- **해결 목표**: 기존 API·DTO·SSE·인증·D5 순서를 유지하면서 상단 앱 바, 기능 레일, 넓은 분석 작업면, 우측 정보 콘솔의 4영역 작업대를 제공한다.
- **성공 기준**: 실제 SSE 상태만 표시하고, 회로·근거·판정·활동을 우측 탭에서 전환하며, dialog가 focus trap·Esc·focus 복귀를 지원한다.
- **Out of Scope**: 새 검색 API, 가짜 검색 결과, 공개 회원가입, D5 단계·판정 규칙 변경, 가격·재고 저장, 실제 PCB 이미지, 외부 UI 라이브러리

## What

**Happy Path**
1. 사용자가 기능 레일에서 프로젝트를 열고 공개 데모 또는 KiCad `.net` 프로젝트를 선택한다.
2. 화면 내 프로젝트와 현재 회로 부품만 검색해 대상 부품을 고른다.
3. 질문을 보내면 실제 SSE 단계가 카드와 활동 탭에 표시된다.
4. 추가 정보가 필요하면 같은 실행을 재개하고, 완료 뒤 근거와 5종 판정을 우측 탭에서 검토한다.
5. 후보·근거 상세을 확인한 뒤 명시적으로 승인하고, 견적 dialog를 열 때 가격·재고를 새로 조회한다.

**Edge Cases**

| 상황 | 처리 방식 |
|---|---|
| 실제 통합 검색 API가 없음 | 불러온 프로젝트와 현재 회로 부품만 검색 |
| 값이나 citation 위치가 없음 | 추측하지 않고 `확인 안 됨` 또는 `MISSING` 표시 |
| SSE 연결 종료 | 기존 run GET 복구를 유지하고 질문을 재전송하지 않음 |
| 비로그인 사용자가 계정을 요청 | 관리자 생성 또는 Google 연결 승인 절차만 안내 |
| 우측 공간이 부족함 | 패널 너비 조절·접기, 900px 이하에서는 전체 폭 결과 영역 사용 |
| 모션 감소 설정 | 장식 움직임 없이 즉시 상태 변경 |

## How

- 기존 React + Vite 구조와 CSS 의미 토큰을 사용하며 색상 팔레트는 바꾸지 않는다.
- `WorkbenchPage`가 레이아웃과 로컬 탐색 상태만 소유하고, 데이터는 기존 project/query, `useRunStream`, 안전 DTO에서 받는다.
- 기능 레일의 근거·판정·승인 항목은 새 페이지 대신 우측 정보 콘솔을 활성화한다.
- 우측 패널은 기존 `CircuitSummary`, `EvidencePanel`, `JudgementTable`, 승인·견적 컴포넌트를 재사용한다.
- 공통 dialog는 `role="dialog"`, `aria-modal`, `aria-labelledby`, focus trap, Esc, focus 복귀를 제공한다. 승인 확인은 backdrop 클릭으로 닫히지 않는다.
- production fixture fallback과 production 더미 로그인은 추가하지 않는다. 가격·재고·URL·조회 시각은 승인 사례와 견적 snapshot에 넣지 않는다.
- 애니메이션은 160~220ms 상태 전환으로 제한하고 `prefers-reduced-motion: reduce`에서 제거한다.

## AC (Given-When-Then)

**AC-01 · 4영역 데스크톱 작업대**
- GIVEN: 인증된 사용자가 1440×900에서 작업대를 연다.
- WHEN: 프로젝트와 대상을 선택한다.
- THEN: 상단 앱 바, 기능 레일, 분석 작업면, 조절 가능한 우측 정보 콘솔이 함께 보인다.

**AC-02 · 실제 실행 상태**
- GIVEN: D5 run이 시작되거나 추가 입력을 요구한다.
- WHEN: SSE 또는 run 복구 응답을 받는다.
- THEN: 수신한 단계만 카드와 활동 탭에 표시하고 가짜 퍼센트나 예상 시간을 표시하지 않는다.

**AC-03 · 근거와 후보 상세**
- GIVEN: 안전 DTO에 citation과 후보 판정이 있다.
- WHEN: 사용자가 근거 또는 후보 상세를 연다.
- THEN: 제공된 문서 위치·checks만 표시하고 없는 값과 PDF 원문을 만들지 않는다.

**AC-04 · 접근 가능한 dialog**
- GIVEN: 키보드 사용자가 dialog를 연다.
- WHEN: Tab, Shift+Tab, Esc를 사용한다.
- THEN: focus가 dialog 안에서 순환하고 닫은 뒤 원래 버튼으로 돌아간다. 승인 dialog는 backdrop 클릭으로 닫히지 않는다.

**AC-05 · 반응형과 모션 감소**
- GIVEN: 390×844 화면 또는 모션 감소 설정이다.
- WHEN: 프로젝트·대화·결과와 dialog를 사용한다.
- THEN: 단일 열/전체 폭 결과 화면으로 전환되고 composer를 가리지 않으며 불필요한 motion이 없다.

**AC-06 · 기존 계약 유지**
- GIVEN: 질문→추가 입력→판정→근거→승인→견적 흐름이다.
- WHEN: 사용자가 전체 흐름을 수행한다.
- THEN: 기존 API 요청 형식, 안전 DTO, SSE 복구, 사용자 소유권, 가격 없는 견적 저장 계약이 유지된다.
