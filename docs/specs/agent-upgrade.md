# 에이전트 보강 (큰 흐름)

- 상태: 진행 중. 큰 흐름의 기준만 정한다. 세부는 조각마다 바꾸고 재 보면서 정하고, 큰 흐름이 바뀌면 이 문서를 고친다
- 기준일: 2026-11-26
- 기준 커밋: `3195d9bd`(로컬 태그 `freeze-2026-11-22`, 개인 사본 `main`과 같음). 보강이 잘못되면 여기로 돌아온다
- 정본 여부: 비정본(정본: [SPEC.md](../../SPEC.md) 2절 멀티 그래프). 조각이 들어가면 SPEC 해당 절을 같은 커밋에서 고친다(AGENTS.md 지킬 것 8)
- 관련 문서: [backend/multi_agent/MULTI_AGENT.md](../../backend/multi_agent/MULTI_AGENT.md), [mcp-search-tools.md](mcp-search-tools.md), [mcp-graph-integration.md](mcp-graph-integration.md), [local-live-api.md](local-live-api.md)

## Why

- 지금 에이전트는 LLM이 도구를 고르지 않는다(2026-11-26 코드 확인).
  - `backend` 전체에 LLM 도구 호출(`bind_tools` · `tool_calls` · `ToolNode`)이 없다.
  - RAG 에이전트(`backend/multi_agent/agents/docs.py`의 `docs_agent`)는 검색 · 재검색 · 웹 조회를 코드 분기가 정한다. `docs_agent`부터 파일 끝까지 약 460줄, `if` · `elif` 약 80개다. LLM은 근거 채점과 답 쓰기만 한다.
  - Supervisor는 LLM 1번으로 계획을 통째로 짜고, 실패했을 때만 재계획한다.
  - MCP 서버(`backend/mcp_skill/mcp_server/server.py`)의 도구 6개 중 서비스가 부르는 것은 `check_corpus` 하나이고, 그것도 코드가 부른다. 실제 일을 하는 도구(사양 카드, 공식 PDF, 웹 참고, 판정)는 MCP 밖에 있다.
- 이 보강에서 에이전트의 뜻: LLM이 스스로 도구를 골라 사용자에게 최대한의 정보를 주고, 그 정보를 믿을 만한지 함께 보인다. 화면 버튼으로 하던 일도 채팅 안에서 에이전트가 한다.

## Goal

- 우선순위: ① 속도 · 정확도 ② 에이전트가 스스로 도구를 씀 ③ 디자인 · 편의.
- 큰 순서: 에이전트 코어(이 문서) → 버튼 동작을 도구로 → 디자인.
- 성공 기준:

| 단계 | 기준 |
|---|---|
| 통과(바꾼 코드를 기본으로 둠) | v3 50문항 통과 수가 바꾸기 전 이상이고, p95가 바꾸기 전보다 늘지 않는다. 같은 날 같은 조건으로 잰다 |
| 목표 | p95 10초 이하, 첫 반응(화면에 진행이 보이기 시작) 2초 이내 |
| 예외 | 정확도가 올랐는데 p95가 2초 안쪽으로 늘었으면 정운이 판단한다 |

- 이 문서 밖: 버튼 동작의 도구화와 디자인은 에이전트 코어가 끝난 뒤 따로 정한다. LLM이 문서에서 점과 선을 뽑는 방식(Microsoft GraphRAG)은 쓰지 않는다.

## What (조각 순서)

조각마다 바꾸기 전에 재고 → 한 가지만 바꾸고 → 시험하고 → 재고 → 기록한 뒤 다음으로 간다. 잰 결과에 따라 순서를 바꿀 수 있다.

| 조각 | 바꾸는 것 | 무엇으로 재나 |
|---|---|---|
| 0. 정리 | 쓰지 않는 영역의 후보표를 만들고(정운이 짚은 곳 + 서비스가 실제로 쓰는지 코드로 확인한 곳), 하나씩 지우며 시험한다 | 전체 pytest, 동결 해시 검사 |
| 1. 도구 반복 | RAG 에이전트의 검색 반복만 바꾼다. 첫 검색은 코드가 Supervisor의 검색어로 미리 하고, LLM이 근거를 보고 답하거나 도구를 부른다. 도구는 `search_docs`(검색 + 다른 품번 줄 · 판본 거르기 + 변형 주석)와 `check_parts`(코퍼스에 있는지) 둘이다. 앞단(역할 답, 사양 찾기)과 공식 PDF · 웹 단계는 그대로 둔다 | v3 50문항(회귀) |
| 2. 그래프 검색 | 부품 관계 그래프(품번 → 시리즈 · 분류 · 패키지 · 접미 변형 · AEC-Q101)를 로컬 Neo4j에 만들고 도구로 준다. 점과 선은 LLM 없이 코드로 만든다 | 새 세트의 그래프 문항, 켜고 끈 비교 |
| 3. 웹 + CRAG | 공식 PDF · 웹 참고를 도구로 주고, 근거가 부실하면 다시 찾는 판단을 에이전트가 한다 | v3 50문항, 새 세트 |
| 4. 판정 도구 | Spec 에이전트를 도구로 준다. 숫자 비교는 계속 `backend/judge/`가 한다 | v3 50문항 |
| 5. 체감 속도 | 도구 단위 진행 표시, 프롬프트 캐시, 도구 동시 호출 | 첫 반응 시간, p95 |

## How (원칙)

- 한 조각에 한 가지만 바꾼다(AGENTS.md 지킬 것 3). 바꾸기 전 코드는 동결 태그를 다른 폴더(`git worktree`)로 꺼내, 같은 날 같은 키 · 같은 환경변수로 잰다.
- 버전을 나누지 않는다. 같은 코드를 계속 고치고, 새 파일 · 스위치로 두 벌을 두지 않는다.
- 로컬호스트에서 증명하고, 운영 서버에서만 할 수 있는 일이 있을 때만 배포한다. 로컬 실행은 운영 DB에 쓰지 않는다([local-live-api.md](local-live-api.md)).
- 도구는 MCP 서버에 모은다. 에이전트는 같은 프로세스 안의 메모리 통로로 부른다(Marvia v2 `src/marvia/rag/mcp.py`와 같은 방식). 도구 안에서는 LLM을 부르지 않는다. 사용자가 누구인지는 LLM 인자가 아니라 코드가 넣는다. 메모리 통로가 동기 노드에 맞지 않으면 함수를 직접 부르는 것으로 시작하고, MCP로 옮기는 일은 별도 조각으로 한다.
- 반복 구조는 LangChain `create_agent`와 미들웨어로 만든다(Marvia v2 `src/marvia/graph/agent.py`). 상한은 프롬프트가 아니라 미들웨어 코드가 막는다(AGENTS.md 지킬 것 6). 조각 1은 문서 할 일 하나에 도구 2번(`DOCS_MAX_SEARCHES`), LLM 3번이다.
- LLM 호출은 `backend/services/llm.py`를 거친다(지킬 것 2). 도구 호출용 입구를 거기에 더해 노드별 모델 · 예산 차감 · Langfuse 기록 · 키 없는 데모의 기록 · 재생이 그대로 적용되게 한다.
- 결과는 지금과 같은 `TaskReport`로 Supervisor에 돌려준다. 여러 번 검색해도 근거 번호가 겹치지 않고, `docs`는 찾은 근거 전부, `searches`는 도구 호출마다 한 줄이다. 인용 검사 · 숫자 검사 · 기억 참조 검사는 반복이 끝난 뒤 코드가 한다.
- 평가: v3 50문항은 회귀 확인에 쓴다. 새 세트 20 ~ 30문항(그래프 관계 질문, 도구를 이어 써야 하는 질문, 근거가 부실해 다시 찾아야 하는 질문)은 그 능력을 넣는 조각보다 먼저 만들어 동결한다. 동결한 평가셋은 고치지 않는다(지킬 것 1).
- 유료 측정은 [evals/guides/preregister.md](../../evals/guides/preregister.md)에 먼저 적고, 비용을 정운에게 알린 뒤 돌린다. 같은 코드도 모은 p95가 13.0초와 15.5초로 흔들렸으므로(2026-11-15) 여러 세트로 잰다.
- 기록: 조각마다 [docs/worklog/jeongun.md](../worklog/jeongun.md)에 바꾼 파일 · 실행한 명령 · 결과 · 확인 못 한 것을 적는다. 결정과 측정값은 정운의 위키 SojaFit 쪽에도 적는다. 커밋 · 푸시는 그때마다 정운에게 묻는다.

## 아직 확인하지 않은 가정

| 가정 | 틀리면 | 확인 방법 |
|---|---|---|
| mcp 1.30.0의 메모리 통로(`create_connected_server_and_client_session`)가 동기 노드에서 동작한다. 지금 `StdioMcpRetriever`의 뒤쪽 스레드 이벤트 루프 방식을 쓴다 | 함수 직결로 시작 | 로컬 스크립트(무료) |
| OpenRouter를 거친 Haiku 5.5가 도구를 제대로 부른다 | 모델이나 경로를 다시 고름 | 몇 번 호출(유료, 소액) |
| 마지막 구조화 답이 LLM 호출을 한 번 더 만들지 않는다 | 답 형식을 바꿈 | 몇 번 호출(유료, 소액) |
| 근거가 충분한 보통 질문은 LLM 1번으로 끝나 속도가 유지된다 | 통과 기준을 못 지킴 | 조각 1 측정 |
| 지금 쓸 수 있는 키(OpenRouter · Voyage · Exa)가 있고, 로컬 `.env`가 운영 DB를 가리키지 않는다 | 측정을 못 하거나 운영 DB에 기록이 남음 | 정운 확인 |

## AC (Given-When-Then)

**AC-01 · 조각마다 나빠지지 않음**
- GIVEN: 바꾸기 전 코드(동결 태그 또는 직전 조각)와 바꾼 코드
- WHEN: 같은 날 같은 조건으로 v3 50문항을 여러 세트 잰다
- THEN: 통과 수가 바꾸기 전 이상이고 p95가 늘지 않는다. 아니면 그 조각은 기본으로 두지 않는다

**AC-02 · 반복 상한**
- GIVEN: 도구를 계속 부르는 가짜 LLM
- WHEN: 문서 할 일 하나를 돌린다
- THEN: 도구 호출 2번 · LLM 호출 3번을 넘지 않고, 지금까지의 근거로 답하거나 실패 보고를 낸다

**AC-03 · 새 능력의 효과**
- GIVEN: 구현 전에 동결한 새 세트
- WHEN: 그 능력을 켠 코드와 끈 코드를 같은 조건으로 잰다
- THEN: 켠 쪽이 그 문항들에서 더 많이 통과한다. 아니면 그 능력은 기본으로 켜지 않는다(Marvia ADR 0062와 같은 판단)
