# 평가 분류 기준 정리와 관련 문항 2건 추가

## Why

- 평가 검수자가 사용자 동작 조건 부족과 코퍼스 근거 부족을 구분해야 한다. 두 경우를 섞으면 같은 NOT_VERIFIED 답변도 관련/비관련이 달라져 거절 지표를 해석하기 어렵다.
- h03을 missing_attribute로 바꾸면 기존 50건은 관련 24·비관련 26이다. 판정을 수량에 맞추지 않고 관련 문항 2건을 더한다.
- 측정 지표: 고유 문항 수, 관련/비관련 수, 변경된 사람 판정 이력과 근거의 보존 여부.

## Goal

- 검수 초안 52건, 관련 26·비관련 26. 기존 50개 ID와 질문을 보존하고 2개 ID를 추가한다.
- 사용자 조건 부족은 근거가 있는 적합성 검토의 relevant + NOT_VERIFIED로, 핵심 답변에 필요한 문서 속성 부재는 irrelevant / missing_attribute로 구분한다.
- Out of Scope: 서비스 판정 코드 변경, 새 코퍼스 수집, 모델 실험·평가 측정, 동결, 두 사람 검수를 AI로 대체하는 것.

## What

- Happy Path: EVALS.md에 분류 기준 기록 → SPEC.md에서 기준 참조 → n01·n02·h03 변경 의견을 현재 초안에 반영하고 이전 답안 보존 → 정답을 보지 않은 별도 AI의 질문 2건에 대해 다른 AI가 PDF 근거 확인 → 검토표에 추가 → 52건 구성·원문·변경 범위 검사.
- 관련 문서가 있다는 사실만으로 relevant로 분류하지 않는다. 질문의 핵심 요청에 답할 수 있는지 먼저 본다.
- 부품 정격 조회에는 조건을 명시한 값을 답할 수 있고, 부가적인 대체 적합성만 미확정이면 relevant다(e04·e08).
- 적합성을 묻고 문서 근거는 있으나 사용자의 TA·펄스 조건이 없어 적용할 수 없으면 relevant + NOT_VERIFIED다(n01·n02).
- 보장 수치가 핵심 요청인데 필요한 문서 속성이 없으면 주변 설명이 가능해도 missing_attribute다(h03·n14).
- 추가 문항에 충분한 근거가 없으면 related 수량을 맞추려고 강제 채택하지 않는다. 새 두 문항은 두 사람 검수 전까지 동결 금지다.

## How

- 기존 경로 `evals/draft_50.jsonl`, `evals/DRAFT_50_REVIEW.md`를 52건으로 확장한다. 파일명의 50은 최초 초안 건수이며 이름을 유지해 기존 링크를 보존한다.
- 새 ID는 `draft52-n21`, `draft52-n22`. 기존 source·target·NET 해시 형식을 따른다. 질문과 input에는 답변 방향·평가 분류·정답 숫자를 넣지 않는다.
- n01·n02의 현재 정답 초안은 NOT_VERIFIED, h03은 irrelevant / missing_attribute로 바꾸되 종전 expected·why·kind·gold_chunks와 사람 판정을 answer_review에 보존한다. 변경된 세 문항에는 1차 판정자 재검수 대기를 명시한다. 사람 2차의 X는 이전 답안에 대한 의견이며 새 답안 최종 승인으로 바꾸지 않는다.
- 비관련 gold_chunks는 빈 목록으로 두되, h03의 기존 근거는 검수 이력에 보존한다.
- 새 두 문항에는 출제 AI와 답안 작성 AI가 분리되었음을 기록한다. 김재훈의 2026-11-02 O를 사람 2차 판정에 보존하고, 하정운의 사람 1차 판정은 대기로 둔다. PDF 페이지·표·행·시험 조건과 manifest SHA256을 대조한다.
- 합의·작업 기록은 ADR과 jaehun worklog에 남긴다. 기존 dataset_v1과 FROZEN 기록은 변경하지 않는다.
- 실행 순서: 위 문서와 데이터 수정 → 고유 ID/26·26/질문 보존/NET·PDF 해시/개정 이력 검사 → 독립 검토 및 diff 공백 검사.

## AC

- Given 기존 50건, When 추가 후 비교, Then 기존 ID·질문·input·source·target이 모두 보존되고 새 ID가 정확히 2개다.
- Given 52건 초안, When 집계, Then relevant 26·irrelevant 26이고 비관련 네 유형이 모두 존재한다.
- Given n01·n02·h03, When 개정 이력 확인, Then 기존 사람 판정과 종전 정답을 복구할 수 있고 변경된 답안의 1차 재검수는 대기 상태다.
- Given 새 두 문항, When 확인, Then 검토표와 JSONL 질문이 같고 PDF 위치·해시가 일치하며 김재훈 O가 보존되고 하정운 검수만 대기 상태다.
- Given 새 분류 기준, When e04·e08·n01·n02·h03·n14를 대조, Then 사용자 조건 부족과 문서 속성 부재가 설명된 기준과 일치한다.
- Given 작업 전 v1·동결 파일, When 작업 후 비교, Then 변경이 없고 평가 실행·동결 성공을 주장하지 않는다.
