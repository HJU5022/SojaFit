# 교체 대상 부품 주변 연결 개념도

## Why

- **페르소나**: KiCad netlist를 올리고 대체 다이오드 후보를 검토하는 회로 설계자
- **상황**: 사용자는 대상 부품의 판정 결과를 읽기 전에 어떤 부품·net이 그 판정의 회로 맥락인지 확인해야 한다.
- **문제**:
  1. 현재 가운데 장식 이미지는 실제 업로드·분석 데이터와 관계가 없어 판정 맥락을 설명하지 못한다.
  2. 연결, 역할, 사용 조건, 후보 근거가 떨어져 있어 사용자가 결과가 어느 부품을 대상으로 한 것인지 다시 대조해야 한다.
  3. 연결 방향이나 전압·전류를 근거 없이 시각화하면 실제 회로도처럼 오해될 수 있다.
- **측정 지표**: fixture 기반 AC 전체 통과, production에서 fixture 대체 표시 0건, 방향 근거 없는 연결의 화살표 0개, 누락 조건의 추정값 표시 0건

## Goal

- **해결 목표**: 기존 프로젝트 API의 KiCad 연결 데이터와 기존 분석 API의 안전한 결과를 결합해 대상 부품 중심의 1·2단계 연결 개념도를 표시한다.
- **성공 기준**:
  - `breadboard_supply`의 `D1`에서 중앙 `D1 / 1N4001`과 주변 `J1`, `S1`, `F1`, `U1`을 확인할 수 있다.
  - 대상·연결·역할·조건·후보 상태가 실제 API 응답에서 화면까지 전달되며 fixture는 테스트에서만 사용한다.
  - 연결 방향 데이터가 없으면 SVG 화살표를 만들지 않는다.
  - 누락된 전압·전류는 추정하지 않고 숨기거나 `정보 필요`로 표시한다.
  - loading, 연결 정보 없음, 대상 부품을 찾을 수 없음, 역할 분석 전, 사용 조건 부족, 판정 완료, 분석 오류 상태를 구분한다.
- **Out of Scope**: 실제 PCB·회로도 렌더링, KiCad 화면 변환, 이미지 생성·검색·저장소, 새 그래프 라이브러리, 업로드 파일 영속 저장 확장, 견적 저장 확장, `connections.json` 변환 경로의 신규 구현

## What

**Happy Path**

1. 인증된 사용자가 기존 프로젝트 상세 API에서 회로 이름과 `connections`를 받는다.
2. 사용자가 대상 부품을 고르면 순수 adapter가 해당 부품의 직접 net과 2단계 연결을 화면 전용 형태로 변환한다.
3. SVG는 대상 부품을 중앙에 강조하고 직접 연결 부품을 안쪽, 2단계 연결 부품을 바깥쪽에 약하게 배치한다.
4. 사용자가 노드를 선택하면 부품 기호, 값, 패키지를 확인한다.
5. 기존 분석 결과가 있으면 역할 코드·역할명·역할 근거, 검증된 조건, 빠진 조건과 후보 판정을 연결한다.
6. 사용자가 후보를 선택하면 기존 판정·데이터시트 근거 영역에서 같은 후보가 선택된다.
7. 개념도 아래에 `실제 회로도가 아닌 대상 부품 주변 연결 개념도입니다.`를 표시한다.

**Edge Cases**

| # | 상황 | 처리 방식 |
|---|---|---|
| EC-01 | 프로젝트 상세를 불러오는 중 | loading 상태를 표시하고 이전 프로젝트의 개념도를 대신 보여주지 않는다. |
| EC-02 | `nets`가 비어 있음 | `연결 정보 없음`을 표시한다. |
| EC-03 | URL 또는 선택값의 대상 ref가 프로젝트에 없음 | `대상 부품을 찾을 수 없음`을 표시한다. |
| EC-04 | 분석 전이거나 역할 결과가 없음 | 연결 개념도는 표시하고 역할은 `역할 분석 전`로 표시한다. |
| EC-05 | 필수 사용 조건이 빠짐 | 값을 만들지 않고 `사용 조건 부족`과 `정보 필요`를 표시한다. |
| EC-06 | 프로젝트 또는 분석 API 실패 | fixture로 대체하지 않고 `분석 오류`와 재시도 가능한 오류 내용을 표시한다. |
| EC-07 | net에 방향 메타데이터가 없음 | 선만 표시하고 SVG marker·화살표를 만들지 않는다. |
| EC-08 | 후보·인용이 많음 | 개념도 안에 전부 넣지 않고 기존 판정·근거 패널에서 선택 후보를 강조한다. |
| EC-09 | 부품 값·패키지가 없음 | 없는 값을 추정하지 않고 해당 항목을 숨기거나 `정보 필요`로 표시한다. |

## How

### 데이터 계약

- 회로·연결 정본은 기존 인증된 프로젝트 상세 응답의 `name`과 `connections.parts|components`, `connections.nets`를 사용한다.
- 역할 근거·조건·누락 조건·후보·데이터시트 근거는 기존 대화 실행의 안전한 브라우저 응답을 사용한다.
- 역할명은 `backend/judge/rules/roles.yaml`을 정본으로 읽는 최소 인증 응답에서 `{code, name}`만 제공한다. 프론트에 같은 이름을 하드코딩하거나 저장하지 않는다.
- 내부 LangGraph 상태나 원시 provider 응답을 브라우저에 노출하지 않는다.
- 테스트 fixture는 `frontend/src/test/` 아래에서만 import한다. production 요청 실패 시 fixture로 폴백하지 않는다.
- 화면 전용 모델은 순수 adapter에서 다음 형태로 만든다. 같은 정보를 프로젝트·분석 응답에 다른 이름으로 다시 저장하지 않는다.

```json
{
  "circuitName": "breadboard_supply",
  "target": {"ref": "D1", "value": "1N4001", "footprint": "..."},
  "nets": [{"name": "RAW", "nodes": ["D1.K(1N4001)", "F1.1(500mA)"], "more": 0}],
  "role": {"code": "R01", "name": "역극성 보호(직렬)", "evidence": ["D1.K → RAW"]},
  "conditions": [],
  "missing": [],
  "candidates": []
}
```

### 표시 계약

- React + Vite의 기존 컴포넌트·스타일을 유지하고 새 그래프 라이브러리 없이 SVG와 CSS로 구현한다.
- 중앙 대상 노드의 시각적 우선순위가 가장 높다. 직접 연결은 안쪽, 2단계 연결은 바깥쪽·낮은 대비로 표시한다.
- 연결 정보만 있을 때는 무방향 선을 사용한다. 별도 데이터로 전력·신호 방향이 명확할 때만 화살표를 허용한다.
- 조건은 사용자가 제공했거나 판정 읽기에서 검증되어 안전한 응답에 포함된 값만 표시한다.
- 후보 판정과 데이터시트 근거는 기존 결과 패널을 정본으로 유지한다.

### 변경 경계

- 프론트: 연결 adapter, SVG 개념도, 상태 표시, 노드·후보 선택 연동과 테스트
- 백엔드: 역할 코드·이름을 제공하는 최소 인증 읽기 계약과 가장 좁은 API 스키마 테스트
- 문서: 이 작업서, 파일 트리 항목, 폴더 파일 목록, `docs/worklog/osc.md`
- 수정하지 않음: 루트 `SPEC.md`, `docs/adr/`, 업로드·견적 영속화, 숫자 판정 규칙

## AC (Given-When-Then)

**AC-01 · `breadboard_supply` 대상 연결**
- GIVEN: `breadboard_supply` 프로젝트와 대상 `D1`
- WHEN: 주변 연결 정보를 표시한다.
- THEN: 중앙에 `D1 / 1N4001`이 보이고 주변에 `J1`, `S1`, `F1`, `U1` 연결 정보가 표시된다.

**AC-02 · 방향을 모르는 연결**
- GIVEN: 연결 방향을 확정할 데이터가 없는 net
- WHEN: 개념도를 렌더링한다.
- THEN: 방향 화살표를 표시하지 않는다.

**AC-03 · 입력되지 않은 전압·전류**
- GIVEN: 전압이나 전류가 입력되지 않은 회로
- WHEN: 개념도를 렌더링한다.
- THEN: 값을 추정하지 않고 `정보 필요`로 표시한다.

**AC-04 · 역할 분석 결과**
- GIVEN: 역할 분석이 완료된 결과
- WHEN: 화면을 렌더링한다.
- THEN: 역할명과 역할 근거를 대상 부품 옆에 표시한다.

**AC-05 · 후보 선택 연동**
- GIVEN: 후보 판정 결과
- WHEN: 사용자가 후보를 선택한다.
- THEN: 기존 판정·데이터시트 근거 영역에서 해당 후보가 선택된다.

**AC-06 · production의 API 미연결**
- GIVEN: 실제 API가 연결되지 않은 production 실행
- WHEN: 화면을 연다.
- THEN: fixture를 실제 결과처럼 대신 보여주지 않고 빈 상태 또는 연결 오류를 표시한다.

**AC-07 · 상태 구분**
- GIVEN: loading, 빈 nets, 잘못된 대상, 분석 전, 조건 부족, 완료, API 오류 중 하나
- WHEN: 작업대를 렌더링한다.
- THEN: 해당 상태의 이름과 안내가 다른 상태와 구분되어 표시된다.

**AC-08 · 노드 상세**
- GIVEN: 값 또는 패키지를 가진 주변 부품 노드
- WHEN: 사용자가 그 노드를 선택한다.
- THEN: 부품 기호와 존재하는 값·패키지를 확인할 수 있고 없는 값은 만들어내지 않는다.
