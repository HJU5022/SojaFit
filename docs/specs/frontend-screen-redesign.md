# 프론트엔드 화면 재설계

## Why
- 회로 검토자는 대화와 분석 결과를 한 작업대에서 확인해야 한다. 중복 메뉴와 과도한 패널 면적은 대화 가독성을 낮춘다.

## Goal
- 공개 랜딩·로그인·작업대 3개 화면에 공통 로고와 Deep Gray `#1E2229`·Silver Slate `#8A94A6`·Orange `#FF5722`를 적용한다.
- 인증·기존 분석 API·DB 구조는 유지한다. 모바일 최적화·운영 배포·일반 Google 가입은 범위 밖이다.

## What
- 랜딩에서 시작·로그인으로 이동한다. 로그인은 기존 이메일 인증과 서버에서 활성화한 Google 진입을 사용한다. 데모 버튼은 개발 빌드에만 표시한다.
- 작업대는 왼쪽 프로젝트/이전 대화, 중앙 대화, 오른쪽 상세다. 오른쪽은 최초 진입 시 접힌다.
- 상단 프로젝트 모달에서 프로젝트 관리·대상 부품 선택을 한다. 대화 행은 한 줄이며 현재 대화와 실행 중 세션을 구분한다. 고정은 사용자·프로젝트별 현재 브라우저에만 유지한다.
- 초기 결과 메뉴는 숨기고, 답변 뒤 해당 run에 실제 결과가 있는 메뉴만 한 줄로 표시한다.
- 질문은 한 칸이다. Enter는 전송, Shift+Enter는 줄바꿈이다. IME 조합·키 반복·빈 질문·대상 미선택·중복 실행은 전송하지 않는다.
- 내 설정과 작업대는 공통 이메일 계정 메뉴와 헤더를 사용한다.

## How
- `WorkbenchPage`는 프로젝트·thread·선택 run을, `ConversationPanel`/`SavedConversationPanel`은 새 분석/읽기 전용 기록을 맡는다. URL에는 식별자만 둔다.
- 이전 선택의 늦은 응답을 AbortSignal과 소속 확인으로 격리한다. 로그아웃·401에서 기존 캐시 정리를 유지한다.
- API는 [프로젝트·대화 탐색](project-conversation-navigation.md)과 [오류 계약](api-error-contract.md)을 따른다. 분석/재개 요청은 자동 재전송하지 않는다.
- 로고·아이콘은 `frontend/public/assets/`다. Docker 프론트 빌드도 public 자산을 복사한다. 구버전 랜딩 컴포넌트와 전용 배경 이미지는 제거한다.
- 입력 label·키보드 초점·dialog 초점 복귀·진행 상태 접근성·동작 효과 줄이기를 유지한다. 중단 버튼은 수신 중단이며 서버 분석 취소를 보장하지 않는다.
- 정본 SPEC의 화면 설명 갱신은 조장 검토 대상이다.

## AC
- Given 비로그인 When 랜딩에서 시작 Then 로그인으로 이동하고 로그인 성공 시 작업대가 열린다.
- Given 운영 빌드 When 로그인 Then 데모 버튼과 데모 상태 조회가 없다.
- Given 새 작업대 When 초기 진입 Then 오른쪽 상세와 결과 메뉴는 숨겨지고 대화 입력이 보인다.
- Given 선택된 대상과 질문 When Enter/Shift+Enter Then 각각 단일 전송/줄바꿈이며 IME 조합은 전송하지 않는다.
- Given 완료 답변 When 결과 메뉴 선택 Then 해당 run의 상세만 열린다.
- Given 사용자 이메일 When 작업대·내 설정 Then 같은 이메일과 공통 계정 메뉴를 표시한다.
- Given 실패 When 오류 표시 Then 안내는 한 번이며 run이 있으면 실행 상태 확인 버튼을 유지한다.

## main 회로 시각화 통합
- 범위: 대화 중심 작업대와 초기 접힌 상세, 단일 질문 입력, 프로젝트/부품 모달, 저장 대화 대상 고정을 유지한다.
- 구현: main의 15종 실제 catalog·원본 회로도/연결 개념도·ELK 배치·공식 데이터시트/외형 페이지·오버레이 스크롤바를 같은 상세 화면에 연결한다. 표시 조건과 정규 출처는 응답에서만 제공하며 저장 DTO 형식은 유지한다.
- AC: Given 원본이 있는 데모 When 상세 열기 Then 원본/개념도 탭과 검증 출처가 보인다. Given 저장 대화 When 회로 탭 전환 Then 대상은 고정된다. Given 업로드 When 상세 열기 Then 원본 이미지를 추측하지 않는다.
- 검증: 양쪽 DTO·화면·catalog 검사와 새 저장 대상/시각화 결합 회귀를 실행한 후 전체 프론트·격리 API·구조·가짜 API 브라우저를 확인한다. 실제 모델/운영 배포는 범위 밖이다. 기능 정본 반영은 조장 검토 대상이다.
