### 랜딩페이지 초안

- 상단: 서비스 이름, 서비스 소개·사용 방법 탐색과 로그인 링크. 별도 서비스 시작 버튼은 중복 배치하지 않는다.
- 첫 영역: "회로를 읽고, 대체 후보를 근거로 검토하세요."를 제목으로 사용한다. SojaFit을 회로 연결·사용 조건에서 부품 역할과 후보별 판정·데이터시트 인용 근거를 제공하는 분석 에이전트로 소개한다. 입력은 공개 데모 회로 또는 KiCad 넷리스트, 현재 검토 범위는 소형 MCU 회로의 다이오드이며 같은 동작을 보장하지 않음을 명시한다. 소개 문구는 실제 지원 범위를 넘어서지 않는다.
- 데스크톱 공간 배치: 1000px 이상은 최대 1440px 컨테이너 안에서 소개·단일 시작 버튼을 왼쪽, 합성 회로/후보/근거 미리보기를 오른쪽에 나란히 배치한다. 기능 카드 3개는 그 아래 가로 한 줄로 작게 정리해 첫 화면에서 소개와 예시를 함께 볼 수 있게 한다. 기존 팔레트·기능 카드 선택·인증별 시작 경로를 유지하고 1000px 미만 전용 재설계는 이번 범위에 넣지 않는다.
- 사용 흐름: 회로 등록 → 대상·조건 입력 → 후보·근거 검토.
- 기능 소개: 회로 맥락, 후보 판정, 문서 위치 인용의 3개 카드를 소개한다. 사용자 피드백에 따라 랜딩의 사람 승인·견적 저장 카드와 관련 하단 홍보 문구는 제외한다. 예시 화면·데이터는 실제 분석 결과와 구분한다. 작업대의 기존 기능 계약은 이 변경에서 수정하지 않는다.
- 한계 안내: 같은 동작을 보장하지 않으며, 판정 규칙이 없는 부품까지 판정 가능하다고 소개하지 않는다.
- 서비스 시작은 본문의 "회로 검토 시작" 버튼 하나로 통합한다. 미로그인은 `/login`, 로그인한 사용자는 `/app`으로 이동한다. 미리보기와 페이지 하단에는 같은 경로로 이동하는 추가 시작 링크를 두지 않는다.
- 하단: 검토 안내 문구만 한 열로 표시한다. 1000px 이상에서는 기능 카드 행과 같은 최대 1360px 내용 폭·좌우40px 여백에 맞춘다. 별도 분석 입력 기능은 이 초안에 추가하지 않는다.

## How

### 2026-11-11 내 설정 화면 통일 승인

- 프로젝트 선택 hover: 사용자가 제시된 세 안 중 ‘텍스트 강조’를 선택했다. 배경과 구분선은 기본 상태로 유지하고 프로젝트 제목/화살표만 Orange 계열로 강조한다. 대상 부품 보조 문구는 Silver Slate로 유지한다. 공통 button:hover:not(:disabled)보다 우선하는 전용 선택자로 오렌지 전체 채움이 발생하지 않게 한다. 기존 키보드 초점 윤곽선과 클릭 기능은 유지한다.
- 후속 헤더 통일/축소: 작업대와 내 설정은 56px 높이·16px 좌우 여백·128×36 로고·12px 요소 간격·같은 배경/하단 선/글자 크기를 사용한다. 프로젝트 제목은 13px/600, 보조 대상 표시는 11px, 프로젝트 영역은 데스크톱 최대 200px로 줄여 검색 공간을 확보한다. 이메일 버튼과 계정 팝오버·개인 화면 설정·설정 이동·관리자 메뉴·로그아웃은 공통 AccountMenu를 재사용한다. 설정 헤더의 별도 이메일 텍스트/로그아웃 버튼을 없애고, 로고 옆에는 작업대 복귀·현재 위치를 표시한다. 프로젝트 선택·검색은 작업대에만 유지한다.
- `/settings`는 기존 보호 경로와 `SettingsPage.tsx`를 유지한다. 랜딩·로그인·작업대의 Circuit S 로고, Deep Gray 배경, Silver Slate 보조 글자, Orange 저장 버튼을 계승한다. 공통 셸은 이 경로에 한해서 그림자 없는 헤더와 로그인 이메일을 표시한다.
- 사용자가 지정한 ‘여기 적은 사실은 다음 대화에서도…’ 안내 문단을 제거한다. 데스크톱에서 왼쪽은 개인 설정·계정 관리의 페이지 내 탐색, 오른쪽은 소속·직무·실장 방식의 설정 폼과 저장된 항목, 별도 계정 삭제 영역으로 구성한다. 새 설정 항목이나 API는 추가하지 않는다.
- 기존 GET/PATCH/DELETE `/api/me/memory`, 변경된 칸만 저장, 칸별 삭제, 모두 삭제 확인, 일반 계정 탈퇴 확인 및 실패·진행·권한 처리는 유지한다. 로그인·랜딩·작업대·DB 구조는 바꾸지 않는다. 모바일 전용 설계는 후속이다.
- AC: Given 로그인한 사용자 When `/settings`에 진입 Then 지정 문단 없이 기존 브랜드 헤더·이메일과 레이블이 연결된 3개 입력을 표시한다. When 저장·칸별 삭제·전체 삭제·탈퇴를 수행 Then 기존 요청 본문·확인 단계·공개 오류·세션 정리 계약이 유지된다. 계정 삭제의 불가역 범위 고지는 유지한다.

### 2026-11-11 구현 승인·교체 적용 기록

사용자가 구버전 화면을 제거하고 최신 목업의 랜딩·로그인을 실제 화면과 API에 연결하도록 요청했다. 이 승인을 반영해 문서 작성 단계에서 화면 구현 단계로 전환했다. 기준은 저장소 밖 `sojafit-project-session-sidebar.html`의 랜딩·로그인이었다. Deep Gray #1E2229, Silver Slate #8A94A6, Orange #FF5722, 큰 중앙 제목·4개 기능 선택·합성 검토 예시, 소개/입력 2열 로그인 구성을 적용했다.

- `/`는 공개 LandingPage, `/login`은 같은 톤의 실제 로그인 폼, `/app`은 프로젝트 미선택 때도 왼쪽 프로젝트 탐색·중앙 대화 준비 화면을 표시한다. 기존 랜딩을 작업대 안에 다시 표시하지 않는다.

- 기존 InitialLanding·30개 이동 질문·LandingServiceIntroduction과 전용 회로 배경 이미지는 참조 제거 뒤 삭제한다. 기존 보조 화면·판정·인용·승인 컴포넌트는 보존한다.
- 검증 순서: 공개 랜딩·로그인→메인·프로젝트 미선택 테스트 실패 확인 → 목업 JSX/CSS 이식과 옛 파일/스타일 삭제 → 단위·빌드 → 새 화면의 실제 세션/API·임시 DB에서 화면을 보며 로그인·프로젝트·기록/분석/승인 확인.
- AC: 비로그인 /에서 서비스 소개를 볼 수 있고 보호 데이터 요청은 0; 시작→로그인 성공→신규 메인; /app 직접 접근은 기존 인증 차단; 프로젝트 없는 메인은 진입 모달 없이 프로젝트 선택/생성 가능; 로그인 실패·비밀번호 폐기·데모/Google 표시·로그아웃 정리 유지; 390/1440px 가로 넘침 없음.

## AC (Given-When-Then)

### 2026-11-11 메인 작업대 비율 보완

- 후속 사용자 지정 범위는 메인 작업대다. 랜딩·로그인 디자인과 인증·API·DB 계약은 유지한다.
- 1440px 기본 폭은 왼쪽 208px, 오른쪽 360px이며 중앙 대화가 55% 이상을 차지한다. 기존 너비 조절은 유지하되 오른쪽 패널은 중앙에 최소 560px을 남기도록 제한한다.
- 1200px 미만에서는 오른쪽 상세를 요청할 때만 겹쳐 연다. 768px 미만에서는 왼쪽 프로젝트·이전 대화도 메뉴 버튼으로 연다. 로그인 직후 자동 선택 모달은 만들지 않는다.
- 대화 내용은 남은 높이를 채워 내부에서 스크롤하고 입력창은 하단에 작게 유지한다. 결과 메뉴 4개는 가로 1행을 유지한다. 프로젝트·이전 대화 전환과 완료 응답은 좁은 화면에서 상세를 자동으로 열지 않는다.
- **AC-11**: GIVEN 1440×844, 1024×844, 768×844, 390×844 화면, WHEN 완료된 대화를 표시, THEN 가로 넘침이 없고 입력 영역이 화면 안에 있으며 대화 내용 영역이 입력 영역보다 높다.
- **AC-12**: GIVEN 좁은 화면의 결과 메뉴, WHEN 문서 근거를 열고 Escape로 닫음, THEN 중앙 너비가 유지되고 초점이 누른 메뉴로 돌아온다. 상세 안의 승인 확인창에서는 확인창만 닫힌다.
- **AC-13**: GIVEN 390×650 화면, WHEN 대화 표시 및 프로젝트·이전 대화 선택, THEN 입력 영역이 화면 안에 있고 대화 내용에 150px 이상을 남기며 선택 후 왼쪽 메뉴가 닫힌다.

아래는 현재 화면의 수용 기준이다. 개별 검사의 실행 결과·환경·제한은 `docs/worklog/sth.md`를 따르며, 문서만으로 전체 AC나 실제 배포 통과를 선언하지 않는다. 기존 기능의 상세 AC는 관련 정본을 참조한다.

- **AC-01 · 공개 랜딩**: GIVEN 비로그인 사용자, WHEN `/`에 접근, THEN 서비스 목적·사용 흐름·한계와 로그인/시작 진입점을 볼 수 있다.
- **AC-02 · 인증에 따른 시작**: GIVEN 랜딩 사용자, WHEN 서비스 시작 선택, THEN 세션 확인 후 비로그인은 로그인, 로그인 상태는 메인으로 이동한다.
- **AC-03 · 로그인 유지**: GIVEN 로그인 화면, WHEN 기존 인증 성공/실패/처리 중 상태가 발생, THEN 각각 메인 이동/공개 오류/중복 제출 방지가 유지된다.
- **AC-04 · 회로 준비**: GIVEN 메인에 프로젝트 또는 대상이 없음, WHEN 화면 표시, THEN 기존 프로젝트 열기·데모·업로드 및 대상 선택의 필요한 진입점을 제공한다.
- **AC-05 · 회로 중심 결과**: GIVEN 완료된 분석, WHEN 후보 선택, THEN 대상·사용 조건을 확인하면서 같은 후보의 판정·기판 수정·근거·미확인 항목을 검토할 수 있다.
- **AC-06 · 실행 상태**: GIVEN 분석 중·추가 입력·거절·오류·연결 종료, WHEN 해당 응답 수신, THEN 상태를 구분하고 기존 재개·조회 복구 계약을 유지하며 질문을 자동 재전송하지 않는다.
- **AC-07 · 승인과 가격 경계**: GIVEN 판정 결과, WHEN 승인·견적 행동, THEN 기존 승인 가능 판정과 확인 절차를 유지하고 가격·재고를 견적에 저장하지 않는다.
- **AC-08 · 기존 보조 기능**: GIVEN 적절한 권한의 사용자, WHEN 회원가입·내 설정·관리자·승인 사례 기능에 접근, THEN 주요 화면을 3개로 정리했다는 이유로 기존 기능이 사라지지 않는다.
- **AC-09 · 반응형·접근성**: GIVEN 데스크톱 1440×900 또는 모바일 390×844와 키보드 사용자, WHEN 주요 흐름 조작, THEN 핵심 행동과 근거를 가림 없이 이용하고 판정 의미를 색만으로 전달하지 않는다.
- **AC-10 · 상태 구분**: GIVEN 이 문서를 작업자에게 전달, WHEN 적용 범위를 확인, THEN 승인된 현재 구현·초기 검토 기록·미구현 후속 계획을 구분하고 로컬 검증을 배포 검증으로 표시하지 않는다.

### 발견 후 보완

- 새 대화 thread 생성503이 중앙에 표시되지 않던 문제를 가짜 HTTP로 먼저 실패 재현했다. 오류/요청 ID를 한 번 표시하고 초점·질문 초안을 유지하며, 사용자 재전송 때만 재시도하도록 보완했다. run ID가 없는 실패에는 상태 확인 버튼을 만들지 않는다.
- Postgres 재개 통합 검사가 운영의 기본3회 판정 읽기와 다르게 초기1회를 가정했다. 재개 시 재호출 방지라는 검사 목적에 맞게 그 테스트에만 JUDGE_READ_VOTES=1을 명시했다. 운영 읽기·판정·모델 설정은 바꾸지 않았다.
- 기존 제한: 저장 대화는 읽기 전용이며 추가 질문은 새 대화에서 시작한다. 상단 단계의 current/complete는 같은 색이므로 시각 구분 개선은 후속이다.

### 운영 반영 순서와 상태

1. **릴리스 후보 확정**: 현재 작업 폴더에는 화면 외 API·판정·평가 자료 변경도 공존한다. 조장이 목적별 변경·필수 의존 파일을 검토하고 Google 일반 사용자/복구 API의 정본 SPEC 반영 요청을 확인한다. 다른 작업을 임의로 제외하거나 통째로 배포하지 않는다.
2. **실제 Google 왕복 확인(팀장 확인으로 이관)**: 2026-11-11 사용자 결정에 따라 로컬 실제 인증 시도는 중단하고 운영 반영 과정에서 팀장이 확인한다. 현재 미리보기의 Google은 비활성이며, 등록된 로컬 콜백은 `http://localhost:8000/api/auth/google/callback`이다. 팀장 확인 범위는 계정 선택/동의→callback→기존 서버 세션→로그아웃과 일반 가입/기존 계정 연결·관리자 승인 경계다. 이번 Google 화면 검사는 mock이며 실제 인증 성공으로 간주하지 않는다. 이 이관은 에이전트의 운영 배포·IAM 변경 권한을 뜻하지 않는다.
3. **Google 가입 SQL 적용 상태 확인**: 운영 DB에는 `026_google_user_login.sql`의 적용 여부를 아직 확인하지 않았다. 백업/복구 확인과 조장 검토 후 SQL 선적용→NULL 비밀번호 호환 코드 반영 순서를 따른다. `db/DB.md`와 `google-user-login.md`의 운영 전 조건을 따른다. 로컬 시험 DB만 변경했고 운영 DB는 조회·수정하지 않았다.
4. **컨테이너 검증(로컬 완료)**: desktop-linux의 로컬 `sojafit:local-release-20261111` 이미지를 빌드했다. localhost4188에서 `/health`, `/`, `/login`, `/app`, `/settings`, JS·로고·아이콘 응답, 비인증401, DEMO_MODE=0의 demo GET/POST404, Google 미설정 비활성, 빌드 파일 포함·`.env` 미포함까지13항목을 통과했다. DB·키 없이 THREADS_ENABLED=0으로 확인했으며 컨테이너는 제거했다. 이 이미지는 현재 전체 작업 폴더의 검증용이며 1번의 릴리스 후보 확정 후 운영 후보를 다시 빌드한다. 운영 DB를 연결한 컨테이너 검증이나 실제 Google 왕복 성공을 뜻하지 않는다.
5. **승인 후 운영 반영**: 운영값은 DEMO_MODE=0, Google 활성·기존 Secret Manager 연결, 실제 서비스 AUTH_ORIGIN을 유지/확인한다. 운영 DB 백업과 이전 이미지·리비전의 복구 경로를 확보한 뒤에만 조장이 배포를 진행한다. Google-only 계정 생성 후 NULL 비밀번호를 처리하지 못하는 코드로 단순 롤백하지 않는다.

운영 설정·OAuth 클라이언트·운영 DB·트래픽·배포·원격 저장소는 이번 검증에서 변경하지 않았다. 실제 LLM/Voyage/Mouser 호출과 평가 점수 재측정은 수행하지 않았다.

## main 회로 시각화 통합
- 범위: 대화 중심 작업대와 초기 접힌 상세, 단일 질문 입력, 프로젝트/부품 모달, 저장 대화 대상 고정을 유지한다.
- 구현: main의 15종 실제 catalog·원본 회로도/연결 개념도·ELK 배치·공식 데이터시트/외형 페이지·오버레이 스크롤바를 같은 상세 화면에 연결한다. 표시 조건과 정규 출처는 응답에서만 제공하며 저장 DTO 형식은 유지한다.
- AC: Given 원본이 있는 데모 When 상세 열기 Then 원본/개념도 탭과 검증 출처가 보인다. Given 저장 대화 When 회로 탭 전환 Then 대상은 고정된다. Given 업로드 When 상세 열기 Then 원본 이미지를 추측하지 않는다.
- 검증: 양쪽 DTO·화면·catalog 검사와 새 저장 대상/시각화 결합 회귀를 실행한 후 전체 프론트·격리 API·구조·가짜 API 브라우저를 확인한다. 실제 모델/운영 배포는 범위 밖이다. 기능 정본 반영은 조장 검토 대상이다.
