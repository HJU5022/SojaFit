# 검증된 회로도와 데이터시트 근거

## Why

대체 부품 결과만 보여 주면 사용자는 실제 회로 맥락과 판정 근거를 직접 확인하기 어렵다. 데모 회로의 공개 원본과 후보 부품의 공식 데이터시트 위치를 함께 제공하되, 개념도를 실제 설계 원본으로 오해시키거나 물리적 직접 교체를 보증해서는 안 된다.

## Goal

수집·검증된 공개 회로 15종 모두에서 공개 원본 회로도와 기존 연결 개념도를 구분해 표시하고, 선택 후보의 공식 데이터시트·인용 페이지·패키지 외형 페이지를 안전한 정규 메타데이터로 제공한다. 새 데모는 Python·TypeScript·Docker 목록을 고치지 않고 단일 카탈로그 등록으로 추가한다.

## What

- `data/circuits/collected/`의 공개 회로 15종 모두에 고정 커밋에서 확인한 원본 회로도를 제공한다.
- 업로드 프로젝트에는 원본을 생성하거나 추정하지 않는다.
- 원본 회로도와 연결 개념도를 별도 탭으로 표시한다.
- 후보 근거에는 공식 HTTPS 데이터시트와 패키지 외형 페이지를 표시한다.
- 패키지 결과는 `동일 패키지 가능성`, `기판 변경 가능성 있음`, `패키지 변경 여부 확인 필요`로 표현하며 직접 교체를 보증하지 않는다.

## How

- `catalog.json`은 데모 ID·이름·정규화 연결 파일 경로의 단일 정본이다. 백엔드, 더미 UI와 Docker 빌드는 이 파일을 읽고 별도 데모 목록을 갖지 않는다.
- 정적 PNG는 exact asset URL, SHA-256, attribution, license와 고정된 license evidence URL로 검증한다. 저장소 commit은 저장소 맥락이며 CDN 바이트의 출처 증명으로 사용하지 않는다.
- 카탈로그 API는 기존 무파라미터 목록 응답을 유지하며 이름·ID 검색과 범위 제한을 지원한다.
- 데이터시트 URL은 `data/manifest.jsonl`의 URL-decoded PDF basename exact match로만 가져온다.
- 패키지 외형 페이지는 오프라인 Docling JSON에서 허용된 표제와 같은 페이지의 picture가 함께 있는 최초 페이지로 결정한다.
- 모델이나 클라이언트가 보낸 URL·외형 페이지는 버리고 서버 정규 메타데이터로 덮어쓴다.
- 외부 PDF는 inline으로 삽입하거나 프록시하지 않고 새 탭의 공식 링크로만 연다.

## AC

- 데모 15종에서 원본 회로도, 출처, attribution과 license를 확인할 수 있다.
- 카탈로그 항목을 추가할 때 애플리케이션 코드나 Docker의 파일 목록을 수정하지 않는다.
- 카탈로그 API의 검색·범위 제한이 정상 입력과 잘못된 입력을 구분한다.
- 업로드 프로젝트에는 원본 회로도 탭이 나타나지 않는다.
- 선택 후보의 공식 데이터시트와 패키지 외형 페이지 링크가 manifest·오프라인 index에서만 생성된다.
- 알 수 없는 문서와 악성 URL 입력은 브라우저 링크가 되지 않는다.
- UI에 물리적 무수정 교체, 핀 호환, 재배선·납땜 방법을 보장하는 문구가 없다.
- backend·frontend focused tests, production build, repo layout과 대상 Playwright 흐름이 통과한다.
