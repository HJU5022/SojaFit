# 0016 사양 표를 버리고 카드 읽기를 기본으로 한다

- 날짜: 2026-11-09
- 상태: 채택
- 근거: 조장 결정(11-09), v3 공식 측정 4(lab 카드 모드, 조장 전달 11-09)
- 바꾸는 것: [ADR 0013](0013-부품-사양-표는-13종을-규칙으로-만들고-애매한-값은-뺀다.md)(부품 사양 표를 규칙으로 만들어 DB에 둔다)을 대체한다.

## 결정
- 부품 사양 표(`part_specifications`)를 버린다. 후보 찾기와 판정 값은 카드(표 행 청크)를 그때그때 읽는 카드 도구가 기본이다.
  - 찾기: `backend/rag/card_find.py`의 `default_find()`
  - 판정 값: `backend/rag/card_specs.py`의 `default_specs()`
  - 사실 확인의 문서 행: `default_specs().doc_rows`(LLM 없음). 품번 · 개정 코드 확인(`check_corpus`)은 MCP 서버로 부르던 대로 둔다.
- 서비스에서는 `backend/conversations/memory_service.py`의 분석 그래프 한 곳이 이 도구를 쓴다(React 작업대의 실행도 이 서비스를 거친다). 평가 실행기 `evals/runners/run_graph.py`도 같은 조립이다. 서비스와 평가 실행기에 전환 스위치를 두지 않는다.
- 표를 만들고 넣던 것을 지운다: `db/011_part_specifications.sql`, `backend/rag/pipeline/specs.py`의 표 만들기 · 대조표 · 적재(`build` · `sample` · `load`)와 그 시험. 카드 도구 · `ingest.py`가 import하는 규칙(`SI` · `SYMS` · `KEYWORDS` · `PKG` · `packages_of` · `family` · `BOTH_DIRECTIONS` · `AEC_H` · `AEC_ALL`)은 남긴다.
- 운영 DB의 표는 11-09에 지웠다([db/DB.md](../../db/DB.md)).

## 이유
- 11-09 코퍼스를 바꾼 뒤 운영 DB의 `part_specifications`는 0행이었다. 같은 날 한 문서(document_id=8, B2104)의 70행만 다시 넣었다(`docs/worklog/sth.md`).
- v3 공식 측정 4(lab, 카드 모드) 결과(조장 전달 11-09, 원시 결과 파일은 이 저장소에 없음):

| 지표 | 값 |
|---|---|
| 관련 정확도 | 0.96 |
| 비관련 거절 | 1.0 |
| 페이지 MRR | 0.976 |
| 응답 시간 p50 | 5.5초 |
| 응답 시간 p95 | 19.0초 |
| 비용 | 1.10달러 |

- 기준([ADR 0015](0015-평가셋-v3를-새로-만들고-청킹부터-다시-잰다.md)) 중 못 넘은 것은 p95 10초 이내 하나다.

## 결과
- 카드 도구는 MCP 서버를 거치지 않고 `DATABASE_URL`로 DB를 직접 읽는다. 서비스 실행 환경에 코퍼스 DB 주소가 있어야 한다. `default_specs()`는 표지 청크(`chunk_index` 0)로 품번 → 문서 색인을 처음 찾을 때 한 번 만든다. 서비스는 앱이 뜰 때 분석 그래프를 한 번 조립하므로(`memory_service.Conversations`) 이 색인도 프로세스마다 한 번 읽는다.
- LLM 호출이 는다. 사양 표 SQL 조회는 LLM 0번이었다.
  - 찾기 한 번: 문서 고르기(분류가 있으면 개요 줄을 보는 `card_pick` LLM 1번, 없으면 검색 1번) + 고른 문서(최대 10개)마다 `card_read`(문서끼리 동시, 문서 안에서는 카드 4장씩 나눠 동시, 프로세스 전체 동시 호출 상한 24).
  - 판정 값: 후보 품번의 문서마다 `card_read`. 찾기에서 같은 코드까지 이미 읽은 문서는 다시 읽지 않는다(`SHARED_READS`).
- 카드 도구의 DB · LLM 오류는 판정 코드가 `search_error` 거절로 바꾸지 않는다(판정 코드는 MCP 장애만 받는다). 그 오류는 실행 실패로 끝난다.
- 지운 표를 읽던 MCP 사양 도구(`get_part_specs` · `find_parts_by_specs`), `backend/graph/mcp_retriever.py`의 `part_specs` · `find_parts`, `backend/rag/spec_lookup.py`의 SQL 조회(`part_specs` · `find_candidates`), 평가 실행기의 `LAB_FIND` · `LAB_SPECS` 분기는 11-10에 지웠다. `evals/runners/run_graph.py`는 카드 도구가 기본이라 평가 실행도 찾기 · 판정 값에서 카드 읽기 LLM을 부른다.

- 현재 위치: `db/011_part_specifications.sql` → 삭제됨(이 결정).
