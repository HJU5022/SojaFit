# 0004 임베딩 모델과 벡터 차원(1536)은 임시 결정으로 둔다

- 날짜: 2026-11-01
- 상태: 채택(임시)
- 근거: 조장 하정운 결정(11-01), `db/002_rag_corpus.sql`, `evals/guides/preregister.md` #1·#2·#7·#8, PR #17 오세창 검수 의견
- 일부 바뀜: 본평가 후보와 순서는 `SPEC.md` 1절과 `EVAL_REPORT.md` 「다음 본평가」를 따른다(11-02). `text-embedding-3-small`·`vector(1536)` 임시 결정은 그대로다(11-03에 모델과 열 형식이 바뀌었다, 아래 "갱신 2026-11-03")

## 결정
- 검색 임베딩은 `text-embedding-3-small`(1536차원)을 쓰고, `chunk_embeddings.embedding`을 `vector(1536)`으로 만든다. 이것은 본평가 전 임시 결정이다.
- 모델은 v1 동결 뒤 사전 등록 #1(`KURE-v1`)·#2(`Qwen3-Embedding-0.6B`) 본평가로 확정한다. 다른 차원의 모델로 바꾸면 새 Migration으로 벡터 열을 바꾸고 임베딩을 다시 넣는다.

## 이유
- 검색 베이스라인을 재려면 지금 쓸 벡터 표가 필요하고, 1,360건 임베딩이 이미 있어 추가 비용 없이 넣을 수 있었다.
- 11-01 예비 실험(초안 19문항)에서 두 로컬 모델은 정확 검색 하이브리드 MRR이 0.895로 `text-embedding-3-small`(0.921)보다 높지 않았지만, 동결 평가셋으로 다시 재기 전이라 확정하지 않는다.

## 갱신 2026-11-03
- 결정: 서비스 검색을 사전 등록 #25의 1위 설정으로 바꾼다. 임베딩 `voyage-4-large`(1024차원, 질문 `input_type=query`), 합친 후보 전부를 Voyage `rerank-3`로 리랭크, 첫 검색부터 재작성한 검색어 사용(라우팅 → 재작성 → 검색), 표지 카드(`page_number` 없음) 제외. BM25·RRF(k=60)·후보 50장·k=5는 그대로다.
- 저장: `chunk_embeddings.embedding`을 차원 없는 halfvec으로 바꿔(`db/008_multi_dim_embeddings.sql`) 3-small 1536차원 행(되돌릴 때 쓸 것)과 voyage-4-large 1024차원 행을 함께 둔다. 차원 없는 열에는 HNSW를 걸 수 없어 인덱스를 지운다(검색은 이미 정확 검색).
- 근거: `evals/guides/preregister.md` #25, 결과 `evals/results/retrieval/r1_2026-11-03.json`. 시험 분할 38문항 쪽 Recall@5 0.579 → 0.908(14승 1패, 95% CI +0.184..+0.487). 사람이 판정한 v2 19문항은 0.724 → 0.825(4승 1패)로 입증되지 않았다.
- 2026-11-04 추가(사전 등록 #27, 측정 전): dense는 허용 카드가 3,200장보다 많을 때 1비트 Hamming 후보 3,200장(`db/009_chunk_embedding_bits.sql`)을 거른 뒤 정확 코사인으로 세운다. 이 줄은 측정 값이 사전 등록 기대를 채워야 유지한다.
- 남은 것: 운영 DB에 db/008 적용과 voyage 벡터 적재(`ingest.py --voyage`)는 아직 하지 않았다. 적용 전에는 `retrieve()`가 voyage 행을 찾지 못한다.
