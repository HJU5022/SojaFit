# 0019 오류 응답 `error.code`는 화면이 다르게 반응해야 할 때만 나눈 15개로 한다

- 날짜: 2026-11-10
- 상태: 채택
- 근거: 조장 결정(11-10), 커밋 `00a036a`의 오류 정적 목록(`backend/`의 `raise HTTPException(` 88곳, `backend/main.py`의 `ERROR_CODES`, `frontend/src`의 `error.code` 비교)
- 바꾸는 것: `backend/main.py`의 `ERROR_CODES`(HTTP 상태마다 코드 하나, 10개)를 아래 15개로 바꾼다. 이름이 바뀌는 값은 `BAD_REQUEST` → `VALIDATION_ERROR`, `TOO_MANY_REQUESTS` → `RATE_LIMITED` · `LIMIT_EXCEEDED`, `SERVICE_UNAVAILABLE` → `UNAVAILABLE`(바깥 서비스 장애는 502 `UPSTREAM_ERROR`로 뺀다), `GATEWAY_TIMEOUT` → `TIMEOUT`이다. `FORBIDDEN`에서 `ORIGIN_MISMATCH`를, `CONFLICT`에서 `CONDITION_PENDING` · `ALREADY_APPROVED`를 나눈다. 오류 코드 표가 있는 `docs/specs/api-error-contract.md`와 SPEC 4절은 구현할 때 고친다.

## 결정
- 응답 모양은 그대로 둔다: `{"error": {"code", "message", "request_id"}}`와 헤더 `X-Request-ID`(`backend/main.py`의 `error_response`).
- `error.code`는 아래 15개 중 하나다. 바깥 서비스(LLM · 임베딩) 장애는 지금 분석 실패 503(커밋 `00a036a` 기준 `backend/conversations/memory_service.py:527`)에 섞여 있어 502 `UPSTREAM_ERROR`로 뺀다. 그 밖에는 상황마다 HTTP 상태를 지금과 같게 둔다. `message`는 지금처럼 사람이 읽는 한국어 문장이다. 이름은 UPPER_SNAKE다.
- 분석 실행 SSE의 마지막 이벤트 `failed`에 담는 `error.code`도 이 표를 쓴다. 지금도 `backend/api/conversations.py`의 `public_error`가 `ERROR_CODES`에서 코드를 고르므로, 분석 중의 조건 대기 409 · 상한 429 · 시간 초과 504는 이 이벤트로 화면에 간다.

  | code | HTTP | 뜻 |
  |---|---|---|
  | `UNAUTHORIZED` | 401 | 로그인 안 함 · 세션 만료 · 로그인 실패 |
  | `FORBIDDEN` | 403 | 관리자 전용 |
  | `ORIGIN_MISMATCH` | 403 | 요청 출처 불일치 |
  | `NOT_FOUND` | 404 | 없는 자원, 남의 대화 · 프로젝트도 404 |
  | `VALIDATION_ERROR` | 400 · 422 | 요청 · 파일 형식 오류 |
  | `CONDITION_PENDING` | 409 | 조건 질문에 먼저 답해야 함 |
  | `ALREADY_APPROVED` | 409 | 이미 승인했거나 승인할 수 없는 판정 |
  | `CONFLICT` | 409 | 그 밖의 상태 충돌(분석 처리 중, 가입된 이메일, 질문 · 회로 한도) |
  | `PAYLOAD_TOO_LARGE` | 413 | 넷리스트 5 MiB · 요청 본문 한도 초과 |
  | `RATE_LIMITED` | 429 | 가입 횟수 · 호출 간격 제한 |
  | `LIMIT_EXCEEDED` | 429 | 하루 토큰 · 비용 상한 |
  | `UPSTREAM_ERROR` | 502 | LLM · 임베딩 바깥 서비스 장애 |
  | `UNAVAILABLE` | 503 | DB · 저장소 · 서버 설정을 쓸 수 없음 |
  | `TIMEOUT` | 504 | 분석 시간 초과 |
  | `INTERNAL_ERROR` | 500 | 예상 못 한 오류, 내용은 로그에만 |

- 코드는 화면이 다르게 행동해야 할 때만 나눈다. 행동이 같으면 코드 하나에 구체적인 `message`를 붙인다.
- 분석 거절(SSE 마지막 이벤트 `refused`, 이유는 `backend/multi_agent/contracts.py`의 `Reason` 값)은 요청 실패가 아니라 분석 결과라 이 표에 넣지 않는다.
- 오류를 남기는 서버 로그 줄에는 `code`와 `request_id`를 함께 적는다.

## 이유
- 지금 `error.code`는 HTTP 상태와 일대일이라 상태 코드 이상을 알려 주지 않는다. 409는 19곳(서로 다른 상황 17가지)이 `CONFLICT` 하나이고, 503은 19곳이 `SERVICE_UNAVAILABLE` 하나이며 502는 없다. 화면이 상황을 가르려면 한국어 `message`를 비교해야 하고, 문구를 고치면 그 분기가 소리 없이 깨진다.
- 나눈 코드마다 화면이 하는 일이 다르다. `CONDITION_PENDING`은 조건 입력 폼을 다시 보여 준다. `ALREADY_APPROVED`는 승인을 다시 보내지 않는다. `RATE_LIMITED`는 잠시 뒤 다시 시도하고, `LIMIT_EXCEEDED`는 다음 날까지 기다린다. `UPSTREAM_ERROR` · `UNAVAILABLE`은 잠시 뒤 다시 시도할 수 있고, `TIMEOUT`은 시간 예산을 다 쓴 분석이라 같은 요청을 바로 되풀이하지 않는다. `FORBIDDEN`(권한)과 `ORIGIN_MISMATCH`(접속 주소 · 배포 설정)는 안내할 내용이 다르다.
- 그 밖의 409(분석 처리 중, 가입된 이메일, 질문 · 회로 한도)는 화면이 `message`를 보여 주는 것으로 같아 `CONFLICT` 하나로 둔다. 코드가 늘수록 화면 · 시험 · 문서가 맞춰야 할 값도 는다.
- 502와 503을 나누면 운영에서 로그의 코드만으로 "바깥 제공자(LLM · 임베딩)가 실패했다"와 "우리 DB · 설정을 쓸 수 없다"를 가른다. 확인할 곳이 다르다(제공자 상태 대 DB · 환경변수).
- 이름을 UPPER_SNAKE로 두는 것은 React가 이미 `error.code !== 'UNAUTHORIZED'`로 비교하기 때문이다(`frontend/src/auth/AuthProvider.tsx:43`). 커밋 `00a036a`에서 화면 코드가 비교하는 값은 이것 하나다(그 밖의 코드 문자열은 시험 픽스처에만 있다).
- 분석 거절을 HTTP 오류와 섞으면, 정상으로 끝난 분석(범위 밖 · 근거 없음)과 실패한 요청을 화면이 같은 자리에서 처리하게 된다.

## 결과
- 구현 전이다. 다음 변경에서 SPEC 4절의 오류 표, `ERROR_CODES`와 예외 처리 코드, 시험을 함께 고친다. 바뀌는 값을 쓰는 `frontend/src`의 시험 픽스처와, 본문이 없을 때 `HTTP_ERROR`를 채우는 `frontend/src/api/conversations.ts:27`도 맞춘다.
- 같은 변경에서 구조화한 JSON 로그를 넣는다: 줄마다 심각도 · `request_id` · `code`, 5xx는 traceback까지, 질문 글 · 키 · 개인 정보는 적지 않는다.
- 커밋 `00a036a` 기준 로그의 빈틈: 로깅 설정(`basicConfig` · `dictConfig`)이 없다. DB 503 처리기(`backend/main.py`의 `database_unavailable`)는 로그를 남기지 않는다. `request_id`를 적는 로그 줄은 3곳(`backend/api/conversations.py` 2곳, `backend/conversations/memory_service.py` 1곳)뿐이다.
- 정하지 않은 것: 표에 없는 HTTP 상태(예: 메서드가 틀린 405)는 지금 `HTTP_ERROR`를 받는다. 구현할 때 정한다.
