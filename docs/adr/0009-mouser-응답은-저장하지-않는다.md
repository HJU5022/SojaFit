# 0009 Mouser 가격·재고는 저장하지 않고, 견적서를 열 때마다 다시 조회한다

- 날짜: 2026-11-02
- 상태: 채택
- 근거: 조장 결정(11-02), Mouser Search API Terms of Service(최종 수정 2013-03-11, https://www.mouser.com/apiterms/) 1·2·4·5절 확인(11-02)
- 일부 바뀜: 견적은 가격 없이 승인 후보의 품번 · 수량만 저장하고, 데모 가격표(`data/demo/`)는 만들지 않았다. 작업대의 "가격·재고"와 견적 목록의 행은 사용자가 조회를 누를 때, 견적서 문서는 열 때 한 번 `/api/prices`로 Mouser를 부른다. 데모 모드와 키 없음은 `available: false`, `parts: []`다. Mouser 값을 저장하지 않는 결정은 그대로다([SPEC.md](../../SPEC.md) 1절 · 4절 · 7절 · 8.4).

## 결정
- Mouser API 응답(가격·재고·단종 여부 등)은 DB, 파일, 데모 응답, 대화 기록·체크포인트, Langfuse 트레이스 어디에도 남기지 않는다. 에이전트 답변 문장에도 Mouser 값을 넣지 않는다.
- 견적서에 저장하는 것은 판정 결과(품번·제조사·수량)와 데모 가격표(`data/demo/`) 값이다. Mouser 가격·재고는 견적서를 열 때마다 API를 다시 불러 견적서 화면에만 보여 주고, 옆에 "가격·재고 출처: Mouser Electronics, 조회 시각, 약관상 저장하지 않음"을 붙인다. 그래서 견적서의 Mouser 가격은 저장한 시점이 아니라 연 시점의 값이다.
- 키 없이 도는 데모 모드에서는 Mouser 칸을 비우고 데모 가격표만 보여 준다. 기록해 둔 Mouser 응답을 재생하지 않는다.

## 이유
- 약관 4절은 Mouser 콘텐츠의 어떤 부분도 캐시·기록·미리 받기·저장하지 못하게 하고, 그것으로 자체 DB를 만들거나 갱신하지 못하게 한다. 5절은 앱 안에서 복사·표시하는 것은 허락하되 출처를 분명하고 눈에 띄게 밝히게 한다.
- 1절은 Mouser 콘텐츠를 다른 회사 콘텐츠와 구분 없이 섞는 것을 허용하지 않는다. TSC 데이터시트 근거와 Mouser 값을 화면에서 나눠 보여 주는 이유다.
- MVP 견적서 가격은 이미 데모 가격표(`price_source` `demo`)로 정해져 있어 이 결정으로 MVP 범위는 바뀌지 않는다.

## 결과
- `docs/TOPIC.md` 범위 칸의 "데모 모드에서 기록해 둔 응답을 쓰고"는 통과한 주제서 원문이라 고치지 않고, 이 결정과 `SPEC.md`를 따른다.
- `db/schema/table-definition.md` 10절의 "실시간 가격과 재고 스냅샷", "Mouser API 요청·응답 이력"은 이 결정에 따라 만들지 않는다.
- 확인하지 않은 것: 키 발급 승인(약관 2절은 Mouser 상품 홍보·판매가 주목적이 아닌 앱을 거절할 수 있다고 적는다), 호출 한도(API 문서에 없음), 견적서를 PDF로 내려받게 하는 것이 저장에 해당하는지.
