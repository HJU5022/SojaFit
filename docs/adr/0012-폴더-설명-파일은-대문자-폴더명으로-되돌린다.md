# 0012 폴더 설명 파일은 대문자 폴더명으로 되돌리고, 파일 위치는 SOJAFIT.md 트리가 정한다

- 날짜: 2026-11-03
- 상태: 채택
- 근거: 조장 하정운 결정(11-03)
- 대체: [0011](0011-폴더-설명-파일은-readme로-쓴다.md)

## 결정
- 폴더 설명 파일은 다시 `<대문자 폴더명>.md`로 쓴다(예: `backend/BACKEND.md`). [0002](0002-폴더-설명-파일-이름-대문자.md)의 이름 규칙으로 돌아간다. `README.md`는 루트 대표 문서 하나만 둔다.
- 대문자 마크다운은 루트 대표 문서 6개와 폴더 설명 파일만 쓴다. 예외는 다른 곳이 이름을 정한 `docs/TOPIC.md`·`docs/GATES.md`(과제 가이드), `backend/mcp_skill/skills/SKILL.md`(Skill 관례, 코드가 읽음), `.github/PULL_REQUEST_TEMPLATE.md`(GitHub 관례)다. 그래서 `evals/PREREGISTER.md`·`db/ERD.md`·`backend/web/DESIGN.md`·`docs/worklog/STH.md`와 평가 검수 문서를 소문자로 바꿨다.
- 폴더와 파일의 위치는 `SOJAFIT.md`의 디렉토리 트리가 정한다. 트리의 모든 항목에 `<-` 설명을 달고, 새 파일은 같은 PR에서 트리 한 줄과 그 폴더 설명 파일의 "파일" 한 줄을 넣는다. 폴더 설명의 "넣는 것"을 새 파일에 맞춰 넓히지 않는다.
- 이 정리에서 역할이 다른 파일을 옮겼다.
  - `docs/specs/`에는 기능 작업서만 남기고, 실험·평가 작업서는 `docs/experiments/`로 옮겼다.
  - 조사·실측 기록과 합의 전 제안은 `docs/research/`로 옮겼다.
  - 동결 전 평가셋 초안과 검수 기록은 `evals/drafts/`로 옮겼다.
  - 평가 지표가 아닌 측정 결과(인증·저장·파서·색인)는 `scripts/results/`로 옮겼다.
  - `evals/README.md`가 겸하던 평가셋 명세는 `evals/dataset-guide.md`로 나눴다(지금 위치 `evals/guides/dataset-guide.md`).
- `tests/repo/test_repo_layout.py`가 위 규칙을 PR마다 검사한다.

## 이유
- `README.md`가 폴더마다 있으면 편집기 탭·검색 결과·에이전트 로그에서 어느 폴더 것인지 이름으로 구분되지 않는다. 0011은 GitHub이 폴더 아래에 펼쳐 보여 준다는 이유였지만, 조장은 이름으로 폴더를 아는 쪽을 택했다.
- 대문자의 효과는 정렬에서 나온다. GitHub 파일 목록과 터미널 `ls`·`git ls-files`는 대문자를 먼저 정렬해 설명 파일이 위에 온다(2026-11-03 확인). VS Code·Finder는 기본 설정에서 섞어 정렬해 효과가 없다. 같은 폴더에 다른 대문자 문서가 있으면 구분이 사라지므로 예외를 넷으로 묶었다.
- macOS 파일시스템과 이 저장소의 `core.ignorecase=true` 때문에 대소문자만 바꾸는 이름 변경은 `git mv`를 두 번 거쳐야 기록된다.
- 폴더 설명이 들어온 파일에 맞춰 역할을 넓혀 온 탓에 폴더 역할과 내용이 어긋났다. 위치의 정본을 트리 한 곳에 두고 테스트로 묶어 다시 어긋나지 않게 한다.
