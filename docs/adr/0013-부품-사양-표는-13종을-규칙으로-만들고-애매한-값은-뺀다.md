# 0013 부품 사양 표는 13종을 규칙으로 만들고, 애매한 값은 빼고, 표본 대조로 검증한다

- 날짜: 2026-11-05
- 상태: 채택
- 근거: 조장 하정운 결정(11-05)
- 일부 바뀜(11-05): 표본 대조는 조장 하정운이 판정했다(대조 방법은 `docs/deliverables/ai_tools_log.md`). 첫 표본 50개 결과는 값 269줄 중 O 265 · X 4(모두 VF), 거르는 값 X 0, 빠진 값 21줄은 모두 PDF에 있었다(놓침).

## 결정
- 판정과 후보 찾기에 쓰는 숫자 사양 표(`part_specifications`)는 데이터시트 표 청크를 규칙(코드)으로 숫자화해 만든다. LLM으로 값을 읽지 않는다. 표는 DB에 저장하고, 사용자에게 보여 주는 근거는 언제나 원본 청크(쪽·표·행)다.
- 범위는 코퍼스의 TSC 다이오드 13종 전부다. 항목 코드는 `db/schema/table-definition.md` A-07의 10개에 `VR`(직류 역전압), TVS·ESD용 `VRWM`(동작 전압)·`VBR`(항복 전압)·`VC`(클램프 전압)·`IPP`(순간 최대 전류)·`PPPM`(순간 최대 전력)·`VESD`(정전기 내성)를 더한 17개다.
- 애매한 값은 추측하지 않고 표에서 뺀다. 뺀 줄은 사유와 함께 검토 목록에 남기고, 그 부품은 "문서로 확인 안 됨"으로 답한다.
  - 한 칸에 여러 부품 값이 몰린 시리즈 범위(`20 - 40`)는 그 줄·칸에 적힌 품번과 값의 개수·순서가 맞을 때만 품번별로 나눈다.
  - 같은 부품·항목·시험 조건에 값이 둘 이상이면 둘 다 뺀다. 시험 조건이 다르면 각각 남긴다.
  - 단위를 모르는 값은 뺀다.
- 정확도는 두 겹으로 잰다.
  - 모든 줄: 값이 원본 청크 글에 그대로 있는지 코드로 검사한다.
  - 표본: 13종에서 고르게 뽑은 부품 50개의 핵심 값을 사람이 원본 PDF와 대조한다. 후보를 거르는 값(역전압·전류·제너 전압·동작 전압)은 표본에서 틀린 값이 0개가 될 때까지 규칙을 고친다.

## 이유
- 벡터 검색은 질문과 비슷한 청크 몇 개를 찾는다. "조건에 맞는 부품을 전부" 찾으려면 값을 숫자로 바꿔 코드가 걸러야 한다. 동결 v2 70문항 단일 기준 점수(사전 등록 #31)에서 과잉 거절 23건 중 19건이 후보 찾기·판정 질문이었다.
- 13종 전부가 지원 범위다(SPEC 6절). 코퍼스에 있는 종류를 판정 단계에서만 빼지 않는다.
- 틀린 값으로 판정하는 것보다 "문서로 확인 안 됨"이 안전하다.
- 원형(11-03, 저장소 밖)은 무작위 30행 원문 대조에서 처음 8건이 틀렸고 규칙을 고친 뒤 새 30행에서 1건이 틀렸다. 11-05 시험에서 숫자로 바꾼 비율은 표 청크의 83.4%이며 이 값은 정확도가 아니다.

## 결과
- 변환 코드는 `backend/rag/pipeline/specs.py`, 단위 환산은 `backend/rag/units.py`다. 변환 결과는 데이터시트 값이라 저장소 밖에 둔다.
- DB 적재(마이그레이션)는 표본 대조를 통과한 뒤 한다.
