# SojaFit 기본 다크 프론트엔드 설계

## 배경과 목표

SojaFit의 로그인·관리자·회로 작업대를 하나의 PCB 분석 도구처럼 보이게 한다. [Flux PCB Editor reference](https://docs.flux.ai/reference/reference-pcb-editor)의 어두운 편집기 셸, 계층적인 도구 패널, 높은 정보 밀도를 참고하되 화면 구조나 브랜드 표현을 복제하지 않는다.

기본 테마는 다크이며 별도 테마 전환 기능은 만들지 않는다. 기존 API 계약, 인증 경계, 라우팅, 작업대 3열 구조, 모바일 drawer와 결과 tab, SVG 연결 의미는 바꾸지 않는다.

## 시각 방향

### 색상 토큰

- `canvas #0B0F14`: 앱 전체와 작업 캔버스
- `surface #121821`: 기본 패널과 상단 바
- `surface-raised #18212C`: 입력·선택·강조 패널
- `line #2B3948`: 패널·표·입력 경계
- `text #E6EDF3`: 제목과 본문
- `muted #8FA3B8`: 보조 설명과 메타데이터
- `trace #35D0BA`: 활성 net, 선택, 기본 동작
- `warning #F0B35A`, `danger #FF6B6B`: 주의와 오류

`color-scheme: dark`를 루트에 선언해 브라우저 기본 컨트롤도 다크 UI와 맞춘다. 색만으로 상태를 전달하지 않고 기존 문구·테두리·아이콘 없는 텍스트 계약을 유지한다.

### 타이포그래피

한국어 본문과 제어는 현재 시스템 글꼴을 유지한다. 부품 참조번호, 부품값, 상태 코드, net 이름과 데이터 좌표에는 `ui-monospace`, `Cascadia Code`, `Consolas` 순서의 모노스페이스 스택을 사용한다. 외부 폰트와 새 UI 라이브러리는 추가하지 않는다.

### 형태와 깊이

큰 그림자나 유리 효과 대신 배경 명도와 1px 경계로 패널 깊이를 구분한다. 둥근 모서리는 6px 이하로 줄여 편집기 도구창의 밀도를 만든다. 버튼과 입력은 최소 40px 높이와 명확한 focus ring을 유지한다.

## 화면별 설계

### 공통 셸

상단 바는 어두운 고정 도구막대처럼 보이게 하고 SojaFit 회로 기호와 활성 메뉴에 `trace` 색을 사용한다. 본문은 넓은 캔버스 위에 배치하며 모든 페이지의 배경·패널·오류 상태가 동일한 토큰을 사용한다.

### 로그인과 관리자

로그인은 중앙의 단일 raised panel로 유지한다. 입력·Google 링크·오류 문구의 대비와 focus를 다크 토큰으로 맞춘다. 관리자 표와 상태 변경 제어도 작업대와 같은 표·버튼 규칙을 사용한다.

### 회로 작업대

기존 프로젝트 rail, 중앙 회로/대화, 우측 근거/판정/승인 구조를 유지한다. 각 열은 같은 배경의 카드 모음이 아니라 서로 다른 도구 panel 계층으로 읽히게 한다. 선택한 프로젝트·후보·tab은 `trace` 경계와 낮은 채도의 청록 면으로 표시한다.

### 연결 개념도

SVG 배경에 낮은 대비의 20px 격자를 CSS/SVG 패턴으로 넣는다. 직접 연결은 청록, 2단계 연결은 낮은 대비의 청회색으로 표현한다. 중앙 대상 부품에는 얇은 외곽 발광만 사용한다. 연결 방향 데이터가 없으므로 화살표는 계속 표시하지 않는다.

### 상태와 반응형

loading·빈 상태·대상 없음·역할 분석 전·조건 부족·판정 완료·분석 오류 문구는 유지한다. 오류는 붉은 경계와 어두운 적색 면, 주의는 황색 경계와 갈색 면을 사용한다. 900px 이하에서는 기존 프로젝트 drawer와 결과 tab 동작을 보존하며, 터치 영역을 줄이지 않는다.

## 구현 경계

주된 변경은 `frontend/src/styles.css`의 의미 토큰과 기존 selector다. 필요한 경우에만 SVG 격자와 데이터용 class를 기존 컴포넌트에 추가한다. API, 상태 모델, fixture, 인증, 가격·재고 비저장, 사용자 소유권 로직은 변경하지 않는다. 이미지·외부 검색 결과·새 그래프 라이브러리·테마 전환 상태·브라우저 저장소는 추가하지 않는다.

## 검증

- 루트가 기본 다크 색상 체계와 `color-scheme: dark`를 제공하는지 확인한다.
- 로그인·관리자·작업대의 기존 동작 테스트를 유지한다.
- SVG 선에 방향 marker가 생기지 않고 선택·깊이 구분이 유지되는지 확인한다.
- `npm run test:run`과 `npm run build`를 실행한다.
- 브라우저에서 로그인, 작업대, 모바일 폭의 focus·대비·overflow를 확인한다.
- 최종 diff에서 API·데이터 계약과 기존 사용자 변경이 건드려지지 않았는지 확인한다.

## 승인된 결정

- 전체 프론트에 적용한다.
- Flux형 편집기 셸을 사용한다.
- 기본값은 다크이며 라이트 모드와 전환 버튼은 만들지 않는다.
- 시각 비교용 별도 시안 도구는 사용하지 않는다.
