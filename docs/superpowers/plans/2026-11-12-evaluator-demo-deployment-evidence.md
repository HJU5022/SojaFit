# 평가자 데모·배포·운영 증거 완료 계획

기준: `OSC-chunk`의 `11dc216`(2026-11-12 원격 `main` 반영). 목표는 빈 로컬 환경의 키 없는 데모, 최종 배포 리비전의 평가 계정 전체 흐름, 최신 커밋의 평가·CI 결과, 실제 앱 요청의 Langfuse 증거를 모두 확보하는 것이다. 기존 11-11 배포 HTTP 점검 28건 통과는 당시 리비전의 증거로 유지한다.

## 선행 조건과 책임

| 필요한 것 | 확인·제공할 사람 | 확인 방법 |
| --- | --- | --- |
| 데모 녹화 및 실모델 평가용 OpenRouter·Voyage 키와 호출 예산 | 모델·평가 담당 | 키 값 공개 없이 설정 존재와 소액 시험 호출 확인 |
| GitHub Actions 실행 가능 상태 | 조직 결제 관리자 | 조직 결제 오류로 runner가 시작하지 않는다. 사용자의 11-12 지시에 따라 이 문제는 이번 작업에서 더 진행하지 않는다. 로컬에서 같은 테스트를 실행하고 원격 CI 결과는 미확인으로 표시한다 |
| 읽기 가능한 평가 DB, GitHub Actions Secrets | 저장소·DB 관리자 | 평가 job의 연결 시험. 운영 DB의 쓰기 권한은 부여하지 않음 |
| Cloud Run 배포 권한, 평가 계정 A/B | 배포 담당 | 리비전·트래픽 확인 및 두 계정 로그인 성공 |
| Langfuse 프로젝트 접근·전송 가능한 키 쌍 | 관측 담당 | 현재 배포의 `403 Forbidden` 원인을 주소·프로젝트·Secret 버전·수신 응답으로 확인 |
| 데모 스냅샷의 외부 배포 범위 | 자료 권리 담당 | 현행 자료 사용 근거 확인. 허용되지 않는 자료는 사용 가능한 합성 자료로 교체 후 재녹화 |

선행 조건의 값과 접근 권한은 현재 작업 트리만으로 확정할 수 없다. 키·쿠키·DSN은 계획서와 결과 파일에 기록하지 않는다. 각 외부 실행은 해당 담당자가 설정을 확인한 뒤 진행한다.

## 실행

1. **빈 DB 초기화를 바로잡는다.** `db/` 최상위에는 코퍼스 SQL과 단일 서비스 기준선, 권한 회수 SQL만 자동 실행되게 한다. 옛 증분의 이력은 `db/legacy/`에 보존한다. `026_projects_catalog_demo.sql` 등 옛 파일에만 있는 유효한 제약을 기준선과 대조해 보존한다. `docker-compose.yml`, `memory_service.initialize`, `tests/db_schema.py`, `scripts/db/verify_chain/verify_chain.sh`의 파일 경로와 초기화 책임을 대조한다. → **검증:** 격리된 빈 Compose 프로젝트를 `.env` 없이 `docker compose up --build` 한 번으로 기동하고 10분 이내 `/health`, 데모 로그인, 42문서·1,556청크 적재와 분석 저장소 준비를 확인한다. 기존 사용자 볼륨은 지우지 않는다.
2. **현재 그래프에 맞는 데모 기록을 만든다.** 첫 `Supervisor/Plan`의 `ReplayMiss`를 재현 기준으로 삼아 기존 `record_demo.py`로 5문항을 현재 코드·동일 스냅샷 DB에서 녹화한다. 답, 경로, 판정, 거절, 조건 질문·재개를 사람이 확인하고 기록 두 파일을 함께 갱신한다. 정확한 호출 키와 미등록 질문의 거절 동작을 유지한다. → **검증:** 모델 키를 비운 재생에서 5문항이 모두 일치하고 외부 호출이 0건이다. DB·녹화본을 바꾼 상태에서도 실제 LLM으로 넘어가지 않고 명확히 실패한다.
3. **로컬 화면과 HTTP로 평가자 흐름을 검증한다.** 데모 A로 프로젝트 생성→질문→조건 입력·재개→근거·판정→승인→수량을 넣은 견적 저장·재조회, B로 A 자원 접근 차단을 확인한다. 저장된 가격·재고가 없음을 견적 데이터와 대조한다. `scripts/smoke/http_smoke.py --demo --refusal`을 실행한다. → **검증:** 모든 단계가 통과하고 재접속 뒤 견적이 조회된다. UI에서 근거·조건·판정과 데모 표시를 확인하며 결과에 커밋과 실행 모드를 남긴다.
4. **최종 코드의 회귀와 실제 모델 품질을 확정한다.** 로컬 전체 관련 테스트·프런트 빌드·인젝션 재생을 실행한다. GitHub 결제 문제가 해결되면 해당 SHA의 `CI`와 `Secret Scan`을 성공시킨다. 같은 SHA로 수동 `Eval (live)`의 동결 v3 50문항을 실행한다. 기준 미달은 실패 문항과 원인을 고쳐 같은 조건으로 재실행한다. → **검증:** CI/JUnit/artifact 링크, 평가 SHA·모델·DB 지문·문항 수·정답/거절/오답·p50/p95·비용을 남긴다. 현재 workflow 기준 정답률 0.95 이상, 오류율 0.05 이하, p95 10초 이하를 충족한다.
5. **최종 리비전을 배포해 두 계정으로 재검증한다.** 배포 전 마이그레이션과 되돌리기 경로를 점검하고 수정 SHA를 명시한 Cloud Run 리비전을 시험한 뒤 트래픽을 전환한다. 운영 A/B의 로그인 방식에 맞춰 기존 HTTP smoke 또는 브라우저에서 질문→조건 재개→승인→견적 재조회와 B의 404를 반복한다. → **검증:** 배포 리비전과 SHA가 일치하고 전체 흐름의 상태 코드·SSE 결과·화면 기록이 같은 실행을 가리킨다. 11-11의 28건 통과 자료와 최종 실행을 구분한다.
6. **Langfuse 수신과 제출 증거를 완성한다.** 배포 Secret의 버전, `LANGFUSE_BASE_URL`, 키 쌍의 프로젝트와 수신 권한을 대조해 `403 Forbidden`을 해결한다. 실제 분석·재개 요청의 `analysis_events`에서 user/thread/version/request/trace ID와 단계별 지연을 읽어 Langfuse 수신 trace와 맞춘다. `docs/deliverables/langfuse/`에 대시보드 캡처 3장 이상과 trace 상세 1장 이상을 둔다. → **검증:** 동일 요청의 로컬 기록과 원격 수신이 일치하고 누락·전송 실패가 없다. `docs/GATES.md`, `EVAL_REPORT.md`, README에 최종 커밋·배포 리비전·증거 링크와 실측 범위를 반영한다.

완료 판정은 위 여섯 단계의 검증이 모두 끝난 때만 한다. GitHub Actions 결제, 모델·DB·배포·Langfuse 권한, 자료 사용 권리가 확보되지 않은 단계는 담당자와 필요한 조치를 명시해 열린 상태로 남긴다.

## 11-12 실행 현황

- `OSC-chunk`에 원격 `main`의 `11dc216`을 반영했다. 이후 변경은 작업 트리에 있으며 아직 커밋·푸시·배포하지 않았다.
- 빈 격리 Compose 프로젝트에서 DB 기준선, 데모 코퍼스 42문서·1,556청크, API 기동을 확인했다. 현재 작업 트리의 `.env`는 `DEMO_MODE=0`이므로 Compose 실행 시 환경 변수로 데모 모드를 명시했다. `.env` 파일은 수정하지 않았다.
- 현재 그래프에서 데모 5문항을 실제 모델로 녹화하고 키를 비운 재생 일치를 확인했다. 로컬 HTTP smoke는 28건 통과·실패 0건·건너뜀 0건이며 결과는 `scripts/results/smoke/smoke_localhost-8000_2026-11-12_011322.json`이다. 공유용 결과의 요청 ID는 제거했다. 결과의 `commit`은 시험 당시 기준 HEAD이며 미커밋 변경의 식별자가 아니다. 브라우저에서 배포용 번들의 데모 A 로그인, 저장된 판정, 문서 근거 표시를 확인했다.
- 프런트 단위 시험 233건 통과. 일회용 PostgreSQL을 연결한 Python 시험은 인증 81건, 삭제 12건, 나머지 1,783건 통과·32건 건너뜀이다. 격리 DB 없이 실행한 전체 Python 시험은 1,749건 통과·159건 건너뜀이다.
- Cloud Run `sojafit` 프로젝트에서 현재 트래픽 100%의 준비된 리비전이 `sojafit-api-11dc216`임을 읽기 전용으로 확인했다. 현재 작업 트리의 수정 코드는 이 리비전에 없다. 배포 Secret 버전 조회는 IAM 거부로 확인할 수 없었다.
- v3 50문항 실모델 gate는 Langfuse `api.projects.get`의 401 인증 오류 때문에 점수 산출 전에 멈췄다. 따라서 이 작업 트리의 50문항 점수·p95·비용, Langfuse 수신 trace는 아직 증명하지 못했다. 운영자의 Langfuse 프로젝트/호스트/키 쌍 확인과 Secret 접근 조치 후 같은 코드 상태에서 재실행해야 한다. 사용자는 담당자에게 조치를 요청하기로 했다.
- 최종 코드의 Cloud Run 배포와 배포 주소 A/B 스모크는 아직 실행하지 않았다. 배포 권한과 평가 계정 접근이 준비되면 수정 SHA를 배포하고 검증한다. TSC 청크의 외부 배포 범위는 자료 권리 담당 확인이 필요하다.
