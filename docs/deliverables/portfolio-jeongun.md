## 문제

소형 MCU로 시제품을 만드는 하드웨어 개발자는 단종 · 재고 부족으로 부품을 바꿀 때 유통사 사양 필터가 원래 부품과 같은 사양만 찾아 줘서, 회로에 비해 과한 부품을 그대로 쓰거나 시험 조건 차이를 놓친다. SojaFit은 KiCad 넷리스트에서 그 다이오드의 역할을 읽고, 후보마다 TSC 데이터시트의 쪽 · 표 · 행을 근거로 판정하는 LangGraph 멀티 에이전트다.

## 내가 내린 판단

- **Supervisor만 싼 모델로 바꾼 시도를 되돌렸다**(사전 등록 #46): 비용은 줄었지만 무관 질문 거절이 깨졌다. 찾기 질문은 코드가 Spec 에이전트로 보내게 한 뒤 같은 모델을 다시 채택했다(ADR 0017).
- **평가셋을 v3로 새로 동결했다**(ADR 0015): v2 점수에 청킹 결함이 섞여 있어, 평가셋과 청커를 함께 바꾼 뒤 다시 쟀다.
- **1 ~ 4문항 차이는 개선이라고 쓰지 않았다**: 같은 코드 두 세트도 2 ~ 7문항이 흔들려서다(3절).
- **사양 표 DB 경로를 버렸다**(ADR 0016): 카드 값 읽기와 코드 비교로 충분했고 표 적재는 유지비가 컸다.
