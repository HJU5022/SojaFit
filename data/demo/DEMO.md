# demo

## 역할
- 이 폴더: 명시적 `DEMO_SCENARIOS=1`·`DEMO_MODE=1` 앱 데모가 사용하는 합성 회로·응답·사양입니다. 실제 코퍼스/모델 정확도를 평가하지 않습니다. `DEMO_MODE=1`만 켠 기존 BM25 평가는 실제 LLM을 유지합니다. `snapshot/`은 키 없는 compose가 로컬 DB에 넣는 실제 TSC 데이터시트 청크 일부(42문서)이며, 합성 시나리오와 달리 검색(`retrieve`·MCP `search_corpus`)이 BM25로 읽습니다.
- 넣는 것: 데모 시나리오용으로 만들어 사람이 검토한 LLM 응답(합성 회로 설명은 [넷리스트], 합성 사양은 가상 문서·쪽·표·행 출처를 표시하며 실제 데이터시트 근거와 구분). 가격표와 Mouser 형식의 가격·재고 응답은 두지 않습니다. 데모 모드의 `/api/prices`는 값 없이 `available: false`를 돌려줍니다(SPEC 7절, ADR 0009). 키 없는 compose가 적재할 데모 코퍼스 스냅샷(`snapshot/`, 전체 v4h 청크에서 규칙대로 뽑은 manifest·청크 줄, 임베딩 없음).
- 넣지 않는 것: 실제 API 응답 원본, 키, 원본 PDF(`data/corpus/`), `snapshot/` 밖의 데이터시트 청크·발췌.
- 담당: 서비스·운영

## 파일
- `scenarios.json` — 합성 회로, 지원 질문 3개, 역할 응답과 가상 부품 사양. 실제 데이터시트가 아니다.
- `snapshot/` — compose `corpus-load`가 로컬 DB에 넣는 데모 코퍼스 스냅샷(TSC 42문서, 청크 1,556개). 출처·이용 조건·고른 규칙·sha256은 [SNAPSHOT.md](snapshot/SNAPSHOT.md)

## 실행·시연
- 새 환경에서 `.env` 없이 `docker compose up --build` 후 `http://localhost:8000/login`을 연다. **비밀번호 없이 "데모 사용자 A로 들어가기" · "데모 사용자 B로 들어가기" 버튼으로 들어간다.** A · B는 로컬 데모 전용 일반 사용자이며 평가용으로 제출한 계정과 다르다(비밀번호 로그인 불가). 사용자별 격리는 창 두 개(시크릿 창이나 다른 브라우저, 쿠키가 따로)에서 A와 B로 각각 들어가 확인한다.
- 기존 `.env`가 있으면 `DEMO_MODE=1`과 `DEMO_SCENARIOS=1`을 모두 명시한다. 기존 볼륨은 초기화하지 않으며 계정 시드는 빈 DB 첫 기동에서만 실행된다.
- 합성 시나리오는 React 이전 화면 `/workspace`에서 본다(React 작업대 `/app`의 분석은 합성 데모 회로가 아니면 422). 데모 사용자 A로 들어가기 → 주소창에 `/workspace` → 데모 회로로 새 분석 시작 → 데모 후보 판정 → 질문 보내기 → 12V/0.1A/전압 강하 모름 → 판정 사례 승인 → 새 분석 시작 → 데모 역할 설명 순서로 확인한다.
- 승인 사례의 정정 메모/철회/복구/기억 삭제를 시험한다. 삭제는 대화·승인 원본을 유지하고 향후 참조와 Store 사본만 제거한다. 자동 삭제는 보관 기간(프로젝트·분석 대화 마지막 활동 뒤 60일)뿐이다.
- 지원 질문/회로 외 입력은 422다. 합성 사양·응답은 실제 부품 적합성이나 모델 정확도를 증명하지 않는다. 외부키가 있어도 이 명시 모드는 LLM/MCP로 fallback하지 않는다.
