# 데이터

G3: **서로 다른 청크 1만 개 이상, 서로 다른 문서 50건 이상**(복제와 변형 제외), 문서 파싱 1종 이상. 2만 개 이상을 권장합니다.

## 폴더

| 위치 | 내용 |
|---|---|
| `corpus/` | 수집한 원문 스냅샷. 수집은 로컬에서 한 번 하고 **저장소에 커밋**합니다 |
| `manifest.jsonl` | 문서와 청크 목록. 인덱스를 만들 때마다 갱신합니다 |

수집한 날짜와 출처 주소를 기록하세요. 서버에서 호출이 막히는 소스를 피하고, 평가자가 같은 코퍼스로 재현하기 위해서입니다. 파일 합계가 수십 MB를 넘으면 강사에게 먼저 물어보세요.

## manifest 형식 (한 줄에 하나)

```json
{"doc_id": "doc-0001", "source_url": "https://...", "collected_at": "2026-11-02", "parser": "pdf", "chunks": 214}
```

청크 단위 기록이 필요하면 `chunks.jsonl`을 따로 두고 `doc_id`와 `chunk_id`, 위치, 본문 해시를 적으세요. 청크 수의 합이 1만을 넘고 해시가 서로 다르다는 것이 G3의 증거입니다.

## 저장소 크기 주의

벡터는 1024차원이면 1만 개에 약 41MB입니다. 본문과 manifest는 저장소에 두고, 벡터는 `db/` 아래 SQL로 적재하는 방법을 강사와 상의하세요.
