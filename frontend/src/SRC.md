# src

## 이 화면 복구 커밋의 운영 경계
- 이 버전의 production은 운영 API에 맞춰 Google 동의와 기존 비밀번호 로그인을 유지한다. 메일 인증/재설정 URL은 로그인으로 이동하고 메일 화면은 포함하지 않는다.
- 질문 NET/TXT 첨부는 개발 모의 검증용으로만 남기며 production에서는 입력을 숨기고 요청 전 차단한다. 프로젝트 넷리스트 업로드는 유지한다. 아래의 개발 기능 설명보다 이 운영 경계가 우선한다.


- `components/ConversationPanel.tsx`는 live thread의 이전 질문/답변을 메모리에 누적하고 현재 실행과 분리한다. 새 요청은 run 상태를 초기화해 이전 답변을 새 질문에 중복 표시하지 않는다. 위를 읽으면 자동 하단 이동을 멈추고 직접 전송하면 최신으로 이동한다. 저장 대화는 기존 cursor GET을 중복 없이 읽고 높이 차이로 스크롤 위치를 보정한다. 페이지 실패에도 기존 본문은 보존하며 과거 live 본문은 최신 결과 링크에 잘못 연결하지 않는다. `styles.css`는 긴 본문의 flex 축소와 저장 목록의 브라우저 자동 앵커 보정을 막는다.

- 채팅 첨부의 현재 범위는 UTF-8 NET/TXT다. ConversationPanel은 파일이 있어도 질문을 전송하고 useRunStream은 별도 multipart 실행 경로를 사용한다. 브라우저가 Content-Type boundary를 정하며 JSON 실행은 그대로다. 업로드 시작만으로 초안/파일을 지우지 않고 서버 run 접수 뒤 같은 초안만 함께 비운다. 실패/새 초안은 보존한다. 보낸 질문에는 파일명을 표시하며 도움말/개인정보 안내에 추출·기록 처리를 명시한다. PDF/이미지는 선택 시 미지원 오류를 표시하고 새 미리보기는 만들지 않는다. 아래 첨부 준비/전송 잠금 설명은 이 후속 구현으로 대체한다.

- 2026-11-12 이메일 인증 구현: 가입 화면은 이메일만 요청하고 EmailActionPage에서 인증 링크·새 비밀번호·확인을 처리한다. /verify-email 및 /reset-password는 공개 화면이다. AuthProvider는 메일 요청만으로 로그인하지 않으며, 재설정 뒤 지연된 초기 세션 조회도 복원하지 않는다. 아래의 이전 미구현 설명은 이 계약으로 대체한다.

- 질문 전송은 ConversationPanel의 공통 submit에서 초안 객체/이전 실행 상태를 기억하고 새 접수 상태가 오면 같은 초안만1회 비운다. 대화 생성 실패·runId 없는 접수 실패는 원문을 유지한다. 대기 중 새로 작성한 질문/첨부와 이미 비운 뒤의 입력은 완료/거절/재개/복구로 지우지 않는다. 기록 데모 질문도 같은 전송 경로를 사용하며 hook/API/인증/DB 계약은 유지한다.

- 2026-11-12 가입 신규 비밀번호는 api/auth.ts validNewPassword와 SignupPage에서15~1024코드포인트·공백뿐/숫자만/단순반복을 차단한다. 기존 로그인 정책은 유지하고 이메일 인증·재설정은 아직 미구현이다.

- WorkbenchPage의 openedTabs는 연 자료만 순서대로 우측 상단에 쌓는다. 고정5메뉴 없이 답변 링크/생성/작은 native 자료 열기로 추가하고 중복은 활성화만 한다. 각×/Delete로 닫고 활성 탭은 이웃으로, 마지막 닫기는 중앙 폭·호출 초점으로 복구한다. Left/Right/Home/End로 탭을 이동하며 열린 본문은 유지하고 닫은 본문은 해제한다. 프로젝트/대화 전환은 목록을 비운다. 기존 API·초안·회로 배율/5:5·답변 완료 시 현재 자료 유지 동작을 보존한다. 아래 과거 고정 메뉴 설명은 이 후속 요청으로 대체한다.
- ConversationPanel의 AnswerText는 현재 결과 근거 번호와 일치하는 `[숫자]`만 문서 근거 열기 링크 모양 버튼으로 표시한다. 저장 기록은 선택 run/메시지 자료 확인 뒤에만 연결하고 사용자 질문/확인되지 않은 번호/URL은 그대로 둔다. 자유 URL/HTML 해석은 없다. 아래 과거의 우측 고정 탭/레일 설명은 이 후속 요청으로 대체한다.

- 연결 개념도는 ± 버튼 대신 캔버스 휠(25% 단위,50~300%)과 포인터 드래그로 탐색한다. DOM 반영 뒤 커서의 SVG 좌표를 맞추고 native non-passive listener로 외부 스크롤을 막는다. 원래 포인터 대상을 캡처해 정상 노드 클릭을 유지하며4px 이상 드래그 뒤 클릭은 차단한다. 배율/맞춤·키보드 +/-·방향키·대상/페이지 초기화는 유지한다. 아래 이전 버튼 설명은 이 후속 요청으로 대체한다.

- 업로드 생성 직후 개념도 위치는 WorkbenchPage의 pendingConceptProject ref로 한 번만 맞춘다. URL 대상/상세 데이터가 준비된 effect에서 기존 패널 폭 전환이 끝난 뒤 캔버스를 nearest 스크롤하며 포커스 이동은 없다. 프로젝트 전환 시 예약을 비워 일반 탐색/상태 갱신에는 강제 스크롤하지 않는다.

- 넷리스트 업로드 성공 후 서버 parts/components의 첫 다이오드(ref D+숫자), 없으면 첫 부품을 URL 대상에 설정하고 회로 탭/상세 패널을 바로 연다. 기존 로컬 구현을 운영에도 반영하며 다른 프로젝트 전환·데모의 대상 초기화는 유지한다. 데이터는 해당 업로드 DTO만 사용하고 자동 분석·데모 대체·추가 모달은 없다. 아래 과거의 생성 후 자동 대상 없음 설명은 이 후속 요청으로 대체한다.

- 프로젝트/이전 대화의 추가 아이콘은 각 workspace-navigation-group hover/focus-within에서만 표시한다. 제목·목록·빈 상태 안내가 해당 범위이며 opacity로 버튼 공간/Tab 접근을 유지한다. 기존 생성/disabled/API는 변경하지 않는다.

- 우측 상세 패널은 기존 드래그/방향키 조절로 왼쪽 작업 메뉴를 제외한 폭의 절반까지 확장한다. 최소320px·초기 접힘/기본360px는 유지한다. CircuitContextDiagram은50~300%·25% 단위 확대/축소와100% 맞춤·스크롤/방향키 이동을 제공한다. 대상/회로/넷 페이지를 바꾸면 배율/위치를 초기화하며 조건/분석 상태 갱신과 노드 선택은 배율을 유지한다. 원본 회로도 도구·API·DB는 변경하지 않는다.

- 대화 상단의 선택 부품 원형 배지(JP4 등)를 제거했다. targetRef·저장 기록의 복원 대상·관리 창 선택·분석 요청은 유지하며 선택한 부품은 관리 창/회로 상세에서 확인한다. 아래 과거의 배지 표시 설명은 이 후속 요청으로 대체한다.

- 로그인 실패 안내: 계정 존재/잠금 여부의 동일401 정책을 유지하고, LoginPage에서 공개 code별 입력/요청 차단/시도 제한/서버·연결/세션 확인 실패를 안전한 문구와 요청ID로 구분한다.401에는 조건부 재가입/Google/반복 실패 대기를 안내하며 비밀번호는 비운다. 본인 삭제 성공 뒤 AuthProvider 메모리 상태로 삭제 완료를 표시하고 로그인/가입 성공·로그아웃/페이지 재시작에서 해제한다. 별도 존재 조회·브라우저 영속 저장·백엔드 변경은 없다.

- 설정 탐색·도움말: 내 설정의 개인 설정 목차를 제거하고 폼 제목을 프로필 정보로 표시한다. 기존 필드 저장/삭제·일반 계정 관리 유지, 관리자는 빈 sidebar 없이 한 열로 표시한다. 작업대 하단 도움말 버튼은 기존 AccessibleDialog로 기본 사용방법을 열고 초점 제한/Escape/닫기·초점 복귀·현재 초안을 보존한다. 안내는 현재 .net 등록/부품/세션/질문/결과/지연 확인과 첨부 미전송 제한만 소개하며 API 쓰기는 없다.

- 질문 입력은 프로젝트/부품 미선택·로딩·분석 중·저장 기록에서도 항상 활성이다. ConversationPanel.tsx의 ConversationComposer를 빈 화면/저장 기록/분석 화면이 공유하며 WorkbenchPage 메모리 draft로 선택 과정의 질문과 파일을 유지한다. 전송은 기존 실행 전제/동시 실행 제약을 지킨다. 이미지/PDF/NET/TXT 첨부는 로컬 선택·제거·이미지 URL 미리보기만 준비하며 아직 서버로 보내지 않는다. 최대5개·파일당5MiB·합계20MiB, 파일이 있으면 미전송 안내와 분석 잠금을 유지한다. 아래 과거의 입력 비활성 설명은 이 후속 승인으로 대체한다.

- 새 대화 +는 기존 thread API로 빈 세션을 즉시 만들고 목록에 강조한다. 생성 중 전환/중복 전송을 막으며 실패 시 기존 대화/초안을 유지한다. ConversationPanel은 생성 ID를 받아 첫 질문에 재사용하고, SavedConversationPanel은 소속·무메시지·무실행을 확인한 빈 세션만 편집으로 전환한다. DB/인증/서버 API 변경은 없다.

- 프로젝트 행 삭제: 저장된 프로젝트의 hover/focus에서만 휴지통 아이콘을 표시하며 선택 버튼과 분리한다. ProjectSidebar의 ProjectActions 삭제/확인/abort·캐시 정리를 확인 전용 모달에서도 재사용한다. 취소/닫기 시 해당 행으로 초점을 복구하고, 삭제 중 전환·중복 요청을 잠근다. 현재 프로젝트 성공만 URL/대화를 비우고 다른 프로젝트 삭제는 현재 초안을 유지한다. API/인증/DB는 변경하지 않는다.

- 단일 선택창 화살표: 공통 select CSS에서 오른쪽12px·세로 중앙에 장식 화살표를 두고 텍스트 오른쪽36px을 확보한다. 네이티브 select와 선택/disabled/포커스 동작은 유지하며 강제 대비에서는 기본 화살표로 돌아간다. 다중/목록형 select에는 적용하지 않는다.

- 2026-11-12 생성 흐름 후속 승인: CircuitSetup은 기존 `/api/auth/demo`의 명시적 활성 응답에서만 데모 선택/생성을 표시한다. 조회 실패/비활성에는 파일 생성을 유지한다. 새 프로젝트 생성 후 두 모달을 닫고 선택만 반영하며 자동 관리 창/분석/대상 추정은 없다. 수동 현재 프로젝트 관리·부품 선택은 보존한다. 오프라인 dummy API도 명시적 데모 상태를 제공하며 운영 번들에는 포함되지 않는다. 아래 과거의 생성 뒤 자동 부품 선택 모달 설명은 이 변경으로 대체한다.

- 2026-11-12 상단 프로젝트 요약 제거: 로고 옆 프로젝트명/부품/화살표 버튼과 헤더 전용 열을 제거했다. 기존 프로젝트/부품 관리 모달은 왼쪽 `현재 프로젝트` 제목 버튼으로 열며 생성 후 부품 선택·진행 중 잠금·저장 대화 대상 고정을 유지한다. 아래 과거의 상단 프로젝트 버튼/hover 설명은 이 변경으로 대체한다. 오른쪽 탭 재배치는 아직 구현하지 않았다. 도움말은 후속 기본 사용방법 dialog로 연결했다.

- 2026-11-12 운영 인증 화면: 로그인/회원가입에서 별도 동의 체크·동의값 전송을 제거하고 처리방침 링크를 남긴다. Google 버튼은 `Google 로그인`, 운영 `/signup`은 공개 로그인과 같은 양식이다. `PrivacyNotice` 인라인 컴포넌트는 제거했다. 로그인·가입 소개 배경은 낮은 대비의 오렌지/슬레이트 CSS 그라데이션이며 외부 사진은 선택 전 후보만 제안한다. 아래 과거의 동의 필수 설명은 이 후속 승인으로 대체한다.

- 실행 복구(2026-11-11): 스트림 수신 120초, GET 복구 최대 30회·1초 간격·요청당 10초 상한. 이후 오래된 실행 정리 API를 한 번 확인하고 상태 확인 버튼을 제공한다. 저장 기록의 새로고침도 이 API를 쓰며 분석은 재전송하지 않는다. 입력 오류는 폼과 공개 오류를 함께 표시한다. 공통 fetch와 SSE 시작 오류는 JSON 실패·HTML·빈 본문에도 안전한 코드·헤더 요청 ID·401 세션 만료를 유지한다.

## 역할
- 질문 한 칸의 조건 표시: circuitContext의 공통 INPUT_LABELS를 추가 입력 폼과 개념도가 함께 사용한다. 판정의 input_conditions를 표시하고 별도 conditions 문자열은 구버전/데모의 사용자 원문 표시로만 쓴다. 추출된 항목이 없으면 값을 추측하거나 무조건 전압·전류가 필요하다고 표시하지 않는다.
- 넣는 것: React 진입점, 화면 경로 셸, 공통 스타일, 실제 화면 동작 단위 테스트와 테스트 설정.
- 넣지 않는 것: 서버 API·권한 판정(`backend/`), 외부 모델 호출, 사용자 토큰의 브라우저 저장, 생성된 빌드 산출물.
- `/`는 새 목업 기반 공개 랜딩, `/login`은 소개·인증 입력 2열 화면이며 데모 모드면 비밀번호 없는 "데모 사용자 A · B로 들어가기" 버튼(로컬 데모 전용 계정, 평가 계정 아님)을 위에, 그 아래 비밀번호·설정된 Google 로그인, `/signup`은 가입(이메일·8자 이상 비밀번호·처리방침 고지 동의 필수), `/app`은 인증된 작업대, `/settings`는 내 설정(소속·직무·선호 실장 방식, SPEC 8.5)과 일반 계정의 계정 삭제(확인 뒤 `DELETE /api/me`), `/admin/users`는 관리자 전용 계정 활성 상태 관리입니다. 작업대는 프로젝트·회로 선택, 질문·진행·추가 입력·연결 복구, 근거와 5종 판정을 제공합니다. `projectId`·`threadId`·`targetRef`를 URL query에 두며 화면 이탈 시 프로젝트·run 요청을 폐기합니다. 로그아웃·탈퇴·세션 만료 때 `AuthProvider`가 React Query 캐시와 sessionStorage를 비우고, 보호 화면이 `/login`으로 replace해 주소의 프로젝트 id를 지웁니다. 900px 이하에서는 프로젝트 drawer와 결과 tab을 사용합니다.

## 회로 이미지와 공식 문서 근거
- `CircuitSchematic.tsx`는 검증된 데모 원본 회로도를 읽기 전용으로 표시하며 출처·라이선스·원본 자료·원본 저장소를 함께 보여줍니다. 데모 15종의 provenance와 자산 해시는 `data/circuits/visuals.json`에서 관리합니다. 이미지 로딩 실패 때 생성 이미지로 대체하지 않습니다.

Google 로그인 화면은 운영의 GET `/api/auth/google/start?consent=1` 계약을 사용한다. 공개 처리방침 링크·짧은 필수 동의·버튼 하나를 제공하며 동의 전에는 버튼과 hidden consent를 비활성화한다. 인증 전 긴 고지/관리자 전용 링크·인증 후 finish 별도 화면은 표시하지 않는다. 신규 가입/계정 연결 판단과 callback은 기존 운영 백엔드 그대로다. 운영 빌드의 이메일 가입 화면은 로그인으로 보내고 가입 링크/데모 버튼은 개발 환경에만 표시한다. 다른 인증 WIP는 외부 백업에 보존하며 테스트 배포에는 운영 이미지의 백엔드를 사용한다.
