# src

## 역할
- 넣는 것: 화면 소스(React·TypeScript·CSS).
- 넣지 않는 것: 판정·검색·인증 로직(`backend/`), 빌드 산출물, 비밀값, 단위 시험(`../tests/`).
- 담당: 서비스·운영.

## 경계
- 화면은 서버가 보낸 DTO만 그립니다. 숫자 비교와 판정은 `backend/judge/`에서만 합니다.
- 서버와의 통신은 `api.ts`의 `api()`와 `streamRun()` 둘뿐입니다. 쿠키 세션을 쓰고 자동 재전송을 하지 않습니다. 401은 `session-expired` 이벤트로 알리고 `App.tsx`가 화면 상태와 `sessionStorage`를 비웁니다.
- 경로는 라우터 라이브러리 없이 `ui.tsx`의 `navigate()` · `useLocation()`으로 다룹니다. 경로 표는 `App.tsx` 한 곳입니다.
- 스타일은 `styles.css` 한 파일의 일반 CSS입니다.

## 파일
- `SRC.md` — 이 폴더 설명.
- `main.tsx` — React 진입점·글꼴·스타일.
- `App.tsx` — 경로 표와 세션 경계. 공개 경로(`/` · `/login` · `/signup` · `/password-reset`, 하단 고지 문서 `/terms` · `/privacy` · `/ai-notice` · `/licenses`, 메일 링크용 `/verify-email` · `/reset-password`)와 로그인 뒤 경로(`/app`: 인자 없으면 새 대화 화면, `?project=&thread=`는 작업대 · `/settings` · `/approved` · `/library` · `/admin` · `/admin/users`, 옛 `/projects`는 `/app`으로 바꿈). `/approved/{id}/report`(인쇄용 보고서)만 사이드바 없이 그린다(#44). 사이드바 맨 위는 "새 대화"이고 프로젝트·대화 나무는 `Conversations.tsx`가 그린다. 사이드바 오른쪽 경계선으로 너비를 바꾼다. 사이드바 맨 아래는 계정 줄 하나이고, 누르면 위로 여는 계정 메뉴(`RowMenu`: 내 설정 · 사용자 관리(관리자) · 고지 문서 4개(`LegalModal`) · 문의 · 로그아웃, #43)가 열린다.
- `api.ts` — 쿠키 API fetch 경계·오류(`ApiError`)·SSE 연결, 판정 5종·실행 상태의 화면 표기(`verdicts` · `statuses`).
- `types.ts` — 공개 API 자료형.
- `stream.ts` — SSE 프레임 복원(UTF-8 청크 경계·종료 이벤트).
- `circuit.ts` — 프로젝트 연결에서 부품 목록과 핀·넷 뽑기, 회로 없는 대화의 넷리스트 요청 답 글자(`NEEDS_CIRCUIT`, 서버 `NEED_NETLIST`와 같음), 질문으로 지은 프로젝트 이름(`projectNameFromQuestion`), 업로드 409 중복 목록으로 할 일 정하기(`duplicateAction`: 같은 넷리스트면 그 프로젝트로 계속, 이름만 겹치면 새로 만들기, #48), 첨부 파일 종류(`acceptsFile`: 받는 확장자인지, `isSchematicFile`: `.kicad_sch` 회로도인지, #52). `unsupportedPartReason`은 LED·표시기·다이오드가 아닌 부품을 판정 대상에서 빼고 서버(`_require_supported_target`)와 같은 문구로 이유를 보인다(서버가 최종 판단). 회로 패널은 고르라는 말 없는 사실 한 줄 `unsupportedPartNote`("이 회로의 D2(LED)는 …", #50)를 쓴다. 부품 점검표(#68)의 거르기 `filterParts`(종류 · 판정 지원만)와 "이 부품 검토" 질문 `reviewQuestion`(ref 받침으로 을/를). 시험 `../tests/circuit.test.ts`.
- `approval.ts` — 한 검토 결과의 승인 목록에서 후보 하나의 승인 상태(이 후보 승인, 다른 후보 승인)를 가르는 순수 함수. 서버는 사례가 남은 활성 승인만 돌려주므로 사례를 지우면 다시 승인할 수 있다. 시험 `../tests/approval.test.ts`.
- `display.ts` — 서버 숫자·기준식·링크를 화면 표기로 바꾸는 순수 함수와 입력창 보내기 키 판정(`isSendKey`: Enter만, Shift+Enter · 한글 조합 중 제외, #38), 진행 단계 시간(`addStep` · `stepMs` · `seconds`: status 도착 시각으로 단계마다 재고 재계획은 이어 더함, #42): 긴 소수는 유효숫자 3자리로(받은 값은 마우스를 올리면 보임), 판정 기준식(`v_in_max * kV`)은 한국어로, 답변 속 등록된 말뭉치 인용 번호(`[79]`)는 숨기고, 링크는 http(s)만, 수량별 가격 조회 경로(`/prices?parts=…&quantity=…`)와 예상 금액 줄(적용 구간·단가·금액, 계산을 보류한 경우 안내), 답의 판정 후보 모으기(`replyCandidates`, #55). 시험 `../tests/display.test.ts`.
- `inputLabels.ts` — 판정 입력 코드(회로 값 이름)의 화면 이름과 입력칸 안내(`inputPlaceholder`). 이름과 뜻은 `backend/judge/rules/roles.yaml` 머리말과 짝이다.

- `Conversations.tsx` — 대화가 먼저인 입구. 사이드바 나무(`ConversationNav`, #31 #36): "프로젝트 +"(새 프로젝트 창) 아래 회로가 있는 프로젝트마다 접고 펴는 줄과 그 대화(`GET /api/threads` 한 번을 프로젝트별로 나눔) · "이 회로로 새 대화", 회로 없는 프로젝트(`has_circuit=false`)의 대화와 빈 프로젝트는 나무 위 "대화"에 한 줄씩. 펼친 프로젝트는 localStorage에 남기고 열린 대화의 프로젝트는 주소가 바뀔 때마다 펼친다. 대화·프로젝트 줄 ⋯ 메뉴로 그 자리 이름 변경(`PATCH /api/threads/{id}` · `/api/projects/{id}`) · 확인 뒤 삭제. 이름을 바꾸면 `thread-renamed` · `project-renamed` 이벤트로 열린 작업대 제목도 고친다. 새 대화 화면(가운데 공통 안내: 넷리스트·회로도 첨부하기 한 줄과 지원 범위 한 줄, 예제 넷리스트를 건네는 입구는 두지 않음(#58), 특정 부품을 가정한 예시 질문은 두지 않음, 입력창은 화면 아래, #41 #45. 질문 입력창 하나, #30: 넷리스트 · 회로도는 입력창 + 메뉴나 화면 끌어 놓기로 첨부(`.net` · `.kicad_sch`, #40 #52) → 파일 이름으로 `POST /api/projects/upload`, 없으면 질문 앞 30자로 회로 없는 프로젝트. 만든 뒤 `Workbench.tsx` `openWithQuestion`으로 새 대화에 첫 질문을 보냄. 409 중복이면 묻지 않고 `circuit.ts` `duplicateAction`대로 같은 넷리스트의 프로젝트로 이어 가거나(작업대 대화 위 한 줄 안내) 이름만 겹치면 `allow_duplicate=true`로 한 번 다시 만든다, #48). 대화(thread)는 첫 질문 때 생긴다.
- `Projects.tsx` — 새 프로젝트 창(사이드바 "프로젝트 +"가 연다. 데모 회로·넷리스트 업로드·나중에 첨부)과 사이드바 목록 새로고침 알림(`refreshNavigation`). 프로젝트 목록 페이지는 사이드바 나무로 옮겼다(#34). `/api/demo-circuits`가 404(운영, `DEMO_MODE=0`)면 데모 회로 탭을 숨기고 넷리스트 업로드로 시작한다.
- `Workbench.tsx` — 검토 대화·실시간 진행·조건 재개·첨부 버전. 오른쪽 위 ⋯(프로젝트 메뉴)에서 이름 변경(작은 창)·삭제(확인 창). 따로 놓을 수 있는 조각: `TargetInfo`(정해진 검토 부품, 읽기 전용, #30. 대화를 옮기면 대상을 비우고 그 대화의 `target_ref`로 다시 정해 새 대화 화면은 정하지 않은 상태, #53. 지원하지 않는 부품 한 줄은 대상이 정해지기 전에만, #50), `CircuitSection`(연결 개념도 · 원본 회로도), `openWithQuestion`(새 대화를 만들고 첫 질문을 보냄, 새 대화 화면도 씀), `RunProgress`(실시간 진행 세로 목록 · 단계별 시간 · 총 시간, 끝나면 접힌 요약, #42. 시간 계산은 `display.ts`). 회로 없는 대화의 넷리스트 요청 답 아래 카드 `CircuitRequest`(넷리스트 첨부 · 기존 회로로 계속)를 붙이고, 그 대화에서 첨부하면 `thread_id`로 같은 대화에 회로를 붙인다(SPEC 8.9). 입력창은 Enter 보내기 · Shift+Enter 줄바꿈 · + 메뉴와 대화 영역 끌어 놓기로 첨부(`.net` · `.txt` · `.kicad_sch`, #40 #52). 질문 · 진행 요약 · 답 · 입력창은 가운데 최대 760px 기둥(`.conversation-scroll` · `.composer-area` 안쪽 여백), 내 질문은 오른쪽 말풍선, 면책 문구는 후보 판정이 든 답에만 한 번(#46 #55, 실행 기록을 받지 못한 저장된 답은 판정 여부를 몰라 그대로 붙인다). 검토할 부품·회로는 평소 닫힌 오른쪽 회로 패널(aside `.context-panel`, "회로 보기"·×·회로가 처음 생길 때 열림, 왼쪽 경계선으로 너비 조절, #39)에 둔다. 회로가 있는 프로젝트를 열면 한 번 저절로 열고, 사용자가 닫으면 localStorage `sojafit.panel.closed`에 남겨 다시 열 때까지 저절로 열지 않는다. 760px 이하(전체 화면 시트)에서는 저절로 열지 않는다(#51). 회로가 있고 대상이 정해진 대화의 답 머리와 대상 고르기 카드의 "회로 보기"(`Reply.tsx` `CircuitLink`)는 패널을 열고 회로 구역(`#circuit-section`)으로 내린다(#47).
- `Reply.tsx` — 검토 결과 답과 조건 입력 카드. 답마다 "AI 생성" 표시(화면 낭독기에는 "생성형 AI를 이용해 만든 답변", #27)를 붙이고, 면책 문구는 판정 후보(`display.ts` `replyCandidates`)가 있는 답에만 붙인다(#55).
- `Parts.tsx` — 부품 점검표 창(`PartsDialog`, #68). 작업대 머리 "부품 점검표"(좁은 화면은 아이콘만)가 "견적 목록"처럼 `Modal`(넓은 옆 창)로 연다. 그 대화의 회로 버전으로 `GET /api/projects/{id}/parts?circuit_version=`을 부르고, 종류 · 판정 지원 · 데이터시트는 서버 값 그대로 보인다(화면에서 다시 분류하지 않음). 위에 종류별 개수 칩(누르면 그 종류만, "전체"가 기본)과 "판정 지원 N개 · 데이터시트 있음 N개" 한 줄, "판정 지원 부품만" 체크. 표: 기호 · 값 · 종류 · 판정 지원(✓와 "이 부품 검토", 아니면 흐린 이유) · 데이터시트(`/library?q=품번` 링크, #67) · 풋프린트, 좁은 화면은 `.audit-scroll` 안에서 민다. "이 부품 검토"는 `openWithQuestion`(바로 보냄)을 쓰지 않고 창을 닫고 새 대화 화면 입력창에 질문만 써 둔다(보내기는 사용자). 회로 없는 프로젝트(v0)는 부르지 않고 넷리스트 첨부 단추를 보인다.
- `Schematic.tsx` — 원본 회로도 구역(작업대 오른쪽 회로 패널의 "회로" 구역에서 연결 개념도 아래). 그 회로 버전에 회로도를 올렸으면(`schematic_file`) `GET /api/projects/{id}/schematic?circuit_version=`의 그림을 "출처: 업로드한 회로도"와 파일 이름으로 먼저 보이고 웹 검색을 부르지 않는다(#52). 예제 프로젝트는 `/api/demo-circuits`의 저장된 도면(`/circuit-schematics/*.png`)과 출처·라이선스를 바로 보이고, 저장된 도면이 없고 넷리스트가 있는 프로젝트는 열 때 프로젝트 이름으로 `GET /api/external-circuits/schematics`(프로젝트·회로 버전·대화 문맥을 보내 서버가 부품·핀 연결이 같다고 확인한 도면만 받음)를 한 번 불러 결과를 바로 보인다. 찾는 중·찾지 못함(다른 이름으로 다시 찾기)·출처·라이선스를 보이고, 그림을 누르면 큰 창(`Modal`)으로 본다. 이미지는 같은 출처 경로만, 링크는 http(s)만 쓴다.
- `schematicSearch.ts` — 원본 회로도 검색을 "프로젝트 번호:회로 버전"마다 한 번만 보내는 탭 메모리(진행 중 검색 공유, 찾은 결과 14분·실패(못 찾음·오류)는 탭이 열린 동안 재사용해 사용자가 다시 찾을 때만 다시 보냄, 직접 찾기가 실패해도 앞서 찾은 결과는 유지). 시험 `../tests/schematicSearch.test.ts`.
