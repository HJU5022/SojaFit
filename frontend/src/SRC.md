# src

## 역할
- 넣는 것: 화면 소스와 그 단위 테스트.
- 넣지 않는 것: 판정·검색·인증 로직(`backend/`), 빌드 산출물, 비밀값.
- 담당: 서비스·운영.

2026-11-13에 화면을 전면 재작성했습니다. 이전 컴포넌트(ConversationPanel · CircuitContextDiagram · JudgementTable 등)와 `styles.css` · `workers/`는 없습니다. 경위는 [FRONTEND.md](../FRONTEND.md).

## 경계
- 화면은 서버가 보낸 DTO만 그립니다. 숫자 비교와 판정은 `backend/judge/`에서만 합니다.
- `api/` · `auth/` · `hooks/useRunStream.ts`는 서버 계약입니다. 화면을 고칠 때 시그니처를 바꾸지 않습니다.
- 스타일은 `styles/app.css` 한 파일의 일반 CSS입니다. 값은 [design.md](../design.md)의 토큰과 눈금만 씁니다.
- 401을 받으면 `api/client.ts`가 `sojafit:session-expired`를 알리고 `AuthProvider`가 화면 캐시와 탭 저장소를 비웁니다. 실패한 요청을 자동으로 다시 보내지 않습니다.
- 비로그인 대화 링크·세션 만료는 `/app`의 쿼리·해시를 로그인 경로 상태와 탭 임시 저장소로 전달해 로그인 후 복귀한다. 외부 주소·하위 경로·백슬래시·제어문자는 거절하고 성공 후 임시 주소를 지운다. 직접 로그아웃·탈퇴는 복귀를 막으며 저장소 차단 시 경로 상태만 쓴다. Google 콜백·가입·연결에도 같은 복귀 규칙을 적용한다. 회귀는 `auth/AuthProvider.test.tsx`.
- 작업대의 삭제·생성·이름 변경 오류는 닫기 버튼, 재시도 시작, 화면 이동과 창 닫기에서 해제한다. 이전 화면·닫힌 창의 요청이 늦게 끝나도 이전 오류나 화면 이동을 다시 적용하지 않는다.
- 대화 삭제는 처리 중 중복 진입을 즉시 차단하고 삭제 버튼을 비활성화하며 삭제 중 상태를 표시한다. 현재 대화 삭제 성공 시 새 빈 대화로 이동하고, 이미 다른 대화·화면으로 이동했으면 그 선택을 유지한다. 실패 후에는 잠금을 해제해 재시도할 수 있다.
- 프로젝트 ID가 바뀌면 검색어를 초기화한다. 프로젝트 목록과 프로젝트 사이 및 다른 프로젝트 사이의 브라우저 뒤로/앞으로 이동에도 부품·프로젝트 검색어를 이어받지 않는다.
- 새 프로젝트 창은 어느 생성 버튼으로 열어도 이름·첨부 파일을 기본값으로 초기화한다. 생성 실패 시에는 창과 입력값을 유지해 같은 내용으로 재시도할 수 있다.
- 프로젝트 생성409의 중복 후보는 같은 계정의 이름/최신 넷리스트 내용 일치다. 기존 열기 또는 명시적 새 생성(allow_duplicate)을 선택하고 입력 변경/닫기/재열기에는 동의를 초기화한다. 선택 파일과 이름은 유지하며 기본 Enter 전송으로 중복 허용을 추정하지 않는다. 기존 생성 API 함수는 선택적 허용 인자를 추가해 종전 호출을 보존한다.
- 프로젝트 이름 변경·삭제에서 NOT_FOUND를 받으면 해당 항목과 회로/검토 목록 캐시를 정리하고 목록을 다시 읽는다. 프로젝트 자체의 조회404도 목록으로 돌아와 안내하며, 대화 버전만404인 경우에는 프로젝트를 제거하지 않는다. 없는 프로젝트의 캐시를 비우기 전에 해당 프로젝트 자동 조회를 막아 화면 이동 대기 중 재조회 반복을 방지하고, 주소가 바뀌면 임시 차단을 해제한다. 늦은 목록/수정 응답은 확인된 제거를 취소하거나 현재 다른 화면·수정 창을 닫지 않는다. 그 외 오류의 입력 보존·재시도는 유지한다.
- 조건 대조 표의 항목 코드는 한 줄을 유지하고, 기준·근거 열은 너비를 나눠 가지며 긴 내용을 줄바꿈한다. 모바일 카드에서는 열 비율을 해제한다.
- 후보 판정은 채팅에 요약과 상세 보기 버튼을 표시하고, 선택한 run·품번의 판정·조건·근거를 속성 칸에서 보인다. 조건은 항목·결과와 요구값·후보값을 간결하게 표시하고 기준·시험 조건·근거를 펼쳐 확인한다. 불충족·확인 불가 이유는 접힌 상태에서도 보인다. 함께 요청한 문서 설명·추가 출처는 유지한다.
- 상세 탭을 다시 열면 메시지별 승인 기록을 서버에서 조회한다. 메시지·품번·판정이 일치하는 승인만 복원하며 다른 질문에 승인을 전파하지 않는다. 조회 실패 시 중복 승인을 막고 다시 확인할 수 있게 한다.
- 최신 미완료 실행은 재진입 시 조건 폼·진행 상태·공개 중단 사유를 복원한다. 대기/실패를 판정 없음으로 표시하지 않는다. 복원은 GET 최대30회만 확인하고 분석/재개/복구 POST를 자동 호출하지 않는다. 재개 오류 때 조건 초안은 같은 run에서 유지하고 성공하면 오류를 해제한다. 오래된 완료 결과 캐시는 새 상태로 갱신한다.
- 응답 수신 중단은 서버 취소와 구분해 표시한다. 실행 상태 재확인은 GET으로만 읽고 진행 중/조회 실패는 중단 상태·재확인을 유지한다. 완료/조건 요청 확인 전 새 분석 전송을 막고 초안은 보존한다. 실행 번호 수신 전 중단은 초안 소실 안내와 대화 새로고침을 제공한다.
- 최근50개 메시지보다 오래된 기록은 채팅 상단의 이전 대화 불러오기로 커서 기반 GET 조회한다. 실패 시 현재 기록과 커서를 유지해 재시도하고 대화 이동 후 늦은 응답은 무시한다. 실행 ID로 선택·DOM을 유지하고 앞에 추가한 높이를 보정해 읽던 위치·상세 탭·초안·첨부를 보존한다.
- 질문 입력창·첨부 목록·전송 안내는 검토 영역 하단에 유지한다. 대화 끝이 화면 아래에 있을 때 이동 버튼을 표시하고, 클릭하면 초안·첨부·선택을 유지한 채 끝으로 이동한다. 답변 도착이나 화면 크기 변화만으로 읽던 위치를 바꾸지 않는다.
- 채팅 답변의 숫자 코퍼스 인용은 그 답변의 evidence에 등록된 번호만 숨긴다. 코드·수치·미등록 괄호와 원본 응답은 유지한다. 문서 근거 보기로 해당 질문의 문서·쪽·표·행/절을 속성 칸에서 열고 같은 문서의 서로 다른 위치도 유지한다.
- 저장/실시간 대화에서 사용자 말풍선은 오른쪽, AI 답변과 진행 상태는 왼쪽에 둔다. 대화 본문의 아바타·이름·이메일·질문 머리말은 렌더링하지 않고 스크린리더용 발신자 설명과 기존 질문 선택은 유지한다.
- 파일 선택·드롭은 같은 검증(.net·.txt/5MiB 이하/빈 파일 제외/중복 제외)을 쓴다. 전송은 파일 한 개를 먼저 정규화 API로 보내 새 회로 버전·대화를 만든다. 대상 부품을 확인한 뒤 분석을 시작하고 실패 시 초안·파일을 유지한다. 일반 run 경계는 파일을 직접 받지 않는다. 창 뒤 첨부 차단과 기본 파일 입력 예외를 유지한다.
- 820px 이하에서는 표가 카드로 쌓이고 레일이 접힙니다. 상세 탭은 오른쪽 패널로 열리며 접기/Escape로 채팅에 돌아옵니다. 제목·회로·대화는 함께 스크롤하고 상세 패널만 별도 스크롤을 유지합니다.
