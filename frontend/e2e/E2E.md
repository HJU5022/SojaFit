# e2e

- 수평 사용 방법은 9노드/20장면을 실제 로컬 Chrome에서 전환하며 초기 숨김·각 팝업 최대 460×380px/지도 안쪽 경계·지도 높이 불변·Escape/초점복귀를 검사한다. 1440px은 열린 창의 1024×720 리사이즈·본문만 휠 스크롤/닫기 노출·명시적 확대의 별도 Esc 경계도 확인한다. 기존 8폭·수치/서체/정책/앵커 검사는 유지하며 API는 가짜 응답이다.

- 대화 누적 회귀는 같은 thread의4회 질문/완료·거절 답변 보존, 다음 응답 대기 중 위로 읽는 위치·새 초안 유지, 입력창 고정·접수 후 비움, 저장 세션 재열기와 이전 페이지 GET1회/읽던 위치 보정을 실제 Chrome+가짜 API로 확인한다. 실제 계정/운영 DB/모델 호출은 하지 않는다. 이전 페이지 오류/수동 재시도와 기존 메시지 보존은 D5Panels 단위 검사로 확인한다.

- NET/TXT 첨부 회귀는 실제 FormData 전송·성공 시 파일/입력 비우기·전송한 질문의 파일명 표시·다음 초안 보존·미지원 형식 거절을 검사한다. SOJA_ATTACHMENT_SERVER를 지정한 로컬 시험은 브라우저→운영 소스 API 파서→에이전트 그래프→가짜 모델→SSE→화면까지 연결한다. 실제 계정/운영 DB/유료 모델은 쓰지 않으며 파일명은 모델 입력에서 제외한다.

- 전송 후 입력 비우기 회귀는 실행 접수 시 빈 입력·대화의 원문 보존, 생성/실행 접수 실패 뒤 원문 유지와 수동 재시도 후 비우기, 응답 대기 중 작성한 다음 질문의 완료 후 보존을 mock Chrome에서 검사한다. 실제 계정 쓰기/모델 호출 없이 기존 SSE/상태 복구 흐름을 쓴다.

- 열린 자료 회귀는 초기 우측/탭0·중앙 전체 폭, 자료 선택→순서대로 탭 추가·중복 방지·활성 전환, 비활성/마지막 닫기·초점/폭/초안 복구를 실제 Chrome에서 검사한다. 답변 인용 번호로 근거 열기·기록별 결과·프로젝트 전환 초기화·생성 자동 개념도·5:5/휠 드래그와 탭 전환 후 회로 배율 보존을 가짜 API로 확인한다. 단위 검사에서는 탭별 닫기·Left/Right/Home/End/Delete 이동도 확인한다.

- 개념도 탐색은 실제 Chrome mouse.wheel/drag로 배율·커서 기준점·양방향 이동·외부 패널 스크롤 불변을 확인한다. 노드에서 드래그하면 선택되지 않고 다음 클릭/Enter는 정상 선택되며 맞춤 후 배율/좌표가 초기화된다. ± 버튼 부재와 기존5:5·자동 업로드 표시도 확인한다.

- 넷리스트 업로드 직후 기본360px 패널에서도 개념도 영역 전체와 선택 노드가 실제 viewport 안에 보이는지 검사한다. DOM 존재/레이아웃 완료만으로 화면 노출을 통과시키지 않는다.

- 새 대화 생성 회귀에서 추가 버튼의 기본 숨김·각 목록 hover 독립 노출·마우스 벗어남·Tab/초점 노출·자리 불변도 검사한다. 가짜 API에서 생성 실패/재시도/빈 대화 복원·전송을 함께 확인한다.

- 상세 패널/개념도 회귀는 격리 운영 빌드와 가짜 API에서1280·1440·1920px 실제 중앙/우측 폭 차이2px 이하·가로 넘침 없음, Worker 배치·200% 확대 크기·방향키 스크롤·노드 선택·맞춤 초기화·API 쓰기0회를 확인한다.

- 로그인 실패 회귀는 401/422/403/429/503·네트워크·HTML503·로그인 후 세션 조회 실패 8종과 본인 삭제 뒤 401/재진입 안내를 합성 API로 재현한다. 비밀번호 비움·요청 ID·안전 문구·로그인 POST 1회·존재 조회 없음·새 페이지 삭제 안내 부재를 확인하며 실제 운영 계정을 생성/삭제하지 않는다.

- 기본 도움말/설정 탐색은 일반 사용자·관리자 각각 dialog 열기·Tab 초점 제한·Escape/닫기·초안 보존, 개인 설정 문구 부재·프로필 필드 유지·관리자 단일 열을 읽기 전용 가짜 API로 검사한다.

- 입력/첨부 회귀는 프로젝트 미선택 작성→로컬 이미지/PDF 선택·미전송 안내→프로젝트/부품 선택 뒤 초안 보존→첨부 제거 후 텍스트 전송→추가 입력 대기 중 다음 질문 작성·Enter 무전송을 가짜 API에서 검사한다.

- 새 대화 + 회귀는 생성 오류 시 초안 보존→재시도→목록 강조/입력 초점→빈 세션 다시 열기→동일 thread 첫 질문을 운영 빌드 가짜 API에서 검사한다. 실제 운영 세션이나 유료 분석을 생성하지 않는다.

## 역할
- 프로젝트 행 삭제 회귀는 기본 아이콘 숨김→hover/focus 표시, 선택 변경 없이 확인·취소/행 초점 복귀,409 오류 후 재시도, 다른 프로젝트의 현재 초안 보존, 현재 프로젝트 삭제 후 빈 작업대를 가짜 API에서 검사한다. 운영 프로젝트를 삭제하지 않는다.
- 운영 넷리스트 생성/자동 개념도 회귀: 서버 데모404에서 파일 form만 제공한다. 저항이 먼저인 다이오드 포함/미포함의 유효 KiCad 데이터를 multipart로1회 생성한 뒤 초기 URL 대상·회로 탭·Worker 개념도·업로드 넷·모달0개·자동 분석0회를 확인한다. 이후 수동 대상 변경/입력 활성화와 enabled=true의 데모 생성도 별도 가짜 API로 검증한다.
- 운영 빌드 로그인/가입 회귀는 동의 체크0개·Google 로그인 활성/consent 미전송·운영 `/signup` 접근·비밀번호 길이·가입 본문·세션 확인 후 작업대 이동을 가짜 API에서 확인한다. 실제 Google 계정이나 운영 가입 데이터는 만들지 않는다.
- 새 대화 thread 생성 503은 오류 1개/요청 ID/초안보존/run POST 0을 확인하고, 사용자 재전송 때만 thread 생성 재시도→분석 1회·오류해제를 확인한다.
- 운영 로그인 검증은 SOJA_E2E_MODE=production으로 빌드한 Vite preview를 대상으로 실행한다. Google status 활성·데모 status 활성 응답을 함께 준비해도 운영 번들은 데모 조회/버튼 없이 Google start에 연결되며 실패 callback 안내를 유지하는지 확인한다. 실제 Google 계정 인증은 mock하지 않은 외부 검증이 필요하다.
- 복구/오류 mock: 스트림 종료→완료/거절/추가 입력 복원, 30회 조회 중단·수동 복구와 분석 POST 단일성, 저장 실행 정리/활성 실행 유지 및 목록 재조회, 422 재개 오류+폼/같은 run 재제출, 시스템 오류의 폼 제거, 일반 조회·스트림 시작의 HTML 401/빈 503/깨진 JSON과 헤더 요청 ID를 검사한다. 활성 실행 유지의 DB 잠금 판단은 mock 결과이며 실제 advisory lock 검증을 대신하지 않는다.
- 진행 표시: thread 생성 요청을 제어해 전송 버튼의 비활성/회전 상태를 확인하고, 응답 처리 중 현재 세션/중단 버튼의 회전·시스템 효과 줄이기·완료 후 초기 아이콘 복귀를 가짜 API에서 검사한다. 실제 서버 취소나 모델 호출로 증명하지 않는다.
- 프로젝트/대상 선택: 새 프로젝트 생성→내 프로젝트 모달의 서버 부품 선택→헤더 반영/입력 활성화, 선택만으로 run/thread POST 없음, 채팅 안 선택 박스/준비 제목 부재와 대화/입력창 높이를 데스크톱에서 확인한다. 기존 분석·승인 흐름도 상단 모달로 대상을 선택한다.
- 답변 메뉴: 새 대화의 초기 메뉴 부재·완료 결과에 필요한 버튼 표시, 과거 답변의 결과 확인→해당 후보 조회와 GET만 사용한 기록 복원을 확인한다.
- 데스크톱 대화 입력: 실제 Shift+Enter 줄바꿈 후 Enter로 전송하고 줄바꿈을 포함한 기존 API 본문이 한 번만 전달되는 것을 가짜 HTTP 흐름에서 확인한다.
- 대화 고정/삭제 신규 검증은 사용자 지정에 따라 데스크톱 1440×900에서만 수행한다. 브라우저 고정 재로딩·고정 해제·삭제 확인/취소/409 후 재시도·현재 삭제 후 초기화·다른 대화 삭제 시 초안 보존을 본다.
- 넣는 것: 로컬 Vite 화면과 완전한 가짜 API를 사용하는 Playwright 사용자 흐름.
- 넣지 않는 것: 실제 모델·Mouser·공유 DB 호출, 운영 계정과 비밀값.

## 파일
- `E2E.md` — 이 문서
- `workbench.spec.ts` — 새 공개 랜딩→로그인 실패·성공→새 작업대, 프로젝트 최초 2개·더보기·접기·계정 전환 후 목록 격리, 로그인 세션 복원부터 근거·판정 표시·과거 기록 새로고침 복원까지의 브라우저 smoke
- `full-flow.spec.ts` — 완료 판정·실시간 가격·사람 승인·가격 없는 견적·사례 삭제 전체 흐름
- `circuit-layout.spec.ts` — 실제 브라우저 Web Worker 배치 완료, net junction·직교 SVG path, 개념도 노드 무겹침 검증
- `dummy-mode.spec.ts` — route 가로채기 없이 개발 전용 메모리 API로 직접 조작하는 전체 흐름, 프로젝트 탐색·큰 대화 영역·결과 메뉴 1행·반응형·새 대화와 저장 메시지·분석 결과 다시 열기 확인

- 랜딩은 1440/1200/1024/820/768/700/390/320px에서 로컬 Noto Sans KR, 본문 16px 이상, 가로 넘침 없음, 첫 화면 작업대 이미지 0개, 실측 3개 동일 행, 수치가 900px 뷰포트 안에 모두 표시되는지 확인한다. 실제 사용 화면 3장의 세로 순서, 모바일 설명 다음 이미지, 이미지 로드·확대/Escape/초점 복귀, 측정 조건 펼치기, 메뉴 해시/스크롤/목표 초점/sticky 헤더, 키보드 Enter, reduced-motion, 보호 API 미호출도 확인한다.
- 1440px에서는 #27 원시 JSON으로 R1 test 38문항 ID·회수율·모든 근거 평균과 103개 검색 시간 중앙값을 재계산해 표시값과 대조한다. 로그인 화면의 기존 서체 유지도 확인한다.

- 최신 main 통합: HTTP route 모의 시험은 운영 빌드 preview(4190), 메모리 더미 직접 조작/회로 배치는 dummy 모드(4191)로 나누어 실행한다. 한 서버에서 더미 API가 route 모의를 우회하지 않게 하며 Windows worker1/trace off를 유지한다. 이메일 인증·재설정 브라우저 시험은 합성 토큰/API 응답만 사용한다.
