# 화면 디자인 규칙

FastAPI가 같은 출처로 React 작업대와 #73의 `/workspace` 분석·기억 화면을 제공합니다. 사용자는 서버 세션으로 로그인한 뒤 자기 회로에서 대상 부품을 선택하고 D5 질문·조건 재개·근거·판정·승인 사례를 확인합니다. 가격·재고는 화면을 열 때만 조회하며 저장하는 견적에는 포함하지 않습니다. 사용자별 thread·기억 계약은 `../../docs/specs/user-thread-memory.md`를 따릅니다.

## 화면 목록

| 화면 | 하는 일 |
|---|---|
| 로그인 | 사전 계정으로 로그인하고 세션 상태를 확인하거나 로그아웃합니다 |
| 작업대 | 공개 데모 또는 KiCad 넷리스트 프로젝트에서 바꿀 부품을 고르고 D5에 질문합니다 |
| 판정 결과 | 회로 역할, 대체 조건, 후보별 대체 판정과 근거를 보입니다 |
| 승인 | 견적서를 저장하기 전에 사람이 확인하고 승인합니다 |
| 견적서·사례 | 승인된 판정으로 가격 없는 견적을 저장하고 승인 사례를 확인·삭제합니다 |

## 원칙

- 대체 판정 5종은 SPEC 3절의 화면 표기를 그대로 씁니다.
- 판정마다 근거(데이터시트의 쪽·표·행이나 공개 문서의 절)를 판정 바로 옆에 보입니다.
- 결과 화면마다 "같은 동작은 보장하지 않는다"를 보입니다.
- 패키지가 달라 기판 수정이 필요한 후보는 판정과 따로 표시합니다.

## 상호작용

- 로그인 실패는 자격 증명을 되돌려 보이지 않는 공통 안내를 표시합니다.
- 로그인 성공 후 로그인 상태와 로그아웃 동작을 표시합니다.
- 로그아웃 성공 시 화면의 이메일·비밀번호 입력을 지웁니다.
- 회원가입·비밀번호 재설정·프로필은 제공하지 않습니다. 질문 연결이 끊기면 저장된 run만 조회하고 질문을 자동 재전송하지 않습니다.
- 로그인 화면은 인증에 집중하고 분석 화면 링크를 제공합니다. 분석 화면은 자기 회로·thread만 표시하며 401이면 표시 중인 데이터를 지우고 로그인 화면으로 이동합니다.
- 사용자 파일·모델 응답은 textContent로 표시하고 브라우저 영구 저장소에 보관하지 않습니다. 업로드는 1 MiB UTF-8 KiCad .net으로 제한합니다.

## 색·글꼴·배치

- 데스크톱은 프로젝트·대화·결과의 3열 배치입니다.
- 900px 이하에서는 대화를 계속 보이게 두고 프로젝트 drawer와 결과 tab을 사용합니다.
- 모든 입력에 label을 두고 진행 상태는 `aria-live`, 키보드 초점은 3px 윤곽선으로 표시합니다.
