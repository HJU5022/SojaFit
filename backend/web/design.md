# 화면 디자인 규칙

브라우저 화면은 FastAPI가 같은 출처로 제공합니다. 로그인 후 `/workspace`에서 자기 KiCad 넷리스트 업로드·대상 선택·분석 대화·조건 재개·판정 사례 승인과 기억 조회를 사용합니다. 상세 계약은 `../../docs/specs/user-thread-memory.md`를 따릅니다. 견적서 발행은 아직 없습니다.

## 화면 목록

| 화면 | 하는 일 |
|---|---|
| 로그인 | 사전 계정으로 로그인하고 세션 상태를 확인하거나 로그아웃합니다 |
| 입력 | KiCad 넷리스트를 올리고 바꿀 부품을 고릅니다 |
| 판정 결과 | 회로 역할, 대체 조건, 후보별 대체 판정과 근거를 보입니다 |
| 승인 | 견적서를 저장하기 전에 사람이 확인하고 승인합니다 |
| 견적서 | 승인된 견적서를 봅니다 |

## 원칙

- 대체 판정 5종은 SPEC 3절의 화면 표기를 그대로 씁니다.
- 판정마다 근거(데이터시트의 쪽·표·행이나 공개 문서의 절)를 판정 바로 옆에 보입니다.
- 결과 화면마다 "같은 동작은 보장하지 않는다"를 보입니다.
- 패키지가 달라 기판 수정이 필요한 후보는 판정과 따로 표시합니다.

## 상호작용

- 로그인 실패는 자격 증명을 되돌려 보이지 않는 공통 안내를 표시합니다.
- 로그인 성공 후 로그인 상태와 로그아웃 동작을 표시합니다.
- 로그아웃 성공 시 화면의 이메일·비밀번호 입력을 지웁니다.
- 로그인 화면은 인증에 집중하고 분석 화면 링크를 제공합니다. 분석 화면은 자기 회로·thread만 표시하며 401이면 표시 중인 데이터를 지우고 로그인 화면으로 이동합니다.
- 사용자 파일·모델 응답은 textContent로 표시하고 브라우저 영구 저장소에 보관하지 않습니다. 업로드는 1 MiB UTF-8 KiCad .net으로 제한합니다.
